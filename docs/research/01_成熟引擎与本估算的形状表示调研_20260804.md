# 成熟引擎与本估算的形状表示调研（2026-08-04晚）

目的：给spec/11（模型生成与形状表示）提供证据。用户口径先钉住：
**要的是模拟世界里的形状（机械臂、带盘、导轮、骨架的碰撞形与外观形），
不是能拿去制造的CAD实体。**

## 一、成熟引擎怎么表示"模拟形状"（外部调研）

### 1.1 MuJoCo（MJCF→mjModel）

- 声明式MJCF：body树+joint+geom+site+asset，编译成只读`mjModel`
  （模型/状态分离，design/24第五节已引）。
- geom词汇（官方文档核实）：plane、hfield、sphere、capsule、ellipsoid、
  cylinder、box、mesh、**sdf**。网格碰撞取**凸包**；非凸靠凸分解或SDF。
- 3.x的SDF插件把"无网格的隐式形状"做成一等geom：插件只需给出SDF值与
  梯度，即进碰撞表；flex（柔性体）也能与SDF geom碰撞。
- 视觉/碰撞分离靠约定：`contype/conaffinity=0`的geom只参与渲染；
  group分层控制显示。惯量可显式给或由geom密度推。

### 1.2 URDF / SDFormat

- link = `inertial` + `visual`* + `collision`*——**三表示分离是格式内建的**；
  joint连link成树。collision惯用简化形（primitive/凸包/低模网格）。
- SDFormat是URDF的泛化（world级、嵌套model、传感器）。
- 事实标准：所有主流引擎都**导入**这两个格式表示机器人，没有引擎自造
  机器人描述格式。

### 1.3 USD与USD Physics

- 组合式场景描述（layer/reference/variant）；UsdPhysics以API schema给
  prim叠加RigidBody/Collider语义；几何带purpose（render/proxy/guide）——
  又一种视觉/碰撞用途分离。Isaac系以USD为场景真源。

### 1.4 SOFA

- 每个对象**三模型**：behavior（力学自由度）/collision/visual，
  之间用mapping同步——分离最彻底的一家（其场景图已在WDS design/23引用）。

### 1.5 Genesis（2024—2025，文档核实）

- `morph`概念=**几何+位姿的混合封装**：primitives、mesh、URDF、MJCF、
  terrain、软体描述都作morph喂给entity。
- 多solver架构（Rigid/MPM/FEM/PBD/SPH/SF/Tool）+coupler跨solver耦合——
  按需激活，与本仓"物理域互不依赖+显式耦合模块"的边界同型。

### 1.6 PyBullet与Chrono

- PyBullet：`createCollisionShape`/`createVisualShape`/`createMultiBody`
  ——碰撞/视觉分离直接体现在API签名上。
- Chrono：ChBody+碰撞模型+视觉资产三分；Parsers读URDF。

### 1.7 六条收敛（外部结论）

1. **力学/碰撞/视觉三表示分离是行业不变式**——每家都有，只是拼法不同；
2. **primitives优先、mesh兜底、SDF补非凸**：五个基本形
   （box/sphere/capsule/cylinder/plane）是全行业交集；
3. **声明式场景文件→编译成运行时模型**（MJCF→mjModel、USD→各后端）；
4. **机器人一律导入既有格式**（URDF/MJCF），没人自造；
5. 形状与位姿解耦（Genesis的morph打包了它们，底层仍分开）；
6. 单位制是各家的坑（URDF米制、MJCF可配）——恰是本仓轴2管的事。

## 二、本估算各仓已有的形状表示（内部盘点，载重引用抽验3/3属实）

| 仓 | 形状表示 | 关键证据 |
|---|---|---|
| **WDS** | **唯一有成体系解析/SDF原语词汇的仓**：`WindingSurface`（有效半径随层数长的隐式圆柱）、`CapsuleObstacle`/`RoundedBoxObstacle`（rounded-core SDF，`φ(x)=φ_core(x)−r_f`）、`CylinderSurface`（有限宽圆角边圆柱，可带槽法兰与凹套）、`RoundedEdgeAnalyticProxy`（胶囊解析代理）。契约层显式分离：`laydown_surface`的`display_mesh_excluded_from_contact_queries`、`static_mesh`的`contact_solver_role="excluded_visual_context_only"` | `dynamic/static_obstacle.py:1`、`contracts/laydown_surface.py:144` |
| **WII** | 机械臂=**POE螺旋轴参数运动学**（不是DH不是URDF）+**逐连杆visual/collision双STL**；`ModelAssetRef`带`sha256/units/usage:"visual"\|"collision"`；碰撞=BVH网格窄相+广相+相邻连杆白名单；导出物`WiiMotionTimeline`是**纯位姿+关节角时间线，不含形状** | `motion-module/src/types.ts:485`、`wii_pose_core/six_axis_ik/kinematics.py` |
| **case2** | **骨架驱动参数化机械臂壳体生成器**（build123d，系数×spec长度不写死毫米）；显式"碰撞包络正本`_*_envelope`"与可见实体分离，安全审查证`refined ⊆ envelope`；碰撞矩阵用OCCT精确B-Rep（距离+布尔公共体积+点在体内），与渲染器刻意分离 | `src/robot_links.py`、`src/collision_matrix.py` |
| **GCW** | STEP face→逐站中心线CSV（含width与左右壁点，即WDS槽道的上游）；lab_render场景="带owner分组的三角汤+标签"，纯显示 | `src/exporters.py`、`lab_render/scene.py` |
| **FTS** | **完全没有仿真形状层**：RigidBody只有位姿+label，端口只有位姿+法向，渲染是位姿+光束线段示意 | `contracts/scene.py`（RigidBody无形状字段） |

三样关键能力的存在性：**(A)碰撞形/外观形分离**已在四个仓（除FTS）各自为政地存在；
**(B)形状primitives词汇**只有WDS有真正的解析原语集；**(C)参数化形状生成器**
case2最成熟（骨架驱动机械臂）、WDS次之（层数生长面/法兰参数）、GCW有支架版。

空白与不一致：五仓五种表示互不相通；三种碰撞算法（SDF罚/OCCT精确/BVH网格）
无共享内核；单位分裂（四仓mm、FTS用m）；证据分级人人有但枚举各异
（evidence_mode / source_step_sha256 / VISUAL_REFINEMENT_PROVENANCE / ProvenancedPose）。

一个可复用的正面模式：**运动体与形状解耦**——WDS把导轮拆成`RollerState`
（转动状态）+`CylinderSurface`（形状），WII把机器人拆成POE运动学+连杆STL+
位姿时间线三件。这与外部的Genesis morph殊途同归。

## 三、合成：内外证据指向同一张规范

1. 外部六条收敛里的第1条（三表示分离）与内部(A)完全重合——**四个仓已在
   无协调的情况下各自实现它**，规范只是把既成事实写下来；
2. 外部第2条（primitives+mesh+SDF）与内部(B)拼合：WDS的SDF原语词汇+
   WII的网格资产形制（`ModelAssetRef`）正好凑齐词汇的两半，参数化生成器
   （内部(C)）是第三类；
3. 外部第4条（机器人导入不自造）与WII现状一致——POE+资产绑定已是"导入
   +绑定"形制，引擎沿用；
4. case2的`refined ⊆ envelope`是**内部独有的增量**：碰撞形的保守方向
   （包络⊇可见 用于安全审查；贴合 用于接触求解）值得立为声明字段——
   外部引擎没有这个显式概念。
