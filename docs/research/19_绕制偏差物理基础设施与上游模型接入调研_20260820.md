## 零、结论

**本仓的物理基础设施还不够。** 已有状态、能量、准静态求解、杆弯扭、接触、张力驱动、输运、传感器声明、模型资产声明和案例治理等底座，但它们尚不能直接回答两个已经出现的真实问题：

1. WII/GCW发布的模型、中心线和时间线，哪些字节可以作为物理输入，哪些只能显示；
2. 绕线机LTS张力传感器面对两侧带材张力、包角、安装敏感轴、导轮自重和ADC时，最终读数是否等于真实带材张力。

当前`drives.TensionSensor`只实现“已标定张力标量→mV→量化读数”，模块文件头已经明确承认它没有“两侧张力矢量合力→悬臂敏感轴读数”这一层。厂商手册与web handling文献都把包角、合力方向、导轮重量、传感器敏感轴和安装方向列为张力测量的必要变量[15-20]。因此，张力测量几何不是可选精修，而是第一个应补的物理基础设施。

上游模型可以直接复用，但“直接”指adapter生成本仓`ModelSnapshot`，不指运行时导入上游源码，也不指把显示网格直接塞进接触求解。WII拥有运动学、规划和状态产物；physics-engine拥有模型/运动输入合同、虚拟物理关系、接触、力学、测量与求解；WDS只读消费physics-engine结果。模型原始生产者是谁不改变物理接口。

### 4.2 为什么不能“模型文件能打开就直接用”

Drake把同一现实对象拆成proximity、perception和illustration三种角色，不同操作可以使用不同几何[15]；SOFA把物理、碰撞和显示模型分开，并用mapping传递位置、速度和力[16]；MuJoCo也明确指出显示可以使用任意三角网格，而碰撞对网格使用凸包，skin只影响显示[17]。三类证据共同说明：**文件身份相同不等于物理表示相同。**

本仓的直接复用判据因此是“语义闭包可复读”，不是“扩展名支持”：

1. 知道它来自哪份制造/设计源；
2. 知道它是visual、collision还是physics；
3. 知道单位、frame、刚体安装关系和运动来源；
4. 知道简化误差、凸性、保守方向和置信度；
5. 能在不导入WII/GCW源码的情况下严格复读。

### 4.3 WDS的边界

WDS只应消费：

- physics-engine接收并复读后的模型/运动输入身份；
- physics-engine给出的力学状态、张力、接触、偏差、测量预测和证据等级；
- WDS自己拥有的工艺参数、路线侧车、标定选择和产品输出。

WDS不得：

- 修改GCW中心线或WII轨迹；
- 导入GCW/WII业务源码；
- 用WII碰撞结论替代physics-engine接触力学；
- 用显示插值帧替代物理求解帧；
- 把一个LTS标量解释成T0—T4五段直接测量。

## 五、物理基础设施应包含什么

### 5.1 模型输入层

一份可求解的绕制物理输入至少要闭合下列角色：

| 角色 | 权威来源 | 本仓拥有的部分 |
|---|---|---|
| 工件/导轮/槽壁模型 | 独立ModelSnapshot；来源不限 | visual/collision选择、资产变换、SDF/解析形、接触参数 |
| 机器人/E1/工件运动与规划 | WII adapter | time/planning-scale消费、源状态与物理边界，不重算IK/FK |
| process frame与累计送带 | WII adapter | 虚拟frame绑定、落位几何与输运输入 |
| R1出带点、活动导轮、entry boundary | WDS路线侧车/现场标定 | 路线图、包角、跨段、观测点与不确定度 |
| 带材材料 | 供应商+实测 | EA、双轴EI、GJ、密度、本构与适用域 |
| 执行器与传感器 | 绕线机硬件资料+标定 | 力学模型、测量方程、时延、量化和证据等级 |

模型输入不能是一个巨型“世界JSON”。应由内容寻址的独立产物组成，并在运行包中引用；任何缺少的物理必需角色失败关闭。

### 5.2 力学与测量层

最小完整链应区分：

1. **真实物理量**：跨段张力、杆单元轴力、接触力、滚轮反力；
2. **传感器承受的力**：两侧带材张力矢量、导轮自重和其他机械载荷的合力；
3. **传感器敏感轴分量**：合力对LTS敏感方向的投影；
4. **电气信号**：桥路mV、放大、零偏、满量程、量化和时延；
5. **控制器显示值**：VR451/ATC600的缩放、清零和滤波结果；
6. **观测器估计值**：若以后估计T0—T4，必须带协方差、可观测秩和nullspace。

现有`TensionSensor`只覆盖第4层的一部分，并把第1—3层压成一个已经标定好的输入标量。因此它不能验证“绕线机测张力是否准”。

## 六、第一组小场景：张力线的收放与测量

### 6.1 场景T-M0：两段带材对测力轮的静力合力

定义带材运动方向单位向量`t_in`、`t_out`，入口/出口张力`T_in`、`T_out`。两段带材对测力轮的合力写成：

```text
F_web = -T_in * t_in + T_out * t_out
```

传感器敏感轴为单位向量`sensor_axis`，去皮后的理想读数为：

```text
F_sensor = dot(F_web, sensor_axis)
```

当两侧张力相等、包角为`beta`，且敏感轴对准合力方向时：

```text
abs(F_sensor) = 2 * T * sin(beta / 2)
```

Maxcess选型公式、ABB测力矢量图和FMS测量说明均采用同一关系[18-20]。这条闭式应成为第一条oracle。

必须红：把入口力方向写反；把包角定义成补角；敏感轴未归一化；把合力模长当敏感轴分量；双支承时忘记支承分配；未去除导轮自重。

### 6.2 场景T-M1：安装角、导轮自重与双支承

在T-M0上加入：

- 导轮与轴承组件重量；
- 敏感轴与合力方向夹角；
- 单传感器/双传感器支承分配；
- tare前与tare后的读数；
- 正负方向和过载。

厂商资料明确指出传感器只测敏感方向分量，包角、合力方向和导轮重量共同决定读数[18-20]。本场景先做一般矢量平衡，不写死现场LTS是单支承还是双支承；现场证据当前仍要求确认实际导轮机械数据、单/双传感器和安装方向。

### 6.3 场景T-M2：LTS桥路、mV、ADC与标定

复用现有`TensionSensor`的满量程、20mV输出和ADC量化，但输入改为T-M1得到的敏感轴力，而不是“真实张力”。验收包括：

- 0、25%、50%、100%量程；
- 正负方向与满量程截断；
- ADC就近量化误差不超过半个台阶；
- 零点、量程、五点往返标定和留出点；
- 标定前只允许`hypothesis_only`，不得输出“真实张力已测得”。

### 6.4 场景T-M3：传感器位置与被控点不同

复用现有绞盘案例，但把两件事分开：

1. 测力轮本身读到哪一个合力分量；
2. 测量位置与落位点之间的包角/滑移怎样改变张力。

全滑移极限可用Euler-Eytelwein式；粘着时只能给不等式和可行域，不能强行使用等号。Yang等的多轮模型与实验说明上下游自由跨段和包覆区共同决定横向响应[3]，现有单次乘法只能作为极限或机制门。

### 6.5 场景T-M4：放线—收线两执行器的小动态链

使用放线端张力/制动力矩与收线端速度两个输入，建立最小自由跨段：

- 放线盘与收线盘半径变化；
- 两端线速度差产生张力；
- 测力轮读数经T-M0—T-M2生成；
- 开环、理想控制器和故意很差的控制器三组；
- 速度阶跃、张力设定阶跃和轻触扰动。

Kim等的双执行器R2R实验采用放线端张力环、收线端速度环并做实物验证[4]；Branca等表明偏心轮和失圆卷会同时扰动速度与张力[2]；Lynch等的观测器依赖轮径、角速度和电机指令等测量，不能从单个LTS凭空恢复所有跨段张力[5]。

本场景的第一版不复现ATC600内部算法，只验证本仓的物理对象、测量方程和装配边界。

### 6.6 小场景的证据阶梯

| 层 | 输入 | 可以声称 | 不可以声称 |
|---|---|---|---|
| E0解析 | 人工几何、已知张力 | 矢量平衡与量化实现正确 | 真机LTS正确 |
| E1合成回放 | 物理引擎生成的张力与运动 | 测量链对已知真值的误差 | 现场标定完成 |
| E2砝码/参考传感器台架 | 已知砝码或参考load cell、实测角度 | LTS几何映射和标定误差 | 完整绕制动态正确 |
| E3低速收放线 | 同步LTS、编码器、参考张力、半径 | 小动态链在该工况通过 | T0—T4全部可观 |
| E4真实绕制窗口 | WII/GCW official模型与timeline | 代表窗口的模型—测量闭环 | 全工件、全速度、全材料泛化 |

## 七、同行路线对本仓的具体影响

### 7.1 moving-web不是“一根弹簧”

Shelton和Reid把横向运动与带速、导轮角度、曲率和导轮动态联系起来，并给出实验验证[1]。Branca等进一步把偏心导轮和失圆卷造成的速度/张力振荡纳入方程并与实验平台对比[2]。Yang等把倾斜导轮、上下游跨段、周向/横向滑移和收放卷边界放进同一个模型并做实验[3]。

对本仓的影响：`transport`、`drives`、`laydown`和接触不能长期保持四个孤岛；但应先通过小场景逐层接，不用一个“端到端”案例掩盖每一层的误差。

### 7.2 杆、带与壳是可信度阶梯，不是互斥选项

DER与Cosserat杆适合中心线、弯扭和快速交互[7-9]；DisMech/IMC说明隐式杆接触可以处理更稳健的摩擦过程[10-11]；离散带/ribbon理论保留比圆杆更多的宽度方向形变信息[12]。非平面REBCO研究又表明hard-way弯曲、扭转和绕制角必须共同考虑[13]；2026年公开的20匝机器人非平面REBCO绕制记录则把离散工具轨迹、重复铺放、成品临界电流和磁场测量放在同一条验证链上[14]。

对本仓的影响：

- 杆模型作为主交互内核；
- 离散带/窄壳作为高风险区升级候选；
- 壳FE作为蹭边、板屈曲和宽度应力的独立oracle；
- Project Chrono等外部栈的cable、beam、shell与网格接触只作隔离对拍，不进入本仓运行时依赖[21]；
- 不用“杆案例通过”声称板屈曲已经解决。

### 7.3 工程模型必须多表示

Drake与SOFA的共同点不是某种格式，而是物理、碰撞、感知/显示表示各自独立并显式映射[15-16]。MuJoCo显示网格与碰撞凸包的差异则说明，不声明角色会产生静默几何变化[17]。

对本仓的影响：任意来源模型可以复用，但必须经`ModelSnapshot`声明角色、frame、units、SHA和资产变换，再由`ModelPhysicsRelation`决定是否进入虚拟物理；“同一个STL”不是充分条件。

## 八、推荐的物理基础设施分层

```text
任意模型来源：visual/collision资产、frame、单位、SHA
  ↓ ModelSnapshot adapter
WII：机器人/E1/工件规划与状态
  ↓ PlannedMotion adapter（time_s或planning_scale）
physics-engine：
  ModelSnapshot + PlannedMotion + ModelPhysicsRelation
  → 状态/材料/边界
  → 杆/带/接触/输运/驱动
  → 传感器物理与观测
  → 求解、案例、oracle、run package
  ↓ wheel/API/结果产物
WDS：只读消费、选择工艺参数、组织代表窗口、输出偏差统计
```

这不是新平台仓。它是physics-engine内部物理责任的闭环；WII以后只在产物出口加adapter，模型生产者不进入运行时依赖，WDS只在消费侧适配。

## 九、反证与限制

1. **“已经有52个案例，所以基础设施够了”不成立。** 案例数量不能替代真实模型输入、测量方程和标定闭环。
2. **“WII模型能显示，所以能直接做物理”不成立。** visual、collision和physics角色不同[15-17]。
3. **“一个LTS读数就是带材张力”不成立。** 测力轮读的是两侧张力和自重的敏感轴合力[18-20]。
4. **“一个LTS可以直接给T0—T4”不成立。** 多跨张力需要动态模型、额外测量与可观测性分析[5-6]。
5. **“GPU能补基础设施缺口”不成立。** GPU只能执行已经定义好的数学；它不会补单位、frame、模型角色、传感器安装或标定。
6. **本轮没有打开现场照片逐点重建LTS导轮几何**，也没有确认单/双传感器支承、敏感轴、导轮质量、包角和VR451比例；因此T-M1以上的现场参数保持未知。
7. **本轮没有执行物理代码改动或真机试验。** 小场景仍是计划，不是已验证能力。
