## 二、三条设计裁决

### 2.1 一份公式源、两个求值后端——逐字节一致是构造保证的

0016甲案要求"核心零依赖+可选NumPy加速档+两实现对拍"。本片的做法是
**积分公式只写一遍**，按`VectorOps`求值；`PurePythonOps`与`NumpyOps`
实现同一组原语（`scale`/`add`/`load`/`dump`）。

于是两个后端执行的是**同一串运算、同一个次序**，逐元素IEEE 754 float64
加乘、无归约、无次序重排——**逐位相同是构造保证的，不是碰巧对上**。
按spec/12第5.3节"能逐字节就必须逐字节，容差是需要理由的退档"，
本模块的对拍档位因此是**逐字节**。实测：600次积分（3个积分器×200组随机
多自由度输入×120步）逐字节零差异。确定性等级按spec/13规则5申报为`bitwise`。

**对拍规模的申报**（spec/12第5.4节要求）：本案例单档最多4000步。
它足以判定的理由不是"步数够多"，而是**上面那个构造论证**——
规模再大也不改变"两边跑的是同一串运算"这件事。真正需要在大规模上对拍的是
能量装配，那随内核搬迁进来时另行申报。

### 2.2 加速档的边界画在哪，以及它今天买不到多少

加速度回调是**调用方的代码**，两个后端都用元组调它。所以今天加速档只
向量化积分器自己的算术，而每步的开销大头在回调里。这是有意的诚实边界，
不是遗漏：已测事实说当前规模的瓶颈就是解释器与派发（标度指数0.59），
真正值得加速的是能量装配。**加速档在这一片里的价值是把0016的对拍机制先立起来**，
不是提速。

### 2.3 打包次序是被声明的字节，不是实现里的隐含约定

`StateLayout.fingerprint()`把次序做成内容地址。测试里有一条专门守它：
两个布局字段完全相同、只是次序相反，`dof_count`一样、向量长度一样——
**任何只看长度的检查都发现不了**，指纹发现得了。spec/12第2.2节说次序换了
"梯度与Hessian的索引全错，而多数测试不会发现"，这条门就是为那句话建的。

## 三、四条B档判据全部复现spec/12预先记下的数

spec/12第九节在写规范时就把这四条的实测值记了下来。本片实现跑出来的数
与那些值**逐位吻合**——规范先行在这里不是形式，它先说了答案，实现照着对上。

| 判据 | spec/12记录 | 本片实测 |
|---|---|---|
| 半隐式Euler误差/`a·T·h/2` | 1±8e-14 | +1.000000000009784 / +1.000000000040481 / +0.999999999940876 |
| **显式Euler误差/`a·T·h/2`** | **−1**（同幅反号） | −0.999999999990215 / −0.999999999959610 / −1.000000000058844 |
| Verlet对`cos(ωT)`误差比 | 3.9985与3.9996 | 1.117095e-4 / 2.793801e-5 / 6.985166e-6，比值同上 |
| 漂移排序 | 1.2252 / 1.0052e-2 / 5.5453e-5 | 逐位相同 |

**"同幅反号"立成了独立的一道门**：`test_explicit_and_symplectic_errors_are_equal_and_opposite`
断言两者异号且幅值相等。按`abs()`写的判据分不开这两个积分器——
plans/02原来那一行就有这个洞，已随本批修正。

## 五、本片明确不做的

- **不做隐式族**（Newmark、隐式中点、generalized-α）：它们随WDS内核搬迁进来，
  且要先解spec/12第11.2节登记的那条——接触摩擦层有真状态，
  "无状态纯函数"的边界要在真搬到接触之前再裁一次。
- **不做自适应步长**：步长二分是抢救不是收敛证据（spec/12第4.3节），
  要自适应先得有失败阶梯的声明。
- **不做准静态求解**：它与瞬态是两条并列的路（spec/12第4.1节），不是本片的事。
- **三个积分器的`production_ready`全是`False`**，并有一条门守着这件事。
  它们是教学案例与漂移排序的对照组，不是生产件。
