## 一、裁决

第一批物理代码只闭合测力轮的静力测量链，不提前声称动态收放线或现场标定完成：

```text
两侧跨段张力与材料行进方向
→ 带材对测力轮的三维矢量合力
→ 导轮静载/tare与传感器敏感轴投影
→ 显式支承份额
→ 既有TensionSensor的mV、ADC与显示张力
→ 内容寻址的分层测量样点
```

实现归属为`physics_engine.tension_measurement`。旧`drives.TensionSensor`保持原样，继续只负责“已经映射到传感器输入的正标量→mV/ADC”；新模块在它外面组合力学层，不原地扩义旧类。

## 二、方向、量与支承约定

入口和出口切向都按材料行进方向声明。入口带段从轮指向来料侧，出口带段从轮指向出料侧，因此带材对轮的力为：

```text
F_web = -T_in*t_in + T_out*t_out
```

等张力时，模长退化到：

```text
|F_web| = 2*T*sin(beta/2)
```

其中beta是两条行进切向之间0—180°的转角：直线通过为0°，折返为180°。这样可以同时判出入口符号写反和把包角写成补角两种错误。

本批固定六层互不复用字段：跨段张力、web矢量合力、gross敏感轴力、tare敏感轴力、net敏感轴力、显示跨段张力。支承分配不由“单支承/双支承”字符串猜测，而由非负且和为1的`support_shares`显式给出；非对称结构没有份额就失败关闭。

电气组合只接net敏感轴力，字段明确叫`zeroed_bridge_output_mv`和`digitized_net_axis_force_n`。它表示tare已经清零后的理想旧`TensionSensor`路径，不表示原始gross桥路，也不裁定tare在模拟前端还是数字端扣除；gross载荷下的真实过载范围留给T-M2现场结构。这一限制避免用一个含糊的`bridge_output_mv`掩盖尚未确认的硬件拓扑。

## 三、跨边界样点

新增draft面：

```text
tension_measurement_sample / 0.1
```

样点记录全部输入、派生层、证据、标定身份、电气链与自指内容哈希。读取端执行：

1. 严格JSON、精确键集、facet版本与自指哈希检查；
2. 重新构造测力轮和可选`TensionSensor`；
3. 从输入重算web/gross/tare/net、各支承载荷、清零后mV、量化net力和显示跨段张力；
4. 对整份文档逐字段比对。

所以只改派生结果再重算自指哈希仍会被拒绝。样点未带实测标定时恒为`hypothesis_only`；几何证据达到`calibrated`或`measured`且显式带`calibration_id`和不确定度后，也只升级为`calibrated_model`，不冒充直接硬件测量。

## 四、两个小场景

### 4.1 T-M0测力轮合力

`cases/tension_measuring_roll_resultant`用17N等张力和0°、60°、90°、180°四个转角，对独立静力生成器的矢量分量与闭式模长。镜像路线只允许横向分量变号。

### 4.2 T-M1安装、自重与支承

`cases/tension_measuring_roll_installation`用单支承、双对称支承和显式非对称支承三种构型，对独立刚体静力生成器的gross/tare/net轴向力与逐支承分配。tare改变gross但不得改变同一web载荷的net结果。

两份生成器都不import被验模块；两份案例均为A档、`interactive`、合成参数、永久`hypothesis_only`。

## 五、性能裁决

`tools/bench.py`增加1000个静态测量样点的显式工作负载，不用单次调用噪声作性能结论。本机Apple M4重复9次中位23.422ms，即每样点约23.4μs；srv01在load 0.55下重复9次中位32.353ms，即每样点约32.4μs。两台CPU路径都低于50ms预算，且较慢的x86服务器仍有35.3%余量。

这条路径是常数规模的Python标量运算，当前不满足GPU三门槛：没有足够批量、没有数据搬运摊销问题、CPU已是交互级。因此本批不引入NumPy、Metal或CUDA，也不改变零运行时依赖承诺。以后参数扫描首先走案例级并行和master；只有profile证明同一数组内核主导端到端墙钟时才重审GPU。

## 六、兼容性与证据

## 七、未完成项与触发条件

本批之后仍有四组明确欠账：

1. T-M2还没有形成独立正式案例：当前组合路径已有mV/ADC单元门，但缺五点正反程标定、留出点、采样周期和测量时延；
2. T-M3小型放线—收线动态链尚未实现，不能把两个静力案例称为绕线链闭环；
3. 现场LTS单/双支承、入口/出口切向、敏感轴、导轮组件重量、VR451比例、滤波和动态响应仍未知；
4. 上游输入闭包仍缺official `wii_motion_timeline.v2`，GCW/WII真实资产也没有进入本批案例。

触发条件：取得现场LTS安装/标定数据，或开始T-M2、T-M3、上游输入闭包、WDS采用中的任一批时，必须从上述对应欠账继续，不得把本批合成静力结果抬成现场测量结论。
