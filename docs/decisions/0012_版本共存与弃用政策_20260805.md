# 0012 版本共存与弃用政策（2026-08-05凌晨）

状态：已决（用户提问"老程序用不了新版本怎么办、要不要留老版本入口"；
本页把已有机制成文并补齐行业惯例的缺件）。

## 一、老版本的入口：**已经天然存在，且永不关闭**

1. **wheelhouse不可变**：已发版本永不覆盖、永不删除（release.py强制）。
   钉住`physics-engine==0.2.0`的程序十年后仍装得上同一份字节。
2. **环境隔离即共存**：每个项目/脚本自己的venv装自己钉的版本，同一台
   机器上0.2.0与0.3.0并行运行互不相扰——这是Python生态的标准答案，
   不需要引擎侧做任何"多版本API入口"。**不许把引擎装进共享/系统Python。**
3. 老版本行为被冻结恰是回执体系想要的：不升级=不漂移。

## 二、随手脚本的规范用法（学现行生态惯例：PEP 723+uv）

一次性脚本在文件头内联声明依赖，`uv run`自动建临时环境：

    # /// script
    # requires-python = ">=3.11"
    # dependencies = ["physics-engine==0.3.0"]
    # ///

每台机器设一次`UV_FIND_LINKS=~/wheelhouse`（shell配置里），此后
`uv run 脚本.py`、`uv add physics-engine`全部自动从wheelhouse解析。
两个脚本钉不同版本＝两个互不相扰的临时环境。

## 三、0.x期的变更纪律

- **minor可破坏兼容，patch只含兼容修复**；修复**不回port**到老minor——
  用不了新版就留在老版（行为冻结），或升级过门禁。
- **稳定倾向档的弃用给一版缓冲**：公开名要改/删，先在版本N标注弃用
  （docstring+CHANGELOG），N+1才移除；实验档（shapes/collision/scene draft面）
  可直接改。
- **CHANGELOG强制**：Keep a Changelog形制；发版脚本检查版本条目存在，
  没写变更不准发——破坏性变更必须被读到，不许靠猜。

## 四、公开GitHub仓（用户同日指示"直接推到公开仓"）

- 镜像到`github.com/Rtiming/physics-engine`（public）；orangepi仍是
  舰队主远程，GitHub是公开镜像，发版脚本两边都推tag。
- **License=MIT**：执行既有记录的形制目标（索引二之二"学PyElastica
  （MIT）的形式"）；当前无外部贡献者，改主意成本为零。
- PyPI仍不发（0010不变）；公开仓的wheel走GitHub Releases随缘，
  舰队内仍以wheelhouse为准。
