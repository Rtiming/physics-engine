# 0010 发布链路与公开API面（2026-08-04深夜）

状态：已裁决（用户选定C路线"wheel+舰队wheelhouse"，并要求规范接口、
声明仓库处于快速演进期）。

## 一、依赖链路裁决：版本化wheel+舰队wheelhouse

- **wheelhouse仓**：`ts-orangepi:wheelhouse.git`，每台机器克隆到
  `~/wheelhouse`，更新=git pull。wheel是不可变工件，**版本不可覆盖**
  （发版脚本强制：同版本已存在即拒发）。
- **消费方**：钉精确版本+`--find-links ~/wheelhouse`；uv.lock记wheel的
  SHA-256——**引擎字节经锁文件自动进入消费方既有的执行树回执绑定**，
  这是本路线胜出的决定性理由（路径依赖会在字节绑定上开洞，git依赖
  要求每台机器装机时能ssh基建）。
- **master**：wheelhouse经既有同步链路带过去（批次B落地时在WDS的
  workspace_sync.manifest加一行），离线可装。
- **开发回路双轨**：日常可`uv pip install -e`引擎目录随便试；
  **门禁与回执只认锁定的wheel，editable状态不得进验收。**

## 二、发版流程（tools/release.py，一键）

仓库干净→版本一致→accept full必须PASS→`uv build`→wheel入wheelhouse
（提交信息含SHA-256）→引擎仓打`v<版本>`tag。低摩擦是刻意的：
仓库处于快速演进期，发版不该是仪式。

## 三、公开API面与0.x语义

- 顶层`__init__`只re-export常用名，模块分两档（档位即本包的面状态）：
  **稳定倾向**=facets/canonical/identity/provenance/run_package
  （已冻结轴的参考实现，破坏性改动须决策记录）；
  **实验档**=shapes/collision（随spec/10、11草案演进，minor内可破坏）。
- **0.x语义**：minor跳变可破坏兼容。消费方钉精确版本、经自己门禁
  自觉升级；升级永远不是被动漂移。
- 首个发布版**0.2.0**（0.1.0是骨架占位，未发过wheel）。

## 四、明确不做的

- 现在不架真正的私有索引服务（pypiserver/devpi）——wheelhouse目录
  就是最简形态，wheel多到管理不动时再升级，路径平滑。
- 不发PyPI——开源时点是用户的远期裁决。
