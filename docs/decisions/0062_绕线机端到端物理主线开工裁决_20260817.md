# 0062 绕线机端到端物理主线的开工裁决

日期：2026-08-17
状态：已裁决，执行台账见[plans/13](../plans/13_绕线机端到端执行与验收_20260817.md)

## 一、问题

用户2026-08-17把目标从"补能力位"改成一个**具体的机器**：绕线机的实际物理要能
仿真出来——原话点名两件事，**张力控制的过程**与**带材蹭边的可能**。

这句话落到能力位清单上不是泛指。它精确覆盖场景⑥的S6.3（执行器物理）、S6.4
（传感器读出）、S6.5（带材过导向轮的接触）、S6.6（蹭边：带材碰法兰）、S6.7
（端到端），外加场景⑤的S5.4（喂料与移动前沿）。**主分母0/6一直不动，动它的
入口就在这六位上**——而不在此前推荐的光学线上（光学一位都不碰绕线机）。

真机链路是有实测记录的，不是设定：`winding-machine/HARDWARE_TOPOLOGY.md`记
LTS1-5悬臂张力传感器（5kg、0—20mV）→ ATC600张力控制器（**内部PID闭环**）→
BOSENSE TBA420功放（0—10V入、0—24V/4A出）→ POC-050L对轴型磁粉离合器 → 卷材
张力对象；ED3L-08AEA伺服经POC耦合收/放线轴，当前配置在CSP位置模式。

## 二、用户当场裁的三条

| # | 裁决 | 最要紧的后果 |
|---|---|---|
| 1 | **主战场是引擎，WDS消费** | 导轮接触、蹭边、执行器/传感器物理、喂料前沿在`physics-engine`原生长成通用机制；WDS改为调用。兑现0015"把物理搬进来"，代价是WDS已跑通的粘滑/自由轮/移动边界要在引擎侧重做一遍 |
| 2 | **机制级先跑通，不冲定量** | 判据一律取**解析靶标**（绞盘闭式、互补条件、镜像反对称、闭环阶跃闭式、能量耗散账），不取现场数据。产物永久标`hypothesis_only` |
| 3 | **张力控制建到"磁粉离合器+理想PID"层** | 建电流→扭矩→张力的被控对象与理想PID；**不复现ATC600的实际回路** |

裁决2的出处不是保守，是WDS`research/05`第三节已经点清的事实：轮有效接触半径、
带-轮μ_∥/μ_⊥、轮轴实际偏斜角、WII物理时间线与`tool_to_tape_exit`标定、带材
EA/EI/GJ与密度——**五项只有现场实测能补，代码堆不出来**，且横漂幅值对其中三项
是一阶敏感的。在它们补齐前，任何定量数字只有机制意义。

裁决3的出处：ATC600无公开的完整通信/参数/寄存器手册（`ED3L_张力控制资料包`
2026-06-03已核，官网只有一页产品资料），POC-050L的L后缀线圈参数厂家资料也没有。
**复现一个拿不到参数的黑箱回路，写出来的PID系数是编的**——按0052通则，
猜出来的裁决比不裁更坏，这里同理：猜出来的控制器比没有控制器更坏，
因为它看起来像真的。

## 三、0034第四节的触发条件已到达——重开并重新裁决

0034第四节原文写明触发条件：**"WDS碰撞预演批次或case2给出带法兰导轮的书面需求
时，本条重开并另立决策记录。"** 用户2026-08-17点名"带材蹭边"就是那份书面需求。
本节即所立的记录。

**裁决：仍然不改spec/11的形状词汇。** 但理由与0034当时不同——0034当时是"没有
真实牵引"，今天牵引来了，改成"**牵引来了，而它要的东西不在词汇层**"：

1. 蹭边接触要的是法兰的**内环面**（带材跑偏后边缘顶上去的那个面），不是带法兰
   圆柱这个复合形；
2. `modelgen.generate_spool`按0032已经把带法兰带盘**精确分解**为`barrel`、
   `flange_low`、`flange_high`三件独立`FiniteCylinder`，法兰贴在筒两端外侧
   `|z| ∈ [W/2, W/2+w]`，三件互不重叠，且产出的每件上`flange_outer_radius_mm`
   恒为`None`。**内环面就是`z = ±W/2`这张平面限制在环带`r ∈ [R_筒, R_法兰]`上**——
   既有原语已经表达得了；
3. 因此本轮新增的词汇在**接触侧**（环带限位面），进`contact.py`，
   **不进`shapes.py`**。

**同时维持`geometry.mass_properties`对带`flange_outer_radius_mm`的圆柱失败关闭。**
那条缺口问的是"带法兰圆柱的质量分布"，而接触求解不需要复合体的惯量——
**它的触发条件（有人要算带法兰圆柱的质量属性）没有到来**，不能借这一轮顺手关掉。
把两件事分开，是因为0034把它们写在同一节里，而它们的牵引不是同一个。

## 五、判据来源——"机制级"靠这张表兑现，不靠自称

| # | 靶标 | 档 | 守哪一位 |
|---|---|---|---|
| J1 | 绞盘（Euler-Eytelwein）`T₂/T₁ = e^{μθ}` | 第1档解析 | S6.5：带材绕圆柱的粘滑摩擦 |
| J2 | 单边接触互补条件：`g > 0 ⟹ f ≡ 0` | 零容差 | S6.6：蹭边不许两侧同时出力 |

| J4 | 一阶对象＋PI闭环阶跃响应闭式（超调、时间常数、静差） | 第1档解析 | S6.3：张力控制过程 |
| J5 | 扭矩—张力换算`T = M/R(n)`，`R`随匝数生长 | 第1档解析 | S6.3＋S5.4 |

## 六、诚实边界（同批写进模块docstring与案例页，不写在这里就算没写）

1. **杆模型原理上看不见边缘载荷下的板屈曲模态**（WDS`research/04`第5.3节，
   `research/05`第2.3节复述）。所以蹭边**只给事件区间、边缘力密度与滑距的上界
   估计**，不给"会不会屈曲"。真定量必须过壳FE交叉裁决，那不在本仓；
2. 全部产物标`hypothesis_only`，理由是第二节裁决2的五项实测缺口；
3. 本轮的带材**没有扭转自由度**（`section_beam`只有一个easy-axis站点），
   所以边缘点由中心线加半宽生成时，**假定材料标架不绕切线转**。这是一条声明
   不是一个实现细节——扭转是0029已登记的欠账，触发条件是本条被真实需求顶穿；
4. 接触体仍是质点＋半径、**没有力矩**（0051）。本轮不改这条，
   所以导轮自旋是**给定的运动学**（`motion`时间线），不是解出来的动力学。
