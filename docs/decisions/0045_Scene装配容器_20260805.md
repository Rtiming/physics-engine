## 一、为什么是"加一层"，不是"把加载器改成装配容器"

`scene.py`的文件加载器**有真实消费方在用**：`pe-scene`两个子命令、
`examples/collision_preview_cell.scene.json`、`tools/bench.py`、
四个测试文件。它服务的是"场景内容100%住在文件里"那条路（MuJoCo/Gazebo形制，
决策0011），那条路今天成立、将来也成立。

装配容器服务的是另一条路：**场景内容由调用方在进程内声明**。
两条路不是同一件事的两种写法，判据很硬——**场景文件表达不了运动源与驱动器**。
`MotionSource`是一个带`pose_at`的对象，`ActuatorDeclaration`带命令空间与时延；
要把它们写进场景文件，得先给它们定一份跨边界字节形制，而那是一个面
（轴1规则1），要先进`engine_facets.py`登记。**今天没有任何消费方要求
"把一条位姿时间线写进场景文件"**，所以不预支（三前提之二）。

于是：

- 加载器的公开面**一个都没动**——`load_scene`、`Scene`、`SHAPE_KINDS`、
  `register_shape_kind`、`SCENE_FACET`、`SCENE_CANONICAL_PROFILE`
  的签名、行为与产出字节逐字节不变；
- 唯一被碰到的既有名是`SceneError`，改的是**类文档**（说明它现在同时服务
  文件加载与装配两条路），不是行为。共用一个异常类是有意的：两条路失败时
  调用方要做的是同一件事（拒绝这个场景），而`pe-scene`已经在按这个类捕获，
  分裂它会让一个装配期错误从退出码2掉成栈回溯；
- **没有做"从场景文件建装配"的通道**。理由同上：那要先定面。

## 二、公开面

`scene.py`的`__all__`加5项：`SceneAssembly`、`FinalizedScene`、
`AssembledBody`、`ContactPair`、`ASSEMBLY_MANIFEST_PROFILE`。

`SceneAssembly`（可变，装配期）：

    declare_body(posed)                     登记一个体（几何+静态位姿）
    declare_motion_source(body_id, source)  把运动源绑到体上
    declare_actuator(body_id, actuator)     把驱动器声明绑到体上
    declare_contact_between(a, b)           **按对**声明要算接触的两个体
    declare_allowed_pair(a, b)              声明允许重叠、不报事件的一对
    finalize() -> FinalizedScene            一次性统一校验，之后容器封死

`FinalizedScene`（冻结）：`scene_id`、`bodies`、`contact_pairs`、
`allowed_pairs`，加`body_ids`、`posed_bodies_at(t_s)`、
`assembly_manifest_bytes()`。

**`posed_bodies_at(t_s)`与`allowed_pairs`不是两个新概念——它们正好是
`collision.BroadPhaseCollisionQuery(bodies, allowed_pairs=...)`的两个入参。**
这是本批"沿用既有消费方，不另造一套"那句话的落点，且有门守着
（`test_scenario_six_feeds_the_existing_collision_query`）。

## 三、四条设计判断

### 3.1 组装期只登记，交叉引用一律留到`finalize()`

spec/10第一节第3条原话是"延迟实例化：组装期只登记，`finalize()`统一实例化
并做类型校验"。本层照办，并且**能说出这条买到了什么**：
先声明接触对、后声明体，与反过来，必须是同一个场景——
**声明的次序不该决定装配成不成立**。有门守着
（`test_declaration_order_of_bodies_and_pairs_does_not_matter`，
两种次序的清单字节逐字节相同）。

例外只有一处：**类型**在登记那一刻就查。一个不是`PosedBody`的东西在登记时
就说得清是错的，留到`finalize()`只会让错误离现场更远。

### 3.2 接触**按对**声明，不设全局表

`declare_contact_between(a, b)`只记账。**没有"全体两两自动检测"这个入口**，
理由两条：接触对数随体数平方增长；而且自动生成的对**没有人声明过它的意图**——
它既说不出自己为什么存在，也说不出什么时候该消失。

这不是新形制：本仓的`allowed_pairs`一直是按对声明的（沿WII相邻连杆忽略），
这里是同一条纪律用在另一侧。

### 3.3 `allowed_pairs`沿用既有语义，与接触对**必须互斥**

`allowed_pairs`的语义是`collision.BroadPhaseCollisionQuery.check_state`
定的：**在白名单里的对直接`continue`**——即"允许重叠、不报事件"。
本层沿用这个名字与这个语义，一个字都不改，类型也保持
`frozenset[frozenset[str]]`。

于是"一致性"有了唯一说得通的定义：**互斥**。
一对既声明成"这一对的接触要算"、又声明成"允许重叠不报"，是两条对同一对
给出相反处置的声明。`finalize()`当场炸。

（考虑过另一种读法："声明的接触对之外全部进`allowed_pairs`"。**否决**：
那正是要避开的平方枚举，而且会把一个派生量写成一条声明。）

### 3.4 位姿只能有一个来源

一个体要么带静态位姿、要么带运动源，**两样都给即拒**。

本层**不发明**"挂载位姿∘运动源位姿"的复合约定。要定那个约定，得先回答
"运动源给的是世界位姿还是挂载系里的位姿"，而spec/10第二节一个字都没写。
默认挑一个的后果与`motion.py`那五条插值语义是同一种：两个调用方算出不同的
物理，两边都以为自己是对的（0038第二节）。

代价是调用方要把挂载位置写进运动源本身——`examples/winding_line_scene.py`
的`_turntable(source_id, x_mm, z_mm, spin)`就是这么写的，一行的事。

## 四、场景⑥装出来了什么（plans/04第九节的对账）

`examples/winding_line_scene.py`，可直接跑：

    .venv/bin/python examples/winding_line_scene.py

| 场景要素（用户原话） | 装配里是什么 | 状态 |
|---|---|---|
| 缠好的盘子慢慢转动放线 | 3个体（筒+两片法兰），各带`AnalyticPose`绕z自转 | 装出来了 |
| 经过两个导向轮 | `generate_roller`各1个体；导轮2带0.8mm轴向未对中 | 装出来了 |
| 一个张力轮 | 1个体 + `ActuatorDeclaration`（磁粉离合器，20ms时延） | **声明装出来了，`apply`仍然没有**（0038边界） |
| 缠到另一个三维盘上 | 3个体，`AnalyticPose`自转 | 装出来了 |
| 同时给这个盘加偏移 | 同一条`AnalyticPose`叠沿z的横动（±8mm） | 装出来了 |
| 模拟实际蹭边 | `带材↔收线盘法兰`两对接触被显式声明 | **只是声明，接触没算** |
| 各轮上的偏移 | 多体装配 + 静态未对中位姿 | 装出来了 |

数字：**13个体、10对接触、4对允许重叠、6个运动源、1个驱动器**，
`finalize()`通过。

四段带材用`RoundedBox`（12mm宽、0.15mm厚、圆角为零）而不是胶囊：
胶囊是圆截面，表达不了"带"（plans/04零之一）。带材落在相邻两回转体的
**外公切线**上（闭式：切线长`√(d²−Δr²)`、倾角`arcsin(Δr/d)`），
但那只是一个**静态初始摆放，不是解出来的带材路径**。

蹭边不是意外：收线盘自由行程只有±4mm（法兰内侧到中面10mm，带材半宽6mm），
而横动幅度声明成±8mm，**必然压到法兰**——用户要的就是这个。

**这条场景仍然算不出任何接触**，脚本自己在最后一行说这句话，
且有门守着这句话不许被删（`test_the_example_script_runs_and_says_what_it_did`）。

## 五、门：本轨没有物理判据，门只能建在失败关闭与确定性上

48条测试。**十四条必红，逐条只犯一个错**——别的字段一律合法，
这样"红了"才证明得了是那一条红的，不是别的规则顺手拦下的。

用户点名的六条：

| # | 非法装配 | 错误消息指向 |
|---|---|---|
| 1 | 重复`body_id` | `duplicate body_id in assembly: ['body/a']` |
| 2 | 接触对指向不存在的体 | `contact pair (…) references unknown bodies: ['body/ghost']` |
| 3 | 运动源绑到不存在的体 | `motion source bound to unknown body 'body/ghost'` |
| 4 | finalize后仍试图修改 | `the scene is finalized; <方法名> is no longer allowed`（**五个入口逐个验**） |
| 5 | 同一对声明两次 | `contact between … is declared twice`（**正反两序都验**） |
| 6 | `allowed_pairs`与声明不一致 | `declared both as a contact pair and as an allowed pair` |

另外八条：驱动器绑到不存在的体、一个体两个运动源、一个体两个驱动器、
体与自己声明接触、`allowed_pairs`指向不存在的体、一个体既有静态位姿又有
运动源、空装配、`scene_id`无命名空间；加五条登记期类型门。

不可变性两侧都有门：finalize前受理、finalize后五个入口全拒；
`FinalizedScene`是frozen dataclass（四个字段逐个验`FrozenInstanceError`）、
只交出元组与frozenset；**炸掉的迟到声明不许泄进已产出的场景**
（半截成功比直接失败更糟）。

**确定性要跨进程验。** 同一进程里哈希种子是同一个，进程内比两次抓不到
"次序随`PYTHONHASHSEED`变"这类隐患。所以确定性门起子进程跑
`examples/winding_line_scene.py`两次（`PYTHONHASHSEED=0`与`12345`），
比stdout逐字节——`cases/generator_determinism`对`modelgen`同款做法。
承诺的是**次序即声明次序**，不是"排过序"，所以另有一条门断言清单没有被
悄悄排序（把清单排一遍序也能让"两次相同"那条绿，而那是另一份契约）。

## 六、克制住没做的（**这一节是本页的重点**）

三前提之二明写"不为想象中的第三个消费方预支通用性"。以下每一条都想过、
都能写、都**没写**，因为场景⑥不要：

1. **父子/运动学树**。一个盘的筒与两片法兰是**三个独立的体、各带各的运动源**。
   加一层"刚体组"很诱人，但那是约束或运动学树，spec/10里没有它，
   场景⑥用六条各自独立的时间线就能表达；
2. **从场景文件建装配的通道**（`SceneAssembly.from_scene(loaded)`）。
   要它就要先给运动源与驱动器定字节形制，而那是一个面；
3. **把`load_scene`重写成走装配容器**。会改错误消息、动既有测试，
   而收益只是"少一份校验代码"；
4. **场景级`horizon_s()`与运动源horizon的相容性校验**。越界由运动源自己的
   `extrapolation`裁（有门），装配层不发明第二套；
5. **`FinalizedScene.motion_sources`直通`assert_replayable_for_fingerprint`**。
   一个property的事，但今天没有哪个运行要声称指纹；
6. **接触对的分组/优先级/求解器提示**（"这一对用惩罚法、那一对用互补"）。
   接触内核不存在，现在定就是替它拍板；
7. **`GeneratedPart`→`PosedBody`的转换助手**。场景⑥要转13次，
   但那是**摆几何**，是调用方的事——留在`examples/`里；
8. **落盘装配产物**（`assembly.json`一类）。没有消费方要读它；一旦要落，
   先进`engine_facets.py`。

## 七、面清册：**这一批没有登记任何东西**，理由写在这里

`engine_facets.py`一个字未改。本批**没有落任何盘、没有跨任何边界**：

- 装配容器全在进程内；
- `examples/winding_line_scene.py`只往stdout打印人看的文本；
- `assembly_manifest_bytes()`产的是规范字节，但它**不是面**——
  与`modelgen.MODELGEN_PROFILE`逐条同理由：不落盘、不进场景文件、
  不进run package，只作"同一份装配声明是否产出同一份清单"的**进程内比较基准**。
  `ASSEMBLY_MANIFEST_PROFILE`的注释里写死了这一条，并写明
  "哪天它要落盘或要被消费方读，必须先进面清册"。

本仓因为忘了这条纪律违反过轴1规则1近两个版本（决策0017），所以
**"没登记"这件事本身要被说出来**，不能只是没做。
