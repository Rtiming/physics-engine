# 0033 接触摩擦的状态边界：粘着锚点是真历史（2026-08-05，调研后裁决）

状态：已裁决。用户口径：**"我也不是很懂，你分析一下调研一下，反正我的要求就是要最真实的那种。"**
本页先说清冲突是什么，再给调研结论，最后落裁决——**按"最真实"这条标准裁**。

## 一、冲突长什么样

spec/13规则2（已冻结）写着：可迁移内核按**无状态纯函数 + 显式状态数组**书写。

而查实WDS那边：这条**只对能量层成立**。接触摩擦层带三样东西——
粘着锚点（`StickAnchorState`）、冻结的接触决策（`FrozenContactDecisions`）、
活动集冻结迭代数——全是求解器内的跨步/跨迭代状态。

按字面读，T5搬到接触那天就撞车：要么破规则2，要么把这三样砍掉。

## 二、调研结论：**粘着锚点不是实现便利，它是物理**

带粘着的库仑摩擦**本质上是历史相关的**，这一点在文献里是共识而不是争议：

- 摩擦的切向牵引力经**return-map算法**求得，**滑移变量是历史相关的内变量**
  （history-dependent internal variables），逐接触点局部存储；
- 切向相对位移被**分解成可逆的"粘"分量与不可逆的"滑"分量**，后者在超过屈服势时累积；
- 这与塑性力学的形制是**同一个**：塑性应变就是这样一个历史内变量；
- 发生滑移时**锚点状态改变**，且锚点必须被更新以保证步末接触力落在摩擦锥内；
- 更精细的模型（rate-and-state）进一步引入表示接触面成熟度的状态变量，
  它不仅依赖滑移速度，**还依赖接触的历史**。

一句话：**"这一点现在粘着还是滑动"这件事，不能从当前位形算出来，只能从历史知道。**
砍掉锚点得到的不是"更干净的实现"，是**另一种物理**——一个没有静摩擦的世界。

用户要"最真实的那种"，那么锚点必须留。

## 三、裁决：把它**外提进状态**，规则2一字不改

三条候选里取**第二条**（把接触状态显式外提成状态数组的一部分），理由如下。

**这不是在规则2上开口子，是把规则2读对。** 规则2说的是"无状态**纯函数**"——
它约束的是**求值方式**：给定状态，函数的输出只由输入决定，不看任何藏起来的东西。
它没有说"这个系统没有状态"。粘着锚点是**系统的状态**，不是求值器的私货。
把它放进状态数组，规则2就自然成立；把它留在求解器里，规则2才被破。

**spec/12第2.2节早已给了它位置**：状态形制那一节明写要区分"真历史"与"求解器便利"——
塑性set、粘着锚点是**真历史，必须进状态并随状态一起被复现**；
"上一步的切线矩阵"这类只是缓存，不进状态；**分不清就都当真历史（保守方向）**。
`state.py`的`StateField.is_history`与`StateLayout.history_fields()`就是为这件事建的，
今天已经有门守着。**接口早就在那儿等着了，本裁决只是确认它就是给接触用的。**

**复现性是硬约束，不是偏好。** 本仓的复现纪律（轴3规则5）押在"状态能pack成向量"上：
不可重放的来源不得声称指纹。锚点若藏在求解器实例里，那个运行就**没法被逐字节复现**——
换句话说，把锚点留在求解器里不只是违反规则2，它还会让接触工况的产物**不能进run package**。
这条比架构洁癖重要得多。

## 四、由此产生的三条执行条款（进spec/12第十一节，T5搬接触时生效）

1. **接触状态进`StateLayout`，且`is_history=True`**。每个接触点的锚点、
   粘/滑标志、累积滑移量都是自由度块，随状态被pack、被复现、被逐字节对拍。
2. **活动集冻结迭代数是缓存，不进状态**——它丢了只影响速度不影响结果。
   这条是spec/12第2.2节"真历史 vs 求解器便利"分界的第一个真实判例。
   **但若无法证明它不影响结果，按保守方向也当真历史。**
3. **接触工况的run package必须携带初末接触状态**，否则不得声称复现指纹。

## 五、代价，如实说

状态向量会变大且**变长**：接触点数随构型变化，而`StateLayout`今天是**固定布局**。
这意味着搬接触时要么允许布局随载荷步重建（并把布局指纹一起入产物），
要么给接触状态预留上界。**这条今天不裁**——它要等第一块真接触内核的形状清楚了再定，
届时另立决策记录。本页只钉死"锚点是真历史、必须进状态"这一条。
