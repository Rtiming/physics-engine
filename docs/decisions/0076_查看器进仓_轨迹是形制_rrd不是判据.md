# 0076 查看器进仓：轨迹是形制，`.rrd`不是判据

日期：2026-08-18　　状态：已落地
承接[0074](0074_真实网格进接触_碰撞归本仓_距离场是根本形制.md)第5.3／5.4节与第六节**阶段五**。
本页只裁查看器这一条轨，**不碰内核**——`src/`字节改动为0（实测）。

## 一、裁决一：查看器进仓，但它的依赖住在`tools/view/.venv`

形制与`validation/`（0025）、`tools/model/`（0073）**逐字同源**，三条硬边界一字不改：

1. 永不进`dependencies`，**连`[optional-dependencies]`都不进**；
2. 永不被`src/physics_engine`import，一行都不许；
3. 重依赖独立venv——rerun只装进`tools/view/.venv`。

**这三条在这里比在别处更硬，因为数更大**：rerun的wheel实测**133.6 MB**，
装完的venv实测**521 MB**。`tools/model/`那两个工具是纯标准库，
`validation/`的python-fcl连它的零头都不到。

**新增一道门**：`tests/governance/test_view_tools_stay_out_of_the_kernel.py`。
它与`test_model_tools_stay_out_of_the_kernel.py`**同源不同料**——
那道门看的是**import路径**（顶层名字`tools`），本门看的是**依赖名字**（`rerun`）。
两道都要在，因为它们防的不是同一个失手：

* 那道门挡"内核`from tools.view import replay`"；
* **本门挡"有人把`rerun`直接写进`src/`"**——那种写法根本不经过`tools.view`
  这个名字，**上一道门一个字都看不见**。

## 二、裁决二：选rerun的理由要落纸，不是只写"选了rerun"

0074第5.3节那张表的结论原样搬进`tools/view/README.md`第二节，
并补三条本轮**实测**到的：

| 项 | 实测 |
|---|---|
| 版本 | `rerun-sdk==0.34.1`（PyPI上已有0.36.0，**本轮不采用**——0074核过的是0.34.1，换版等于换一个没核过的东西） |
| 许可证 | `MIT OR Apache-2.0`（`importlib.metadata`的`License-Expression`字段），与本仓MIT相容 |
| 可得性 | `rerun_sdk-0.34.1-cp310-abi3-macosx_11_0_arm64.whl`，本机Python 3.13装得上 |

**"可得性"这把尺子对我们自己也得用**：0074把`openvdb`判出局用的正是它
（"出局（可得性，不是能力）"）。

**一条0074没写、本轮实测到的事**：rerun的CLI**默认开启匿名使用统计**，
首次运行会打印一段说明。`setup_view_env.sh`因此显式跑一次`rerun analytics disable`。
它不改本仓任何字节，改的是使用者自己的rerun配置。

## 三、裁决三：**产轨迹与画轨迹是两个环境，中间只有一份JSON**

这是本页最要紧的一条结构裁决，不是省事：

* `trace_from_closed_loop.py`——`physics_engine` ＋ 标准库，**不认识rerun**；
* `replay.py`——rerun ＋ 标准库，**不认识`physics_engine`**。

于是：装不上rerun的机器**照样能产轨迹**；没有引擎的机器（要给别人看的那一台）
**照样能画**；而`src/`两边都不认识。

**这条承诺配了一道门**（governance那份的第四条判据：产轨迹侧不许import rerun）。
理由是注错验证当场量到的一件事：**植入"产轨迹侧import rerun"这个缺陷时，
只有第四条判据红，第三条（全仓只有`tools/view/`认识rerun）不红**——
因为`tools/view/`本来就在第三条的豁免里。
**第四条不是冗余，它守的是别人守不到的那一格。**

## 四、裁决四：`.rrd`不是判据

本目录产物**永不进任何门**。理由是本仓既有纪律
（spec/08规则1：实测数不作金标）在查看器上的直接推论——
**一个查看器同时当判据，等于让被验的东西自己出考卷**。

`cases/closed_loop_tension_step`那三条门判的是`generate_oracle.py`那份
**独立闭式解**，与本目录零交集。本目录画的是同一次运行，
**但它画错了不会有人红**——所以它不许被信。

一条实测旁证：演示轨迹的峰值`1.1375139838369677` N，
案例清单的闭式金标`1.137505182988744` N，相对差**7.7e-6**——
内核一阶积分器对精确解的离散误差，正是案例门本来就在容忍的量。
**这个数说明轨迹画的确实是门在判的那条运行，但它不代替那道门。**

### 4.1 本轮实测撞出来的一条更硬的理由

**`.rrd`不是逐字节可复现的**：同一份轨迹连画两次，两次SHA-256实测不同
（记录里带`log_time`与随机`recording_id`）。
而0001代码三前提第3条是"消费方采纳后既有产物指纹**逐字节不变**"。
**一个指纹不稳的产物在结构上就当不了判据**——这不是纪律选择，是它自己的性质。

### 4.2 顺带抓到的一条落盘缺陷（本轮自查）

**`rr.save()`返回不等于文件写完。** 第一版`replay.py`在`save()`之后立刻`stat()`，
报出321475字节，而进程退出后文件实际是343875字节——**回执里那个数是假的，差22400字节**。
病根是rerun的落盘异步（数据在记录被关掉时才冲干净）。

修法：`save()`之后显式`rerun_shutdown()`再`stat()`。
这条与`run_package.publish_package`那套"写完复验哈希"同源——
**声称写了什么与实际写了什么必须是同一个数**，而回执是本工具唯一对外声称的东西。

## 五、裁决五：`engine_run_trace`形制**写成草案，不偷偷进`src/`**

"任何跨边界字节形制先进`engine_facets.py`登记再落盘"是硬纪律（AGENTS.md／0017）。
而`engine_facets.py`在`src/`里，本轨的卖点之一是**它不吃源码预算**。

**做法**：形制写进`tools/view/README.md`第五节作为草案；
落盘的字节里`"facet": "engine_run_trace"`照写，
**这样它一旦升进清册，已有的轨迹文件不用改一个字节**。

**待裁（后续批次）**：`engine_run_trace`要不要升进`engine_facets`。

* **升**——补一条`ENGINE_RUN_TRACE_FACET`出生draft，理由是它确实跨了边界
  （两个环境之间、两台机器之间）；
* **不升**——明确记成"工具间的私有形制，不作跨边界承诺"，
  理由是它今天只有一个生产者一个消费者，而0001代码三前提第2条要求真实消费方。

**今天两者都没有裁**，本节是这个状态的如实记录，不是拖延的借口。

### 5.1 形制里三条"没有默认值"，逐条有出处

1. **`units`缺席即抛**——与`tools/model/mesh_aabb.py`同一条纪律。
   一个把mm当m画的查看器，**出来的图看着还很合理**；
2. **`synthetic`缺席即抛**——0017抓到的真实缺陷是
   `examples/collision_preview_cell.scene.json`里的AABB是**编的**。
   查看器把这个风险放大一个量级：合成圆柱与真实资产的网格**长得一样可信**。
   所以这一条比"留空比填默认值诚实"更强：**它不许留空**；
3. **`stride`缺席即抛，且必须配`undecimated_extrema`**——
   演示轨迹的源是20万步，抽样是必须的，**而抽样会漏掉峰值**，
   那正是本案例三条判据里的第一条。未抽样的极值单独算一遍写进字节，
   由`replay.py`贴成静态说明：**曲线上看不到的那个峰，文字里写着**。

## 六、注错验证表

判据7条（4条边界判据 ＋ 3条必红/反面用例），共8个测试函数。
两轮：**改判据**（M）与**植真缺陷**（D）。每轮清`__pycache__`。

| 轮 | 注错 | 结果 |
|---|---|---|
| M0 | 不改 | 8绿 ✅ 基线 |
| M1 | `imported_roots`丢掉`ImportFrom`分支 | **红**：植入用例 |
| M2 | 禁名集合缩成只有`rerun` | **红**：植入用例＋pyproject植入用例 |
| M3 | pyproject判据只读`dependencies` | **红**：optional植入用例＋防空跑用例 |
| M4 | 发行名不把`-`归一成`_` | **红**：optional植入用例 |
| M5 | pyproject读成空字典（空跑） | **红**：optional植入用例＋防空跑用例 |
| M6 | 判据改成扫字符串而不是AST | **红**：三条（含"不许误报"那条反面用例） |
| M7 | 产轨迹侧的路径指向不存在的文件 | **红**：第四条判据 |
| D1 | 内核里植入`import rerun` | **红**：判据1＋判据3 |
| D2 | `[optional-dependencies]`里植入`rerun-sdk` | **红**：判据2 |
| D3 | 产轨迹侧植入`import rerun` | **红**：**只有判据4** ← 见第三节 |
| D4 | `tests/`里植入`from rerun.blueprint import …` | **红**：判据3 |

**没有发现空门**：7条判据每一条都有至少一个注错能单独把它打红。
D3那一行是本轮最有价值的一格——它证明第四条判据不是冗余。

**两条反面用例**（判据不许误报、判据不许空跑）是照
`tools/model/`那轮"抓到自己两道空门"的教训**预先**补的：
一条会误报的判据与一条不报的判据一样坏，因为误报会被人加豁免，
而豁免一旦开口子就再也关不上。

## 七、本页明确不做的

* **不改`src/`一个字节**（实测0）。`engine_facets.py`的登记留给后续批次；
* **不把`.rrd`接进任何门**（第四节）；
* **不给接触点接真实接触求解器**——今天`points`块是几何构造的切点，

  体积问题见0073第二节Bullet issue #2918那297 MB的账；
