# 0014 用户级定位与性能第一（2026-08-05凌晨，用户裁决，定位纠偏）

状态：已裁决。用户原话：**"就算是我个人项目，你要做用户级别的要求。
用户的电脑上，我永远不知道是什么状态，永远要把自己的性能拉到首位。
你这个定位错了，修改策略和文档。"**

## 一、纠的是什么偏

此前的策略与文档把性能问题往**环境**上归因、往**舰队设施**上找解：
"等机器安静再跑"、"重计算上master"、"多会话协调错峰"。这些对**我们
自己的开发内循环**是对的止痛药，但被错误地摆到了产品策略的位置。

**用户级定位下它们全部不成立**：用户只有一台状态未知的机器——
可能正忙、核少、无集群、无wheelhouse、无orangepi。产品不能要求用户
的机器安静，不能把吞吐外包给一个用户没有的集群。

## 二、由此立的三条产品性能法则（进spec/13 v0.2）

1. **单机冷启动性能是第一指标**。集群只是倍数，不是答案。引擎与其
   设施的每个公开操作在"一台任意状态的机器"上要快，且有**声明的
   延迟预算**（首批实测入册：import 110ms、场景校验端到端0.22s、
   验收full 3.4s、wheel 30KB离线装）。
2. **争用韧性**：功能性操作**永不因宿主负载拒绝执行或改变结果**。
   负载敏感只允许存在于开发计时裁决（SLA判not_evaluated），
   绝不进功能路径——这是把WDS/引擎既有的"功能与计时正交"升格为
   产品法则。
3. **零设施假设**：运行时零依赖、单wheel离线安装、不引用任何舰队
   资源——这些今天已是事实，从今天起是**承诺**（破坏它们=破坏性
   变更，走决策记录）。
