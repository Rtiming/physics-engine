# 0025 同行库对比实验的身份与合规（2026-08-05）

状态：已裁决并已执行。承接[0015](0015_从治理层走向真引擎_案例与性能_20260805.md)
**张力B**（同行库的身份是oracle，永远不是依赖）与用户裁决原话
"**把别人的库下载下来进行对比实验**"。

本页把张力B从一段登记文字变成可执行的边界，并记下第一次执行的结论。
执行体：`validation/`、`cases/peer_fcl_distance/`、`tests/cases/test_peer_fcl_distance.py`。

## 一、身份边界（三条硬的）

1. **同行库永不进`dependencies`。** `pyproject.toml`的`dependencies = []`是0014立的承诺。
   同行库连`[optional-dependencies]`都不进——0016给NumPy开的加速档那条口子是为
   **本仓自己的数值内核**开的，不是给同行库的通道。
2. **同行库永不被`src/physics_engine` import。** 一行都不许。
   自检：`grep -rn "import fcl" src/` 必须零命中。
3. **独立目录、独立venv。** 同行库只装进`validation/.venv`（已被仓根`.gitignore`的
   `.venv/`一行覆盖）；主环境保持只有`pytest`与`ruff`两个dev依赖。

再加一条来自轴7规则4的纪律：**只调用，不移植**——哪怕许可证允许复制。
抄了同行的实现，对拍就不再独立，这道门就从"两个证人"退化成"一个证人照两遍镜子"。

## 二、许可证结论

本仓LICENSE是MIT，GPL/LGPL类会传染。沿用WDS已立的边界（GPL类只作对拍、不得复制代码；
可复制来源限MIT/Apache），并补一条更严的"只调用不移植"。

第一批实测结论（逐库明细与本地核验记录见`validation/LICENSES.md`）：

| 库 | 许可证 | 结论 |
|---|---|---|
| python-fcl 0.7.0.11 | BSD-3-Clause | 可装、**不复制代码**、不随本仓分发 |
| 随轮的 FCL 0.7.0 / libccd 2.0 / OctoMap core 1.9.8 | 均BSD-3-Clause | 同上。OctoMap需盯：其core是BSD而octovis是GPL-2.0，**本次wheel只含core的两个二进制** |
| numpy 2.5.1 / Cython 3.2.9 | BSD复合 / Apache-2.0 | 可装、不复制、不分发 |

**本次没有GPL/LGPL依赖进来，不触发传染风险。**
一条如实记下的缺口：该wheel未随附三个第三方二进制各自的许可证原文，
上表那三行的结论来自上游公开声明而非本地文件。只本机装、不再分发时无碍；
将来要随任何产物分发，必须先取回原文入库。

## 三、版本钉死的方式

三层，缺一层就钉不住：

1. **依赖清单钉版本**：`validation/requirements-peer.txt`全部用`==`；
2. **判据声明钉版本**：`cases/peer_fcl_distance/criteria.json`的`peer.pinned_version`，
   conformance测试逐次核对，装的版本与钉的不一致就**红**（不是warn，不是skip）；
3. **产物钉二进制**：每次对拍的manifest带`peer_library.bundled_binaries_sha256`
   ——wheel名相同而编译产物不同是真实可能，只钉版本号钉不住。

版本一动，四步一步不能省（`validation/README.md`第四节）：重跑语义复核 → 更新算子路由表 →
重算容差并重写理由 → 更新许可证页。**同行漂了而我们自动继承结论，等于把别人的回归当成我们的证据。**

## 四、对拍产物的溯源字段

产物走run package（轴4/5，用本仓自己的`publish_package`与`read_verified_package`），
manifest在spec/13第三节`runtime_environment`之上加一块`peer_library`：

| 块 | 字段 |
|---|---|
| `peer_library` | 名称、版本、许可证（含SPDX）、上游URL、**安装方式**、安装目标、随轮二进制逐个SHA-256、身份声明一行 |
| `runtime_environment` | Python版本与实现、平台、架构、numpy版本、**BLAS实现**、确定性等级 |
| `generator` | `algorithm_id`（带`algorithm:`前缀）、版本、源文件相对路径 |
| `sweep` | 种子、每格样本数、样本总数、注错模式 |
| `subject_under_test` | 被验的生产内核全名逐条列出 |

产物**不入库**：它带机器指纹，入库等于把一台机器的状态当成仓库事实。
落`work/`（已`.gitignore`），要留证据就留manifest那几行。

## 五、不一致时的处理纪律

0015的原话是"**同行的数不是真值，是另一个证人**：不一致时先怀疑双方"。落成四步：

1. **先查语义，不先查代码。** 两侧的对象定义、单位、四元数次序、算子语义先逐条对齐。
   本次对拍最贵的一条发现就出在这里：FCL的三条距离路**不是同一个算子**，精度差六个量级
   （`distance(signed=False)`解析精确、`distance(signed=True)`走libccd绝对约1e-6、
   `collide().penetration_depth`解析接触生成），拿一个开关跑完全部构型是不诚实的省事。
2. **请第三个证人。** 语义对齐后仍不一致，用**与两侧都无关的写法**独立算真值。
   本次用`fractions.Fraction`精确解段-段最小距离（枚举内部驻点+四条边界，
   与本仓的Ericson分支法是两种写法），只有最后开方落到float。
3. **结论按证据写，不按身份写。** 本次三条大偏差**全部判定为FCL错**：
   最坏一条FCL的相对误差45.6%（还是个分离构型），而本仓与精确真值逐位相同或差1e-14。
   同行库不因为是同行就获得推定正确。
4. **同行的缺陷入案例页的"已知失效清单"，但不入判据。** 把同行的bug钉成门，
   下一个版本修好了我们反而会红——这与spec/08规则1"实测数不作金标"同源。
   本次的做法：判据只判**路由到的那条可信算子**；FCL两条已查实会大错的路
   全程记录进产物的`observed`块，作为"同行也会错"的证据，不作判据。

## 六、第一次执行的结论（2026-08-05实测）

- 装上的是 **python-fcl 0.7.0.11**（PyPI预编译wheel，macOS arm64 / cp313，未本地编译）；
- **2700组固定种子输入**（球-球/球-胶囊/胶囊-胶囊 × 分离/擦边/穿透，每格300组），
  与本仓闭式解逐点对比：**最大绝对偏差2.27e-13 mm，接触判据分歧0**；
- 抓到**同行两处真实缺陷**（详见`cases/peer_fcl_distance/case.md`第五节），
  两处都用精确算术复核过，本仓是对的一方；
- 三条注错（四元数次序、漏减半径、胶囊半长当全长）**全部让门红过**——
  这三条都是**仓内自洽测试抓不到、只有另一个证人能指出来**的错，
  这正是"下载同行库做对比实验"这条裁决的价值所在。
