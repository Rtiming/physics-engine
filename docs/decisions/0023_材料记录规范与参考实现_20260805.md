# 0023 材料记录规范与参考实现（2026-08-05）

状态：已决并执行（T6 materials资产轨道）。面`engine_material_record` 0.1在T0闸门
（提交`fac8fe2`）已登记，本轨道只`import`不改`engine_facets.py`。

## 起因

spec/01模块地图materials那格写着一句话：「形制即规范种子：一份材料记录聚合
力学性质+光学性质+外观引用，各域各取所需字段」。这句话立了一年也还是一句话——
没有规范页，没有数据结构，没有门。T6把它变成
[spec/14](../spec/14_材料记录与物理性质_v0.md) + `src/physics_engine/materials.py` +
`tests/test_materials.py`。

## 落了什么

1. **spec/14（v0.1草案，不冻结）**：七条规则、记录形状、证据分级统一映射、
   按域取字段、mm↔m换算边界、六条最低红例、四条明确不做的。冻结条件三条写在页首。
2. **`materials.py`**：`MaterialRecord`/`MaterialProperty`/`EvidenceRef`/
   `AppearanceRef`四个frozen dataclass + 严格加载器`load_material_record`
   （字节锁在解析之前、未知键失败关闭）+ 内容地址自校验 + 单位后缀校验
   （走`identity`现成的）+ 域与证据校验 + `properties_for_domain`按域取字段
   + `converted_to`显式换制。零运行时依赖，只用标准库。
3. **`tests/test_materials.py`**：23条，六条红例逐条实测红过，另有十一条
   失败关闭与六条绿例（多域共享字段、按域报最弱分级、字节往返、显式换制）。

## 三个取舍

**取舍一：域是属性的标签，不是记录的分块。**
分块（`mechanics: {...}, optics: {...}`）更像WDS记录的样子，但它表达不了
`thickness_mm`同时属于两个域这件事——而这恰恰是聚合记录唯一的存在理由。
分块形制下这个字段只能写两遍，两遍就会漂移，漂移了聚合就白做。
所以采标签形：属性带`domains`，记录带`applicable_domains`，属性越界即拒。
这是本轨道两处增量之一，理由是两个消费方合起来才暴露的问题。

**取舍二：未测量的量取FTS的`unset`语义，不取WDS的占位零。**
WDS的形制是`axial_damping_N_s: 0.0` + `damping_status: "zero_unmeasured"`——
值是零，旁边一个状态字段说明这个零不是物理主张。这在WDS内部是自洽的
（它的求解器要一个数才能跑），但作为**跨域交换形制**它把风险留给了读侧：
读的人只要没看那个旁注字段，就拿到了一个看起来像标定结果的零。
FTS的`E_UNSET_HAS_VALUE`更严——没有值就是`None`，读侧不可能忽略。
跨边界形制取严的那一侧。WDS采纳时的迁移是机械的：`zero_unmeasured`→
`grade="unset", value=None`，求解器在自己那侧决定用什么数跑，
但那个数不再冒充材料属性。

**取舍三：换算表只登记纯长度量纲，复合量纲报错不猜。**
`EI_easy_N_mm2`要换到米制得先决定它是不是MPa。猜一个因子写进去，代价是
将来某天有人发现方向反了，而所有引用过它的指纹都得重来。
报错并在消息里指路（"resolve it in the consumer's adoption declaration"）
的代价只是现在多写一行采纳声明。这一条是spec/13"不知道就说不知道"的直接应用。
