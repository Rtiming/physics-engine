## 一、裁的是什么，以及为什么先做边界

0016第四节把光学的归属列作"仍被阻塞"：技术上可行（其数值路径落加速档），
但归属待裁。今天裁了：**进来**。

裁完之后本轨道的第一优先级**不是**光学算法，是边界。理由有三条：

1. **用户的原话就是先要分离**。"不要相互干扰"是这次裁决的一半内容。
2. **边界要先于第二个域到场**。spec/01第一节从2026-08-04起就写着"物理域之间
   互不依赖"，但那时只有一个物理域——**一条只有一个域的隔离规则不可能被违反，
   也因此从未被验证过**。第二个域进来的那一刻，是它第一次可能被违反、
   也是最后一次能廉价立起来的时刻。
3. **本仓有过同构的教训**：`cli.py`长期在写一个未登记的面，没有门拦得住，
   直到0017专门去收拾。域耦合一旦发生，代价比那件事大得多——两个域缠在一起之后，
   "把光学单独拆出去"就从改一行变成改一片。

所以交付顺序是：**spec/15 + 域隔离门 → 光学第一块 → 两个案例**。

## 二、边界的执行体（本轨道最重要的产出）

`docs/spec/15_物理域边界与跨域耦合_v0.md` 把spec/01那两句写成四条可判定规则，
加两条元规则；`tests/governance/test_domain_isolation.py` 是它的门。

**用AST静态扫import，不用运行时探测**，三条理由：①运行时只看得见"这次真的
执行到的"import，**函数体里的延迟import看不见**——而偷连最常见的形态恰恰是
延迟import（说是"避免循环依赖"）；②静态扫不导入被扫模块，所以NumPy加速档缺席时
门照样成立（0014零设施承诺）；③静态扫覆盖到今天还没有任何测试导入过的模块。
静态扫唯一的盲区是字符串动态import，由门⑤堵：**物理域与耦合模块里一概禁用
`importlib.import_module`/`__import__`整个机械**。

**五条门**（域间零依赖／域只向基座伸手／域不得import耦合／基座不依赖域／完备性
与动态import各一条）外加两条元门（登记表非空、扫描器自身能看见延迟import），
共16条测试。每条门的必须红都实注入实测过（改真实src、跑、再改回），
实测输出见spec/15第六节。两条最值得记的：

- 门③在包门面上的形态是"**域的公开名不进`physics_engine/__init__.py`**"。
  这条本来是靠记性守的硬纪律，现在是一行import就红的门。
- 门④**完备性**是前三条门不会慢慢空掉的唯一保证：`src/physics_engine/`下
  新模块不登记即红。没有它，新模块一个个进仓，门会一直绿、只是不再管任何事。

两条**反向**用例（门不许过严）：耦合模块同时依赖两个域**不该**被判违规。
一道只会说"不"的门与一道坏门无法区分。

**由此得到一条明确结论并写进spec/15第三节以免被当成疏漏**：
`physics_engine`包内，**物理域与`couplings`都是依赖图的叶子**——
组合发生在库之上（案例、消费方、examples），不发生在库之内。

`couplings/`模块位已留、今天不存在；耦合三型的选用规则蒸馏自research/03第二节
（**默认单向链起步，需要反馈才升分区，单体永远是最后选项**），不发明。

## 三、光学第一块：范围、取舍、数值形态

`src/physics_engine/optics/`（子包，五个模块）：

| 模块 | 内容 |
|---|---|
| `bessel.py` | `J1`：上升级数（`|x|≤12`）+ Hankel渐近展开最优截断（`|x|>12`），精度申报 |
| `diffraction.py` | 艾里斑`E(x)=2·J1(x)/x`、首零常量、以及**四道单位边界的换算函数** |
| `fts.py` | 归一化sinc、无切趾ILS与半宽、Norton-Beer三组系数与窗、切趾的通量代价 |
| `parameters.py` | 从`materials.properties_for_domain("optics")`取参数——**用现成的域间接口** |
| `errors.py` | `OpticsError` |

**范围严格限定在闭式解与一维变换**。明确不做的（负空间声明写在子包docstring里）：
二维FFT场传播、带切趾的ILS闭式、自切趾、相位误差、采样与混叠、偏振与相干、
以及"第二套FTS"。

### 3.1 数值形态：本块不做加速档，理由不是"来不及"

0016甲案：核心零依赖，NumPy只在可选加速档。**本块不做加速档**，
理由是本块全部公开操作都是**每次调用几十个浮点运算的标量闭式，没有数组可向量化**。
research/06已测出本仓的标度指数约1.05（线性、**没有可摊薄的固定成本**），
在这种形状上套加速档只会多出一层派发。

这是spec/13第一节义务1"优化先profile"的一个前置形态：**没有工作量的地方不谈加速**。
加速档的正当位置是二维场传播——那里才有真正的数组工作量，随下一块进来。

### 3.2 `J1`要自己造轮子，所以精度必须申报

`scipy.special.j1`不在选项里（0016），`math`没有贝塞尔。这是本块唯一一处
自造轮子，因此：

- **分段点12.0是实测选出来的**，不是猜的：两段各自的绝对误差随x一升一降，
  12附近交叉。四个候选（11/12/13/14）的最坏绝对误差分别
  2.60e-12 / **8.27e-13** / 1.24e-12 / 4.97e-12。
- **渐近段按最优截断**（项一旦不再变小就停）。渐近级数发散，写死项数的实现
  在中等x上会差好几个数量级——x=14处最优截断的绝对误差2.58e-15，
  而固定6项的相对误差2.7e-8（绝对3.6e-9）。
- **申报的是绝对误差不是相对误差**：`J1`有零点，零点邻域的相对误差没有意义
  （x=3.83处值3e-12、绝对误差9e-17、相对误差3e-5）。
- 申报值：**`|J1_算 − J1_真| ≤ 1e-12`，`x ∈ [0, 60]`**，1936个点实测最坏
  8.2734e-13（在x=12.028）。域外**未测**——渐近段只会更好是推断不是实测，
  按诚实条款写"未测"不写"成立"。
- **申报是被验的不是被声称的**：`tests/test_optics.py`有一条`batch`档门逐点跑
  那1936个点（0.23 s），**两个方向都断**——不成立要红，比实测松一个数量级
  也要红。案例只冻结16个采样点，16点选得再好也覆盖不了整段。

### 3.3 单位边界：本块最大的坑，每一处都有名字

0024立下的实践是"能量→力→加速度的每一处单位边界都要有名字"。
光学侧的坑更密，处理如下（全部写成有名字的常量或有名字的函数）：

| 边界 | 危险 | 处理 |
|---|---|---|
| 谱学波数σ=1/λ（周/米） ↔ 角波数k=2π/λ（弧度/米） | **差2π，不报错** | `RADIANS_PER_CYCLE`常量 + `spectroscopic_wavenumber_per_m`/`angular_wavenumber_rad_per_m`两个函数并存，逼调用点说清要哪个 |
| 角度 ↔ 横向空间频率`f=sinθ/λ` | 小角下几乎对，大角下静默错 | `spatial_frequency_per_m(half_angle_rad=…, wavelength_m=…)` |
| 孔径**半径** ↔ **直径** | **差2倍**，图样宽一倍不报错 | `airy_argument(aperture_radius_m=…)` 与 `airy_first_minimum_half_angle_rad(aperture_diameter_m=…)`，名字里带单位角色；常量`AIRY_FIRST_MINIMUM_DIAMETER_FACTOR`由首零除以π算出，不另写一个1.22 |
| 归一化sinc `sin(πz)/(πz)` ↔ 未归一化 `sin(z)/z` | **差π**，首零位置不同 | 函数名`normalised_sinc` |
| 单边最大光程差L ↔ 全程2L | **差2倍**，分辨率错且"看起来合理" | `DOUBLE_SIDED_OPD_FACTOR`常量，参数名`max_opd_m`并在docstring写明单边 |
| 毫米制记录 ↔ 米制光学 | **差1000倍**（0024那条bug的形态） | `OPTICS_LENGTH_UNIT = "m"` + `properties_for_domain(…, expect_length_unit="m")`失败关闭 |
| 未测量 ↔ 零 | `unset`被`or 0.0`吃掉 | `require_optics_parameter`拒跑并把证据分级带进失败信息 |

**光学域不另造材料通道**：`optics/parameters.py`只是`materials`的读者，
记录的加载、校验、内容寻址、换制全在`materials.py`。spec/14第一节
"一份记录聚合多域字段"本来就是现成的域间接口。

## 四、两个案例与它们抓到的三件事

`cases/scalar_diffraction_airy`（2条oracle）与`cases/fts_instrument_line_shape`
（2条oracle），生成器都走**与被验实现不同的算法**：贝塞尔积分的周期梯形求值、
`sinc(z)=1/2`的二分求根、切趾窗的复合Simpson积分。三件被抓到的事：

1. **Norton-Beer的weak与medium切趾窗在扫描端点附近不单调**。
   第一版把"窗单调不增"写成判据，当场红：
   `weak的窗在0.0492 m处回升了：0.381368→0.382054`。
   查下来是真的：C1为负，窗先跌到内部极小（弱x*=0.9684、比`A(L)`低2.726e-3；
   中x*=0.9648、低4.713e-3）再回升到C0；strong的C1=0所以单调。
   **Norton-Beer从未要求窗单调**，是判据写错不是实现写错。
   处理：删掉单调断言，改成把极小的位置与值钉成两条判据
   （`window_minimum_*`）——**它同时成了C1抄错的直接捕手**，
   因为极小落在端点内侧还是端点上完全由C1的符号决定。
2. **oracle的独立性要求的是算法不同，不是把物理常数换掉**。
   艾里案例第一版让生成器用它自己二分出的**真**首零去算首个暗环的角度，
   当场红（差7.502e-12）。红得对：引擎的1.22因子按定义就是**引用值**除以π，
   金标换成真值，这条判据测的就变成"那个引用值被截了7.5e-12"而不是单位换算。
   **这是本轨道最贵的一条发现。**
3. **生成器脚本的SHA门真的会拦人**：ruff自动修了生成器的一个括号，
   读侧当场红（`generator script changed without regenerating the oracle`）。
   0020设计这条门时说的就是这件事。

容差全部是**算出来的**（0024第三节的纪律）。最能说明问题的一条：
`amplitude_at_literature_zero`期望值是**0**（物理上首零处振幅恰为零），
容差3e-12的来源是`|dE/dx| = 0.210225`乘以引用值的截断量7.512e-12
= 预测残值1.5793e-12，**实测1.5793e-12吻合到四位**。
即该容差里只有约2e-16是实现的，其余全是那个被截到1e-10的引用常数——
所以案例页明写"**本案例对J1零点精度的判别力止步于1e-10量级**"。

## 五、明确不做的（本裁决的负空间）

- **不做二维场传播**。角谱法、菲涅耳传播、孔径掩模都要数组与FFT，属加速档，下一块。
- **不做带切趾的ILS闭式**。要球贝塞尔`j_i(u)/u^i`与它的小自变量级数
  （直接用sin/cos写会在`u→0`处相消到失去全部有效位）。
- **不搬FTS的成熟实现**。物理正本在fts-digital-twin；搬迁按spec/12第七节的
  切换门走（两实现对拍 + 随迁验证门 + 随迁已知失效 + 随迁适用声明），不在本块预支。
- **不做耦合实现**。`couplings/`只有模块位与进仓条件；今天没有一个消费方要耦合。
- **不重新推导Norton-Beer系数**。`Σ Ci = 1`是必要自洽条件不是正确性证明，
  这条限制写在案例页的已知失效清单里。
- **不裁决基座内部层序**（spec/15第七节待裁决1：spec/01的图与文字对
  "物理域能不能依赖资产圈"给出不同读法，需要一次口径确认）。

## 六、预算与规模申报（spec/13零之二 + 0018的记账义务）

  （`__init__` 4 521、`bessel` 5 133、`diffraction` 7 665、`fts` 8 931、

- **面**：本块**不登记新面**。光学的返回值全在进程内，没有跨边界字节形制；
