## 二、判决：``L_geo``不变，而0066那条欠账的措辞要改

**臂动不改``L_geo``。** 理由不是"取常数更省事"，是场景本身：

> 入带点是世界系里固定的一个点，最后那只导向轮的出带点也是。
> 两个固定点之间的直线段长度**是一个常数**。

轨道C（0067第三节）已经把这一条冻在**类型**上：`laydown.FreeSpanGeometry`的两个端点
是纯常量元组，``length_mm()``**连``t``都收不到**，传参进去抛`TypeError`。
所以"轨道C给出``L_geo(t)``那天"这个触发条件**永远不会到**——
轨道C没有给，而且它是**故意不给**的。

0066那条欠账因此有两处要改，**它们是两种不同的错**：

| 处 | 原文 | 判决 |
|---|---|---|
| 第九节 | "跨段几何长度**随位姿变**……真机上自由跨一端固定在R1、一端随机械臂走" | **事实错**。那是plans/14第3.3节**第一版**的说法，同一页已经订正过（用户2026-08-14口述），而0066抄的是订正前的那一版 |
| 第十节 | "轨道C给出``L_geo(t)``那天，``geometric_length_mm``从字段变成入参" | **触发条件永远不会到**。轨道C给的是所需送带率不是跨长 |

**但"取常数"这个结论本身是对的**——0066做对了一件事却写错了理由，
而写错的理由会把下一个人送上一条不存在的路。这一条与0066第五节第3小节
"实测当场否掉我先写下的结论"是同一族：**先写下的那句话没有被量过**。

`transport.FreeSpan.geometric_length_mm`的docstring本轮照这个判决重写；
`plans/07`第六节**追加**了一行指名订正它——按0069的分槽纪律本轨道**只追加表尾**，
**没有去改0066那一行**，两行并存时**以0071这一行为准**（收口时可以把0066那一行划掉）。
**我也没有去改0066本身**：决策记录是审计痕迹，订正它的正确形式是新开一页指名道姓
（本页第二节），不是回去改历史。

### 2.1 那``L_geo``什么时候会变？**有东西横向顶在跨段上的时候**

两端仍然固定，被顶开的是中间。带材走的不再是直线段而是折线，
**折线比直线长**——这是几何恒等式：

    L_path(δ) = sqrt(a² + δ²) + sqrt(b² + δ²)        a + b = L
    p(δ)      = L_path − L ≈ δ²·L/(2ab)

于是本轮给`FreeSpan`加的那个入口叫``path_excess_mm``而**不叫**``geometric_length_mm(t)``：
名字里就写着它是**增量**、且它只有一个来源。**非负是失败关闭的**——
负增量意味着有人拿它当"跨长可以缩"的旋钮，而那正是被订正掉的那条错误因果。

### 2.2 那臂动到底怎么进张力？**经所需送带率**

落位点必须待在那个固定入带点上，所以"这一瞬要放多少带材"由线圈的运动定。
把它写成落位点在槽上的弧长速率``σ'``，再用Frenet关系换一次：

    Ω_tan = κ(σ)·σ'      ⟹      σ' = Ω_tan / κ(σ)

**这条式子是本轮1.3的全部内容**，而它同时给出了那个必须有的退化档：

* **平面圆**（``κ``恒定）＋臂把切向匀速转 ⟹ ``σ'``**恒定** ⟹ 扰动**恒为零**；
* 槽的曲率沿路径变 ⟹ 同一条匀速转切向的臂运动，``σ'``就在变 ⟹ 张力被扰动。

> **扰动来自"曲率在变"，不是来自"切向在转"。**
> 切向转得再快，只要``κ``是常数，送带率就是常数，张力一动不动。

这一条与直觉相反，值得单独写一行——而它也是"平面圆退化档必须为零"这句话
在本模型里**必然**成立的原因，不是一个碰巧。

## 三、"扰动恒为零"那一档：**我先写下零容差，实测当场否掉**

任务书要求平面圆退化档"扰动恒为零"，我第一版就照着写了**零容差**。
实测：``c = 0``档20000步（``dt = 1e-4``，共2秒）峰谷差**2.2752e-11 N**，
``c = 50``档**1.1376e-11 N**。**两档都不是逐位零。**

病根**不在扰动**：所需送带率确实是常数（`ConstantTakeup`那一侧方差**逐位为零**，
这一条留着判零容差）。病根在**起点**——`at_steady_state`那一趟``T → L_mat → T``
的往返有几个ulp（0066实测四档最坏3.908e-12 N），于是``T·R − M ≠ 0``逐位，
而``c = 0``**没有任何阻尼**把它吃掉，20000步就把它积成了那个数。

有意思的是**有阻尼档比无阻尼档还小一半**——轴承把那几个ulp的激励吃掉了一部分。
两档并排列进清单，是为了让"零容差做不到"这件事有**两个独立的数**支撑。

**这是本页第二条"先写数再去量"的现形**（第一条是0066那次），
而两次都是被自己的门抓住的。

## 四、1.4的形制：`PenaltyAnnulusLimit`那次教训的直接产物

本仓吃过一次亏：`PenaltyAnnulusLimit`把法兰朝向**编码在限位坐标的符号里**，
于是单元门永远抓不到、`winding_line_endtoend`端到端跑一次才炸。
所以`TransverseTouch`的每一条都是**独立字段**，并各配一条必红：

| 字段 | 单独承担什么 | 必红 |
|---|---|---|
| ``push_direction`` | **方向**，显式单位向量，且必须与跨段正交 | 非单位、非正交各一条 |
| ``offset_mm`` | **量值，必须为正**——它不兼职表示方向 | ``≤ 0``一条 |
| ``station_from_guide_mm`` | **作用点**，写明从导轮端量 | 出界一条 |
| ``start_time_s`` / ``end_time_s`` | **起止**，两端都显式，区间左闭右开 | 零长度、负起点、右端取闭各一条 |
| ``profile`` | **时间剖面**，白名单、没有默认值 | 未声明剖面一条 |

**位移控制而不是力控**：真的手指给的是介于两者之间的东西，取位移控制的理由是
**它给出精确几何**（``δ``是输入、``p``是恒等式），而力控要在每一步解一个关于``δ``
的非线性方程（``T``自己也随``δ``变），于是判据里会混进一个求解器容差，
**而那正好盖住这道门本该分辨的东西**。力控档没做，登记在第七节。

### 4.1 一条真的恒等式：横向冲量与材料长度账

"全程有账"不能是"两边都记一下看着差不多"。设触碰窗口内``g``（横向力的几何因子）
恒定、制动力矩恒定，对半隐式Euler的两条更新分别求和再消去``Σω``：

    ∫F dt = (g/R)·[(J/1000 − c·dt)·Δω + M·N·dt + (c/R)·(ΔL_mat + dt·Σv_收线)]

实测残差**8.29e-16 N·s**（冲量本身0.011149 N·s），相对**7.44e-14**，
``dt``四档（4e-6 → 5e-7）全部在同一量级——**恒等式，不是收敛结果**。

**那个``−c·dt``是半隐式的指纹**：长度账用的是**步末**转速而力矩账用的是**步首**，
两者差一个``dt·Δω``。写成``J/1000``（即丢掉它）在``dt → 0``时看不出来，
而注错验证里"丢掉``−c·dt``"这一条**当场红**。

## 七、诚实登记：本轨道**没有**做到的

1. **"触碰→尖峰→回落"只做到前两段。** "有控制器时回落"那一半**一条都没做**——
   1.1控制器可插拔与1.2真闭环归轨道E（0070），`drives.py`是它独占的。
   **没有那一半，本轨道只证明了扰动进得来，没有证明它压得下去。**
2. **力控触碰没做。** 本轮的原语是位移控制，横向力是输出。理由见第四节。
3. **非平面槽没做。** 1.3的解析槽是**平面**的（``surface_normal``恒为``(0,0,1)``），
   而plans/14第2.2节的结论是真实工件"非平面与hard-way是通例"（挠率0.454—6.648 °/mm）。
   挠率进的是**帧**的转动而不是切向的转动，机制式``σ' = Ω_tan/κ``本身不变，
   但入射角的面外分量会动。
4. **扫描档走的是解析速率不是`laydown`速率。** 四档扫描各跑一个整周期（最慢65973步），
   全程走`laydown`要1.3e8次站点访问、本机分钟级。接线那条另有一门判两条路给出
   同一条张力曲线（1500步最大差8.71e-6 N）。**这是一个可以被质疑的取舍。**
5. **`ArmLaydownTakeup`每一步一次最近点全扫**，``O(站点数)``。真实工件607站点、
   时间线数千帧时要回来量——与0067第七节第5条是同一笔账，**空间索引仍然没做**。
6. **闭合残差在本案例里恒为机器零**，因为位姿是"姿态选定、平移反解"构造出来的。
   真实时间线里位姿与送带账来自不同上游，**闭合几乎必然不成立**——
   那时"接的是哪一条"才真正要紧，本轮只在单元门里用一个人造的不自洽夹具判了它。
7. **触碰的时间剖面只有矩形**，没有斜坡也没有半正弦。理由是**本仓没有量过**
   一次真实的人手触碰是什么形状，给一个平滑剖面会让人以为那个形状是有出处的。
8. **触碰点没有接触力学**：没有摩擦、没有接触斑、没有局部弯曲。带材仍是0066那根
   只有``EA``的一维弹簧。真实手指会把带材**局部压弯**，那要过`rod`与`contact`。
9. **能力位一位都没动。** `docs/capability_ledger.json`本轮**一个字没碰**（0069第一节第10行）。
   S6.3与S5.4仍`partial`：扰动通道有了，但闭环与真实工件都还没有。
10. **`benchmarks/engine_budgets.baseline.json`本轮没碰**（0069第一节第4行，轨道禁碰）。
    源码实测从**914802**涨到**957867**字节，**净增43065**，
    仍在0069第三节那条中止线（1000000）之内，**余量42133**。
    **中止线没有被越过，所以本轨道不停下来报告，但这个数要进收口那笔账。**
11. **产物永久`hypothesis_only`。** 一条实测输入都没有；自由跨的两个端点在上游
    一个空着等标定、一个连定义都还没有（plans/15第4.2节2026-08-17订正版）。
