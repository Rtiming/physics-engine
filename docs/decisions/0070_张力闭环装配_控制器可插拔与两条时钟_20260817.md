状态：**已落地**。轨道E（决策[0069](0069_并行波次三的完整冲突面清单与阶段一分工_20260817.md)第二节预分配），

## 零、一句话

**接上了，而接上之后量出来的第一个结论是"这条通道压不住那个扰动"。**

## 一、1.1 控制器可插拔：协议吃两个量，不吃一个误差

### 1.1 问题

`drives.PidController`是具体类，`TensionLoop`吃的是它。plans/09第138行、
plans/14第299行两处都把"控制器不可插拔"记成过欠账，理由是
"要试前馈/增益调度/锥度张力得能换"。

### 1.2 裁决：协议是``step(*, measurement_n, setpoint_n, dt_s) -> (新控制器, 命令)``

原入口是``step(error, dt_s)``。**误差是一个有损接口**——从``e``推不回``(y, r)``，
于是下面这些控制器在只给误差的协议上**写不出来**：

* **设定值加权**（2自由度PID，``u = Kp(b·r − y) + Ki∫e − Kd·dy/dt``）——
  工业张力控制器的标准配置，比例项与微分项各自看的不是``e``；
* **对测量做非线性处理**（死区、限速、卷径/锥度调度）；
* **前馈**（``u = f(r) + 反馈``）——ATC600的锥度张力就是这一类。

**协议的形状必须容得下"一个外部写的、我们不知道内部结构的控制器"**，
而真机口径正是那一个：用户的环跑在Trio上，读`VR451`（张力测量）、
写`VR481`（手动量），ATC600置手动模式后**只当功率级**驱动离合器线圈，
其内部PID完全旁路。给那个环的只能是"测量与设定"，不能是我们替它算好的误差。

### 1.3 ``step``这个名字给了协议，原方法体原文搬到``step_on_error``

`PidController`的数值行为**逐位不变**——0062落地时那个方法体一个字没动，
只是改了名并在外面套了一层"由测量与设定算误差"。有一条门判两条入口
**逐位相同**（不是`approx`）。

代价如实写：``step(error, dt)``这个调用形式**没了**。仓内只有三处调用点
（`TensionLoop`一处、`tests/test_drives.py`两处），改完全绿；
仓外没有消费方（WDS钉`0.6.0`且不调用`drives`）。`drives`是实验档，
按本仓API两档纪律，minor内可破坏而CHANGELOG必写。

### 1.4 ``isinstance``只查方法在不在——**那半条边界也写成了一条门**

`typing.Protocol`的``runtime_checkable``只查属性存在、不查签名（`typing`的既定行为）。
于是`TensionLoop`那条构造期检查挡得住"传了个没有``step``的东西"，
挡不住"参数名写错了"。后者在第一次调用时当场``TypeError``。

**本仓把这条边界写成了一条门**（`test_a_controller_with_the_wrong_signature_passes_construction_and_dies_on_use`），
理由是0049第六节那条教训：**门认得"被提到"、认不得"被登记"**——
一条只写在docstring里的边界，下一个人不会读到。

### 1.5 验收判据挪了位置，而挪的理由要写下来

plans/15的原文是"用一个故意很差的控制器（纯比例、增益极小）跑同一算例，
超调与稳态误差**都必须变坏**"。

**这条判据在`TensionLoop`上不可判**。`TensionLoop`吃的是`SpoolTension`，
而那个模型里**没有扰动**（0066第一节：只要电流不动，张力就不动）。
设定值阶跃下，一个增益极小的纯比例控制器的响应是一条**没有超调的**一阶上升——
"超调变坏"在那条算例上恰好是"超调从0.163变成0"，**方向反了**。

所以验收挪到1.2的闭环扰动算例：**扰动引起的峰值偏移**才是控制器要压的那个"超调"，
而它对好坏控制器都存在。实测见第四节。

## 二、1.2 裁决A：控制器接**制动力矩**，不接收线速度

0066第九节把这一条记成明账，原文"接起来要一层把``brake_torque_nmm``交给
`MagneticParticleClutch`的装配层，且要重裁'控制器接在哪一路'"。

真机是双执行器：`ED3L-08AEA`伺服在CSP位置模式下定收线速度、
POC-050L磁粉离合器定制动力矩。`transport.SpanTransportLoop`恰好也是这两个输入。

### 2.1 稳态权限：一个通道与最不确定的参数无关，另一个正比于它

稳态是``T = M/R + c·v/R²``，于是

    ∂T/∂M = 1/R        ← **与``c``无关**，纯几何
    ∂T/∂v = c/R²       ← **正比于``c``**

``c``是本模型里**唯一的阻尼通道**，而它一条实测都没有（0062第二节裁决2）。
**``c = 0``（理想轴承）时收线速度对张力的稳态权限恰为零**——
把整条回路的权限建在唯一一个没有实测的参数上，等于什么都没建。
案例有一条**零容差**门判这个"恰为零"。

按各自额定量的1%算（``R = 60``、``c = 50``、``M₀ = 1200``、``v₀ = 20``）：

| 通道 | 1%给多少张力 |
|---|---|
| 制动力矩 | **0.2 N** |
| 收线速度 | **0.0027778 N** |

**72倍**，而且恰好是整数72（``M₀·R/(c·v) = 1200·60/(50·20)``）。

### 2.2 收线速度是被绕线程序占用的过程量

伺服在CSP位置模式下跟的是绕线程序给的位置-时间表。拿它去抑制张力扰动，
等于让张力环去改**带材落在哪里**——那是落位的事（`laydown`），不是张力环的事。
0066第5.1节已经写过同一句话的另一半："收线端是伺服给定的，张力改不动它"。

### 2.3 真机就是这么接的

    LTS1-5 → ATC600 →（手动模式，只当功率级）→ TBA420 → POC-050L
    用户自己的环：读`VR451` → 写`VR481`

**读的是张力，写的是离合器。收线端不在这条环里。**

### 2.4 这条裁决的代价，必须同批写

**收线速度通道的动态权限比制动力矩通道大得多**：高频下``T/v_收线 → K/s``
（``K = 200 N/mm``），而制动力矩要经过放线盘的两个积分才到张力。
**两个通道是互补的：制动力矩拿直流，伺服拿交流。** 裁掉伺服那一路，
等于把交流那一半让掉——而扰动恰恰在交流那一头。

后果就是第三节那个否定的结论。

## 三、1.2 裁决B：两条时钟——整数倍抽取＋零阶保持

`transport`是半隐式Euler、步长要能分辨``ω_n = 379.6 rad/s``；
控制器是采样系统、真机上跑在毫秒量级。**两者不是同一个时钟**，
而"让库去猜"正是本仓反复吃亏的那一类。三条裁决，逐条失败关闭：

1. **控制周期 ＝ ``control_decimation × plant_dt_s``**，抽取比是正整数且**没有默认值**。
   非整数比值会让某个控制拍落在推进步中间，**那一步的零阶保持边界无从定义**——
   "前半段用旧命令、后半段用新命令"要么改推进格式，要么就是一次静默的近似；
2. **保持的是电流不是扭矩**。电流是执行器的输入、扭矩是它的状态；
   保持扭矩等于把磁滞旁路掉。有一条门判"非控制拍上电流一个字不变，
   而扭矩每步都在动"；
3. **时延线的``dt_s``必须逐位等于控制周期**。`ActuationDelayLine`按**拍数**记时延
   （0038），拿推进步长去填它**不会报错**，只会让声明的``delay_s``变成另一个时间。
   **这是"两条时钟对不齐"最常见的形态**，所以它是本轮最要紧的一条必红门。

一步里的次序按真机的因果：**先取步首张力测量，再算命令，再推进**。
把测量放到执行之后等于一个物理上不存在的零延迟测量，
而它会让闭环看起来比真机稳得多（与`drives.TensionLoop`那条同源）。

## 四、实测：接上了，而它压不住

全部2026-08-17、本机Mac，``Δv = 2 mm/s``（10%线速度阶跃），
闭式来自案例金标（四阶闭环的精确留数解，根用Durand-Kerner到机器精度）。

### 4.1 三档

| 档 | ``τ`` | 控制器 | 峰值闭式／实测 | ISE(0.2s)闭式／实测 | 稳态偏移 |
|---|---|---|---|---|---|
| 开环 | — | 全零增益 | 1.0604531／1.0604629 | 4.8206e-2／4.8206e-2 | 2.7778e-2 |
| `fast` | 0.5 ms | PID | 0.3374866／0.3376856 | 2.9265e-4／2.9283e-4 | **0**（实测1.6e-10） |
| `nominal` | 50 ms | 纯积分 | 1.1375052／1.1375140 | 6.6918e-2／6.6918e-2 | **0** |

相对偏差：峰值9.26e-6／5.90e-4／7.74e-6，ISE 8.07e-6／6.07e-4／1.37e-5。

### 4.2 压制比——**本轮最要紧的两行**

| 档 | 峰值比 | ISE比 |
|---|---|---|
| `fast` | **0.31825** | **6.0709e-3（165倍）** |
| `nominal` | **1.07266** | **1.38817** |

`fast`档：峰值压到0.318倍而ISE压到六百分之一——**压下去的主要不是峰高，
是它不再一直响**（振荡实部从−5.000到−470.709，衰减时间常数0.2 s → 2.1 ms）。

**`nominal`档两个数都大于1：闭环把扰动响应变坏了。**

### 4.3 为什么变坏——闭式早就说了

闭环特征多项式

    D(s) = τ·s⁴ + (1 + dτ)·s³ + (d + Ka·τ + G·Kd)·s² + (Ka + G·Kp)·s + G·Ki

``Ki``**只出现在常数项上**，它把Routh裕度吃掉；``Kd``出现在``s²``系数上，
而那正是``2ζω``那一项——**能加阻尼的是``Kd``，不是``Ki``**。

而``nominal``档**只能用纯积分**：把`fast`那套设计（含``Kd``）放上去时，
Routh第一列``a₃a₂ − a₄a₁ = −16525.92``，**负的**——任何正的``Ki``都不稳。
实现在这里**失败关闭**而不是返回一个负的界。

于是额定档只剩``Ki``一个旋钮，而它是往反方向拧的：
振荡实部从−5.000退到−4.579。

### 4.4 病根是一个无量纲数

    ω_n·τ = 379.6 × 0.05 = **18.98**

**执行器比对象慢19倍。** 这一个数就是`nominal`档全部结论的来源。

**真机上这条谐振是靠摆杆/储带机构（dancer）压下去的，而本仓没有摆杆模型。**
已登记进`docs/plans/07`第六节。

### 4.5 1.1那条"换得动"的验收（`fast`档，同一算例只换控制器）

| 控制器 | 峰值 | 稳态偏移（``t = 2 s``） |
|---|---|---|
| 好（PID） | **0.3376856** | **+1.60e-10** |
| 坏（纯P，1%增益） | 1.0487479（**×3.11**） | +2.6830e-2（**×1.7e8**） |
| 坏（纯P，0.1%增益） | 1.0592700（**×3.14**） | +2.7693e-2 |
| 完全不控 | 1.0604629 | +2.7734e-2 |

**两条都变坏**：超调×3.11、稳态误差×1.7e8。坏控制器的稳态偏移有闭式
``Δv·K·d/(Ka + G·Kp)``，增益极小时它几乎就是完全不控那个数（``Δv·c/R² = 0.0277778``）
——**这正是"增益极小"的含义**。

顺手量到一条：**纯比例增益也把阻尼吃掉了**（振荡实部−5.000 → −4.895 → −3.954）。
``Kp``抬高``s¹``系数而``s²``系数不动 ⟹ ``ω``升而``2ζω``不变 ⟹ ``ζ``降。

### 4.6 注错验证：**九轮，而第一轮有一条没红**

逐轮清`__pycache__`（同字节数的变异会留下被当成新鲜的旧缓存，0066第6.4节）。

| 注错 | 红了哪些 |
|---|---|
| 零阶保持失效（每步都重算控制器） | ZOH门、多速率门 |
| **时钟对齐检查被摘掉**（裁决B第3条） | 时延线`dt_s`必红门 |
| 绞盘方向取反 | 平方门、闭环稳态绞盘门 |
| 特征多项式掉一个`MM_PER_M` | 多项式手推门、稳定界门 |
| Routh第一列非正时不失败关闭 | 额定档拒收`fast`设计那条必红门 |
| **对象用步末扭矩推进**（因果次序反了） | **第一轮全绿 → 补门之后红** |
| 前馈电流不接进去 | 稳态起点门 |
| 协议入口把误差算反（`drives`） | 两条入口逐位相同门 |
| `TensionLoop`不再检查控制器协议 | 协议失败关闭门 |

复原后90条全绿。

**第六行是本轮最值得写下来的一条。** 把"对象用步首扭矩推进"改成"用步末扭矩"
——那是把测量与执行的因果次序反过来——**九条注错里唯一一条没红的**。

病根是那个差是``O(dt)``的，而``dt = 1e-6``下它落在每一条容差之下。
**一道分辨不出因果次序的门，等于没有判过因果次序**，而模块docstring里
"次序不是随手排的"那句话当时是**没有门守着的**。

补法不是把容差调紧（那会让别的东西开始假红），是换一个**能分辨它的量**：
一步、逐位、粗步长（``dt = 1e-4``、``τ = 5e-4``，一步走完18%的路），
拿步首扭矩独立算一遍角加速度与实现给的新转速对拍。
**同一条门里还判了"步首扭矩与步末扭矩必须真的不同"**——
两者相等时逐位那条断言照样过，而那时它什么也没证明。

这一条与0066第5.2节那句"一条从没被注错验过的门，你不知道它在验什么"同源，
**而这次现形的是我自己写下的那句"次序不是随手排的"**。

## 五、1.5 传感器位置≠被控点

`drives.capstan_transfer_ratio`早就有了，缺的是把它接进闭环。

    T_落位点 = T_传感器 · exp(μθ)

``μ = 0.3``、90°包角给``exp(0.4712) = 1.6019776512823565``。

**实测（`fast`档、跑0.05 s到沉下来）**：

    读数     20.277777778939075   设定 20.27777777777778   误差 **+1.16e-9**
    落位点   32.48454681953038    比设定高 **60.1978%**
    落位/读数 1.6019776512823565  ＝ exp(μθ) **逐位**

**这个误差不是控制器不好，是它看不见。** 判据的分辨力在于：
**必须先证明环真的调准了它测到的量**（误差1e-9），才谈得上"剩下的60%是看不见的"。

### 5.1 方向搞反：误差是**平方**

    对   T_落位/T_读数 = exp(μθ)  = 1.6019777  ⟹ +60.198%
    反   T_落位/估计   = exp(2μθ) = 2.5663324  ⟹ **+156.633%**

实测``真值/反向估计 = 2.5663323952081356``对``exp(2μθ) = 2.566332395208135``——
**差一个ulp**。

金标把``exp(μθ)``与``exp(2μθ)``**分开给值**，于是一个凑出来的2.566
过不了"它必须等于前一条的平方"那道门。`CapstanSpan.sensor_on_tight_side`
**没有默认值**，理由与`TensionLoop.measurement_transfer`同源。

### 5.2 绞盘是一层观测，不是一个动力学环节——而这是物理不是省事

导轮把两侧解耦（**这正是绞盘存在的理由**）：跨段里的张力是``T``，
导轮下游是``T·exp(μθ)``，放线盘看到的是``T``。
代价如实写：本模块因此**算不了**"落位点张力反过来改变跨段张力"，
而真机上导轮的滑移状态一变那件事就会发生。

## 六、模块归属：为什么是新模块

`tension_control`import `drives`与`transport`（都在力学）与标准库，
**没有一条边越到别的域，也没有向上**。判据仍是0035那条：
**import决定环，不是愿望决定环**。

它没有长进`drives`或`transport`里是**所有权问题不是方向问题**：
装配层同时依赖两边，塞进任何一边都会让那一边反向依赖另一边。

## 七、本轮明确没做的

| 没做 | 理由 |
|---|---|
| **摆杆/储带机构** | 真机压住跨段谐振靠的就是它，而本仓没有这个模型。**这是第四节那个否定结论的正解，也是它的登记条目** |
| **第二控制通道（伺服接张力）** | 裁决A裁掉了它，理由在第2.2节。但两通道互补这件事是真的，**mid-ranging双通道控制器是本轮明确留下的口子** |
| **传感器噪声通道** | 有量程截断与ADC量化，**没有**零漂、温漂、非线性、蠕变。后果：额定档"大``Kd``能不能用"这个问题回答不了（扫描实测``Kd``加到设计值100倍能给峰值×0.3449，**但那是在理想传感器、1 MHz控制率下**） |
| **闭环的收敛阶** | 实测比值稳定在2.1—2.3而**不是干净的2**，且不随``Δv``变（0.02/0.2/2三档一致）⟹ **不是线性化floor**。`drives.py`记过同一族现象（精确ZOH的对象＋Euler的控制器给了更高的阶）。本轮没解释清楚，**故不设门**——不设门比设一个自己都不信的门诚实 |
| **设定值阶跃工况** | `at_steady_state`把设定值**由稳态定义**。设定值阶跃要另一个入口 |
| **``ω ≤ 0``的静摩擦保持段** | 沿用0066的失败关闭。本轮它**接住了两次真事故**（1 ms控制周期、1 ms下发时延），见案例页第五节 |
| **`capability_ledger.json`** | 0069第二节明令轨道禁碰。S6.3仍`partial`：执行器物理接上了对象，但落位点几何与噪声通道都没有 |
| **`docs/spec/15`第二节登记表加`tension_control`一行** | 0069第一节第8行明写这是"不会红的面"，**由收口一次补齐**，轨道禁碰 |

## 八、后续触发条件
