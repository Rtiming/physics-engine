# 0035 环序纠正与域归属复核（2026-08-05）

状态：已裁决。域隔离门（决策0031）落地当天就抓到三件事，两件是**图与文本的矛盾**、
一件是**我自己分类错了**。逐条裁。

## 一、spec/01的环图与它自己的文本矛盾——**改图，不改文本**

spec/01第一节的图自上而下是：呈现与交互圈 / 资产圈 / **物理域圈** / 内核圈，
并写着"依赖只许向下"。

而同页第四节第1条写着："资产圈不做物理：modelgen产几何、materials记性质、
appearance记外观——都是**数据与校验**，不含求解器。**物理域从材料记录取参数**。"

**物理域从材料取参数，就是一条向上的边**——与图直接矛盾。代码里同一件事也已发生：
`scene`（内核圈）import `shapes`（资产圈）。

**裁决：图错，文本对。** 资产圈的正确位置在**内核圈与物理域圈之间**：

```text
呈现与交互圈   ← 依赖下面全部
物理域圈       ← 依赖资产圈与内核圈
资产圈         ← 依赖内核圈
内核圈         ← 不依赖任何上层
```

理由：资产圈按第四节第1条的定性是**数据与校验、不含求解器**——
它是物理域的**输入**，不是物理域的**消费者**。一个不含求解器的层不可能在
求解器之上。原图把"资产"排在"物理"上面，大概是按"越抽象越靠上"排的，
但这一页的纵轴定义是**依赖方向**，不是抽象层级。

## 二、`state`要不要升进基座——**否决，但理由不是它不通用**

`state.py`是纯声明容器（字段+布局+向量），看起来完全可以给任何域用。
落地光学时确实动过把它升进基座的念头。**否决。**

理由不是"它不够通用"，是**本仓三前提第二条**：今天没有任何光学代码需要它，
现在升格就是"为想象中的第三个消费方预支通用性"，而那正是AGENTS.md明令禁止的。

而域隔离门有一个好性质值得记：**升格无法悄悄发生**。
某个光学模块一旦import `state`，第①③条门当场红——
所以这件事只能显式走决策，不能由一次顺手的import事实完成。
**宽松方向的改动必须显式**，这是本门比一句规范文字强的地方。

触发条件：某个非力学域真的需要状态容器时重开。

## 三、`sensors`的归属：我分类错了，门抓住了

我最初把`sensors`登记成**基座的内核接口**（spec/10的六接口之一）。
门当场红：`sensors` import `state`，于是"基座依赖物理域"——
spec/01第一节"内核不依赖任何上层"方向反了。

**这不是门过严，是我把愿望当成了事实。** `sensors`要校验"这个观测通道
是不是在读一个自由度"，就必须知道自由度是什么，而今天唯一存在的状态布局是力学的。
**所以今天的`sensors`就是力学传感器**，把它叫域中立的内核接口是aspiration不是fact。

**裁决：`sensors`归力学域。** 触发条件：第二个域长出自己的状态容器时，
`sensors`要么升成域中立（连带`state`升基座，走决策），要么按域分裂。

## 四、这三条合起来说明了什么

域隔离门上线**当天**就抓到一处图文矛盾、一处我的错误分类，
而这两件事在它上线之前都已经存在了很久——**spec/01的两条边界从写下来就只是文字**，
没有任何东西检查它们。

这正是本仓"每个门要红过"那条纪律的推广版：**一条没有执行体的规范条款，
它说的话与它管的事之间会慢慢长出缝，而缝是无声的**。
门的价值不在于它今天绿，在于它上线那天会告诉你之前错在哪。
