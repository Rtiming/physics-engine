## 一、这一轨补的是什么

本页把那一句兑现，落两个新文件：

| 文件 | 内容 |
|---|---|
| `src/physics_engine/optics/field.py` | 二维复数场容器、基2 Cooley-Tukey的一维/二维正逆变换、复数的字节形制 |

## 二、裁决一：非2幂的长度**失败关闭**

`fft`/`ifft`/`fft2`/`ifft2`只吃2的幂，别的长度当场炸并在报错里说清"补零之后会是多长"。

三个候选，逐条给理由：

| 候选 | 裁 | 理由 |
|---|---|---|
| **失败关闭** | **取** | "这个长度我不会算"与"我给你一个别的长度的答案"是两件事 |
| 隐式补零 | 否 | **补零不是同一个问题的另一种算法，是另一个物理问题**：频率栅距从`1/(N dx)`变成`1/(2^m dx)`、窗口的物理宽度变了、周期卷积的折返边界也变了。这些改动全都"看起来更好"（谱更密、图样更光滑）**而且一个字的错误都不报**——正是0024那条1000倍单位bug、0031第3.3节整张表反复吃亏的形态 |
| Bluestein（chirp-z） | 否 | 它能算任意长度，但**精度要另行申报**：把DFT化成长度`≥2N−1`的循环卷积，中间要乘两次chirp`exp(iπn²/N)`，`n²`在大N上先溢出有效位再取模，相位精度是另一套误差模型。本仓对自造轮子的纪律是"精度必须申报而不是假定"（0031第3.2节`J1`那一段）。**今天没有任何消费方要非2幂**，为一个想象中的消费方预支一套没测过的精度正是代码三前提第二条禁的事 |

补零**可以做**，但必须是调用方写下来的一次决定：`zero_pad_to_power_of_two`是个有名字的
动词，`fft`自己不偷偷做。测试里有一条正面断言它**真的改了谱**（长度5的常值场只有DC，
补到8之后bin 1不再是零）——一个"什么也没做的补零"与"没有补零"要能分开。

**GAP与触发条件见第八节。**

## 三、裁决二：一个复数落盘就是一个二元组`[实部, 虚部]`

这是[0052](0052_阶段1至3开工前的七条裁决_20260812.md)第八节明写的未裁项，
原文"阶段5：复数怎么落盘 —— 它定的是全仓**所有**复数量的约定，
而今天只有一个候选消费方"。今天有了：本轨的案例真的要把复振幅冻进`oracle.json`。

### 3.1 约定

* **一个复数** = 长度2的浮点数组，次序固定为`(实部, 虚部)`（`COMPLEX_COMPONENT_ORDER`）；
* **一串复数** = 二元组的序列；
* 要走`oracles`的定长二进制通道时，按**C序展平**成`float64`（于是逐元素交错）——
  因为`oracles.flatten_values`对嵌套列表本来就是C序展平。
  **这两种形态是同一条规则的两次应用，不是两条规则。**

### 3.2 四条理由

1. **它不引入任何新机械**。`oracles._pair_up`对列表逐分量配对，于是实部虚部各自吃
   同一条容差、报错时路径带`[0]`/`[1]`；`canonical`的`allow_nan=False`自动挡住
   `nan`/`inf`；`array_logical_sha256`的`float64`小端流原样可用。
   换成对象`{"real":…,"imag":…}`要在`_pair_up`里加一条Mapping分支，
   换成字符串`"1+2j"`要加一套解析器——**两者都是为了一个复数去改全仓的判据机械**；
2. **它与本仓既有的向量形制同形**。三维向量在本仓就是长度3的浮点数组，
   分量次序靠位置不靠键名。复数是二维实向量，没有理由自成一格；
3. **极坐标（模+相位）被否决，而且是被证伪的不是被议论掉的**。
   `tests/test_optics_field.py::test_the_rejected_polar_wire_form_really_does_lose_bits`
   实测2000个随机复数走`cmath.polar`/`cmath.rect`往返，**逐字节对拍**
   （`float.hex()`）——直角形制2000个全部逐位相同，极坐标形制掉位过半。
   更硬的一条：**零振幅处相位无定义**，而场的零点恰恰是衍射图样里最要紧的地方；
4. **次序写成常量**，因为反了不报错——它与波数那两套差2π的约定同类（0031第3.3节）。

### 3.3 执行体今天放在光学域里，**升基座的触发条件写死**

按域隔离门，`electromagnetics`不许import `optics`——所以第二个域出现复数量时，
**不能靠import本模块来遵守这条约定**。今天不升基座（`canonical.py`），
判据是0035那条：**今天没有任何非光学代码需要它，现在升格就是为想象中的
第三个消费方预支通用性**。

本仓有个好性质保证这件事不会烂掉：真去import它的那一刻域隔离门①当场红，
**升格无法悄悄发生**。触发条件：**第二个域真的要落盘复数量的那一天**
（届时把`complex_to_components`/`complex_from_components`移进`canonical.py`，
光学侧改成re-export）。

约定与仓里既有字节机械的接口有一条门盯着：
`test_the_wire_form_survives_the_repository_canonicaliser`把一个场喂进
`canonical_bytes`再`strict_loads`回来，逐字节对拍，并断言`nan`被挡住。
**不接上就只是一段愿望。**

## 四、三个传播形制与它们**互补的**适用域

| 形制 | 近似 | 输出网格 | 适用域 |
|---|---|---|---|
| `propagate_angular_spectrum` | 无（标量精确） | 与入射面**同间距** | `0 ≤ z ≤ z_c` |
| `propagate_fresnel` | 傍轴 | `λz/(N·dx)`，**随z张开** | `z ≥ z_c` |
| `propagate_fraunhofer` | 傍轴＋丢掉孔径二次相位 | 同上 | `z ≥ z_c` 且边缘相位 ≤ 0.1弧度 |

**两个域的边界是同一个数** `z_c = N·dx²/λ`，两侧各自的推导写在模块docstring里
（传递函数形制的相位局部频率 对 冲激响应形制的啁啾局部频率，整理出来是同一个不等式
的两个方向）。**越界失败关闭**，理由是诚实条款：
**一个在混叠区静默给数的传播器是冒充**——它给出的图样光滑、对称、看起来完全合理，
而且错得没有任何迹象。这与`airy_first_minimum_half_angle_rad`在`λ/D`过大时拒答同源。

**两轴不等长时两个域之间会张开一条缝，本轨不掩盖它**：角谱要两轴都不混叠所以上界取
`min`，菲涅耳同理下界取`max`。方阵上两者相等、无缝交接；`256×8`这种扁网格上
上界是`8·dy²/λ = 1.264e-3`、下界是`256·dx²/λ = 4.046e-2`，**中间32倍宽的一段
两个形制都拒答**。那不是实现的漏，是那个网格在那段距离上没有能力表示结果
（y方向窗口只有8个采样宽，衍射早就跑出窗口了）。有一条门正面断言这条缝存在。

夫琅禾费的门槛`FRAUNHOFER_MAX_EDGE_PHASE_RAD = 0.1`**不是拍出来的**：
同一个圆孔分别用`propagate_fresnel`（保留该相位）与`propagate_fraunhofer`（丢掉它）
算一遍，量归一化强度图样的最大差——实测边缘相位0.02→**4.80e-6**、0.05→**3.00e-5**、
0.10→**1.20e-4**，**随相位平方增长**（5倍相位、实测25.0倍误差）。
取0.1即申报"丢掉这一项带来的强度偏差不超过1.2e-4"。

`aperture_half_width_m`在`propagate_fraunhofer`上是**必填**：场自己不知道孔径有多大，
远场成不成立由孔径尺度决定。要调用方说出来，等于逼他面对"我这个构型真的在远场吗"。

## 五、本轨抓到的三件事（比新功能值钱的那一项）

### 5.1 **真缺陷**：孔径边界落在采样点上，采样缝宽会整差一格

第一版的单缝掩模写`half = (M/2 − 0.5)·dx`，边界恰好落在第`M/2`个采样上，
于是"这个点在孔内还是孔外"由浮点最后一位决定。实测：同一段代码在`dx = 10e-6`时
给出8个采样、在`dx = 2.5e-6`时给出**31个**（期望32）。

后果不是精度差一点：**采样缝宽差一个整格**，夫琅禾费零点因此整体挪位，
而图样看起来仍然是漂亮的sinc平方。它是在"Dirichlet核→连续sinc"的收敛阶研究里露的馅——
四档实测偏差 7.9721e-3 → 1.4349e-3 → **2.6770e-2** → 8.1863e-5，
"阶"是 2.474 → **−4.222** → 8.353。**一个负的收敛阶是唯一的迹象。**

处理：`_reject_edge_on_a_sample`，边界落在采样点上（`1e-9`格以内）即**失败关闭**，
报错里告诉调用方偏开四分之一格。**不给容差偷偷把它算进去**——
"这个采样点在不在孔内"在几何上确实没有答案，替调用方猜一个就是冒充。
修好之后四档是 7.9721e-3 → 1.4349e-3 → 3.3335e-4 → 8.1863e-5，
阶 2.474 → 2.106 → **2.026**，干净的`O(h²)`。

顺带一条要写进案例页的规则：**采样后的缝宽是`M·dx`，不是几何半宽的两倍**，
两者可以差半格以内，闭式对拍要用前者。

### 5.2 判据自己的参照可能比被验对象更差：平移定理的相位约化

平移定理的预测相位若直接写`cmath.exp(-2πi·k·m/N)`，N=1024上残差比值是
**120.6**·eps·Σ|x|；把相位先按**整数**`(k·m) mod N`约化（整数取模精确）再进`exp`，
降到**1.85**——**差65倍**。那120.6里绝大部分是`exp`的大幅角约化误差，
即那条门测的其实是`cmath.exp`不是FFT。

**判据不这么写，就是拿一条更差的参照去验一条更好的实现。**
同一条写法抄进了案例生成器（`direct_transform`）。

### 5.3 圆孔阶梯边的误差是**振荡的不是单调的**，如实记不假装是`O(h²)`

固定物理孔径（半径320微米）加密网格，对`diffraction.py`那条艾里闭式的最大偏差实测
R=16→1.5101e-3、R=32→1.4691e-3、R=64→1.9796e-4，"阶"是**0.040**与**2.892**。
原因是笛卡尔格上圆内格点数的涨落（Gauss圆问题那一类）。

所以那条门只断两件事：每个分辨率都在申报上界`3e-3`内、且加密到R=64时真的更好。
**假装它是`O(h²)`会得到一条随机红的门**——那比没有门更坏。

与之配对的一条把"网格地板"与"菲涅耳项"彻底分开：
`propagate_fraunhofer`丢掉了唯一含`z`的近似项，所以它对艾里的偏差**与z无关**，
实测两个距离上逐位同一个数（1.4696e-3）。而`propagate_fresnel`随菲涅耳数下降
从1.3354e-2掉到那个地板上——**这就是"菲涅耳数极限退化到艾里斑"的实测形态**。

## 六、预算与规模申报（spec/13零之二 + 0018的记账义务）

* **规模与墙钟**（本机三次中位数，**只报这个规模下是多少，不下任何跨机结论**；
  plans/16的M8立的口径是本机墙钟不作数）：

| 网格 | `fft2`一次 | 菲涅耳传播一次 | 秒/(N²·log₂N) |

| 64×64 | 0.0039 s | 0.0045 s | 1.83e-7 |
| 128×128 | 0.0167 s | 0.0187 s | 1.63e-7 |
| 256×256 | 0.0718 s | 0.0783 s | 1.49e-7 |

  那句话说的是**将来可以有**，不是"这一块必须有"。要进来的条件是spec/13第一节的

  今天没有任何消费方在512²以上的规模上等这个。**零依赖的正本先写对。**

  但案例的`oracle.json`里**第一次出现了复数**，它盖的仍是既有的
  `engine_oracle_manifest` 0.1（复数在那个面里就是一串浮点，第三节的约定
  正是让它不需要新面）。见第七节第1条。

## 八、本页登记的GAP

| GAP | 触发条件 |
|---|---|
| **非2幂长度的变换没有实现**（今天失败关闭） | 出现真的要非2幂的消费方时；届时要裁的是"补零还是Bluestein"，**并且必须连同精度申报一起做**，不许只挑算法 |
| **复数字节约定的执行体住在光学域里，别的域够不着** | 第二个域（今天最可能是`electromagnetics`）真的要落盘复数量的那一天；届时把两个转换函数升进`canonical.py`。**它无法悄悄发生**——真去import的那一刻域隔离门①当场红 |
| **角谱那一侧没有任何案例冻结金标** | 平面波本征函数、倏逝波衰减、`z→0`退化、半群四条今天只有`tests/`里的门，没有进`cases/`。触发条件：角谱被第二个消费方用上时，或下一条光学案例开工时 |
| **半群那条判据依赖平台的三角函数幅角约化** | 它在某个平台上红的时候。传递函数相位在那些构型里是`k·z ~ 1e5`弧度；本机libm做精确约化所以残差停在eps量级（实测比值2.14）。**红了先查平台，不要先放宽**——那正是这条门该报的信号 |
| **没有加速档，512²以上纯Python会进本机批级** | 有消费方真的要在512²以上的规模上跑时；届时按spec/13第一节"优化先profile"＋两实现逐字节对拍走，不是"这里有数组所以该上numpy" |

## 九、明确不做的（本裁决的负空间）

* **不做NumPy加速档**（理由见第六节）；
* **不做非2幂**（第二节）；
* **不做反向传播**（`z < 0`）：倏逝分量会按`exp(+k|z|·sqrt(…))`爆炸，
  在浮点上那不是"病态"是"没有意义"；
* **不做透镜、像差、多元件、部分相干、偏振**——一个都没有；
* **不做菲涅耳的传递函数形制**（同网格的那一种）。今天两个形制已经把整条`z`轴盖住，
  再加一个只是在同一个区间上多一条路，而每多一条路就多一处"该用哪个"的歧义。
  触发条件：有构型需要"傍轴 且 输出网格不随z张开"时；
* **不碰`optics/__init__.py`与任何既有`src/`文件**（0084第三节）；
* **不改`cases/README.md`、`capability_ledger.json`、`engine_budgets.baseline.json`、
  `CHANGELOG.md`、`plans/07`、`tests/governance/*`**——全部列在第七节交主代理。
