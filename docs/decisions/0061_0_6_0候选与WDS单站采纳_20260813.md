# 0061 0.6.0候选与WDS单站采纳

- 日期：2026-08-13
- 状态：已裁决并实现；0.6.0正式发布，消费方合入与验收仍独立执行
- 触发：用户授权执行0060登记的第一项后续——WDS实际采纳一个easy-axis站点

## 一、版本事实先于接线

只读核验得到四个不能绕过的事实：

1. `v0.5.0`已经指向提交`315d458`，wheelhouse里的0.5.0 wheel是不可变已发布制品；
2. 该wheel不含0059/0060新增的`sections.py`与`section_beam.py`；
3. 当前源码比`v0.5.0`多37个提交，却仍自报0.5.0；
4. `tools/release.py`发现同版本wheel会硬拒绝，真实发版还会写wheelhouse、打tag并推两个
   远程，不能把本地候选构建偷换成发版授权。

因此本批先把源码版本升为0.6.0并以候选wheel完成WDS独立分支验证；用户随后授权正式
交付，0.6.0按干净main、不可变wheel、`v0.6.0`tag与双远程链路发布。发布、消费方合入、
master环境安装仍是三道独立证据门：第一道完成不自动解除后两道。

## 二、为什么第一片是显式线弹性

WDS现有塑性以`RodReference.natural_kappa1`保存闭式残余自然曲率；physics-engine以每个
纤维点的塑性应变和累积塑性应变保存材料历史。前者在整个feed步接受后更新，后者要求
每个被continuation接受的全局平衡点显式commit。若本批直接接塑性，至少要同时改
continuation结果、上下文历史回传和growth，且两套本构并不语义等价。

本批新增`LinearElastic1D`：

- 只有`young_modulus_n_mm2`，没有未经证据支持的巨大屈服应力哨兵；
- 非零塑性历史输入直接失败关闭；
- 应力、切线与势分别为`E*epsilon`、`E`与`0.5*E*epsilon^2`；
- 与`ElasticPerfectlyPlastic1D`共用截面求积与站点装配；通用状态布局仍携带每点两个
  恒零历史槽，但线弹性分支不演化、不提交非零材料历史。

这允许先验清一条真实消费接缝，同时把塑性trial/commit的扩大改造留在后续独立决策。

## 三、WDS接缝与默认兼容

消费方接缝位于`BendingEnergy`，不是替换`solve_equilibrium`：

```text
WDS全杆Newton
  -> total_quantities
  -> BendingEnergy
       默认None：原batched easy+hard逐句原路
       opt-in：目标站点原easy减项+physics-engine easy加项
               其余站点与全部hard仍走WDS
```

单站局部次序固定为9个位置坐标加2个边扭角；适配器把引擎11维梯度/Hessian散射回
WDS全局索引。站点身份绑定目标顶点、两边静止长度、自然曲率与`EI_easy`；`d1/d2`
是当前运输gauge，必须与`gamma`成对在每次求值时重建局部layout。continuation只改变
这一对gauge可以继续；静止长度、自然曲率或刚度漂移则失败关闭并要求重建站点。

矩形中点纤维的离散二次矩不精确等于解析`w*t^3/12`。适配器使用
`E_algorithm=EI_easy/sum(A_i*y_i^2)`，使被替换站点的离散线弹性刚度与WDS已声明
`EI_easy`一致；该E是算法校准量，不冒充材料试验值。

当前开关默认关闭；WDS另增一个1.1命名案例，以独立scenario kind/plugin身份显式开启，
不原地改变既有1.0插件身份。动态的三个公开入口在检测到该配置时抛
`NotImplementedError`：线弹性本身是可恢复势，但共享term仍保守声明不支持动态，且
质量、积分与动态回归尚未验证；塑性分支还另含增量耗散，不能静默进入守恒能量账。

## 四、交付链漏洞一并关闭

WDS的master清单此前写精确版本，但`check`只做模块import，0.4.0与0.6.0都会显示“ok”；
`env`又只从默认pip索引安装，不会消费仓内相对wheel。这个组合会让本机锁到0.6.0、
master却继续跑旧版本。

消费方候选因此新增`vendor_pydep`：清单绑定wheel的SHA-256；`check`先失败关闭conda
激活，再核远端wheel哈希、安装版本和wheel RECORD所列模块字节；`env`用
`--force-reinstall --no-deps`安装相对vendor wheel后重验。这样同版本不同字节也必须红。
候选阶段没有写master共享环境；正式wheel发布后，由WDS自己的交付批重新安装、对拍和验收。

## 五、证据与不能声称的事

进仓门：

- 规范：spec/12的能量项协议、0060的准静态站点与历史边界已覆盖；
- 真实消费方：WDS自己的生产`BendingEnergy`通过显式opt-in调用本仓，不是复制公式；
- 默认兼容：开关为`None`时原实现逐句原路；既有1.0插件/案例身份不变；候选另做代表性
  case前后物理指纹对拍；
- 性能与依赖：仍为纯Python、零新增运行时依赖；只替换一个站点，未预支通用多站框架。

本地定向门覆盖：真实引擎调用探针、energy/gradient/Hessian对原站点、独立梯度差分
Hessian、八段continuation的运输gauge重建、三步真实growth调用、默认路径状态字节不变、
静态绑定漂移与越界站点必红、三个动态入口必红、线弹性污染历史必红、master同版本异
字节/错误hash/环境激活失败门。候选wheel的SHA只服务候选验证；解除候选状态与安装说明
后，正式发布树连续构建两次，均为248306字节，SHA-256均为
`53114e430a62c2023fb02c512b40f3cfbb558b4d0ac32819ec81a17922ea71be`。WDS必须
以这份正式字节替换vendor并重签自己的证据。完整门禁数字以两仓各自验收输出为准。

本批**不声称**：

- WDS main已经采纳、master V2已经通过；
- 既有全部14个默认案例已逐案做改造前后双版本对拍；新增1.1命名案例不替代这道门；
- 塑性、动态、整杆多站、轴向N、hard-axis、扭转或独立截面场已接入；
- 机械纤维积分点关闭了S1.2电磁截面场自由度缺口。
