## 二、姿态表示：为什么是单位四元数

三条，前两条是硬的：

1. **万向锁是定义上的洞，不是数值上的难。** 任何三参数姿态表示都在SO(3)上有
   坐标奇点（拓扑事实：SO(3)盖不住一张三维图卡）。取ZYX欧拉角时运动学映射
   `ω → (φ̇, θ̇, ψ̇)`带`1/cos θ`，`θ = ±90°`处右端项**根本不存在**——
   积分器在那里不是"精度掉了"，是被喂了一个没有定义的导数。
   而自由飞行的姿态全程乱转，它**必然**穿过那个角（本片的Dzhanibekov案例
   12秒内翻两次身，欧拉角实现会在翻身途中炸掉）。
2. **欧拉角有24种约定**（12种轴序 × 内旋/外旋），换一种就是换一个物理。
   而本仓**已经有一套四元数约定在用**：`shapes.PosedBody.rotation_xyzw`与
   `motion.Pose.rotation_xyzw`，都是**xyzw**次序、都表示**体→世界**。
   再引入第二套姿态词汇是自找的——`peer_fcl_distance`已经把"四元数次序错"
   实测成一条必红（1.508e+2 mm偏差、360/540样本越界）。
   本片因此复用同一套，并有一条门逐位对拍`rigidbody.attitude_matrix`与
   `PosedBody.rotate_local_mm`。
3. **不选旋转矩阵**的理由同样具体：9个数带6个约束，正交性漂移要Gram-Schmidt
   拉回（一次六维投影）；四元数4个数带1个约束，拉回就是一次除法。

四元数唯一的缺陷是**双重覆盖**（`q`与`−q`是同一个旋转）。这条本仓已经登记过——
`motion`的`rotation_arc`语义就是为它立的。它影响的是**插值走哪条弧**，
不影响运动学方程：`q̇ = ½·q ⊗ (ω, 0)`对`q`与`−q`给出同一条轨迹。
所以本片不为它做任何事，只是不假装它不存在。

### 2.1 归一化漂移：门守在归一化**之前**那一侧

`|q| = 1`不是任何显式积分器的不变量。处置是每步归一化一次
（与`motion._normalise_quaternion`同一句话："不是语义变换，是把一次浮点舍入的
偏离收回来"）。**要紧的是门守在哪一侧**：

归一化之后`|q|`恒等于1，所以"断言`||q| − 1| < ε`"是一条**永远通过**的断言——
spec/12第6.2节点名的那类假通过，只是换了个物理外衣。因此：

- 诊断报出的是**归一化前**的单步最大偏离，判据也比这个；
- 超过`QUATERNION_NORM_STEP_ABS_TOL = 1e-6`即**失败关闭**，不二分不静默拉回；
- 归一化次数是确定性整数，一并进判据（少一次=某条路径跳过了投回单位球）。

实测（无力矩非对称刚体、2秒）：RK4在dt=8e-3/4e-3/2e-3上归一化前偏离
2.288281e-12 / 7.005507e-14 / 2.220446e-15，判据上限取1e-11
（约4倍余量，比失败关闭阈值低五个数量级）。

**这条护栏真的红过**：显式Euler在dt=2e-3上**第一步**就被挡下
（偏离6.999976e-06 > 1e-06），所以漂移排序判据改在dt=5e-4上跑。
一条从没红过的护栏与没有护栏是一回事。

## 三、`StateLayout`的边界：我撑开了什么，没撑开什么

（总指挥点名要的一节。0033处理接触锚点时撞到过同一块地基，当时明写
"**状态布局是固定的，而接触点数随构型变**"，并裁"不裁，等第一块真接触内核"。）

### 3.1 我实际撞到的边界**不是**那一条

姿态是**定长**的：四个标量、宽度固定、次序固定。`StateLayout`本来就是
"若干个定宽`StateField`按声明次序拼成一维向量"，姿态**原样落在它的设计域内**——
我没有引入可变长度段、没有按体类型分块、没有任何新机制。
`RIGID_BODY_LAYOUT`就是四个普通`StateField`（位置3 + 速度3 + 角速度3 + 姿态4 = 13）。

我撞到的是**另一条**边界，属轴2不属布局形状：**`StateField`要求名字带单位后缀，
而四元数分量是真无量纲**。`identity.assert_quantity_fields_have_units`早就把
"无量纲"当成一个需要**显式列出来**的类别（轴2规则5："留空装有是禁止的形状"），
但`StateField`没有这个口子。于是唯一的出路本来是**在名字上挂一个假单位**——
那正是spec/14第五节盯着的"静默1000倍"那一族病的入口。

**处置**：给`StateField`加`is_dimensionless: bool = False`，两个方向都堵
（没单位又没声明→拒；声明无量纲却带单位后缀→也拒）。

**这个标志不进`StateLayout.to_document()`**，理由是打包契约的内容地址描述的是
"次序与宽度"，量纲不改变哪个数落在哪一格；算进去会让**既有布局的指纹全部变一遍**，
破0001三前提第三条。有一条门证明这件事：手写一份旧口径的文档，
断言`to_document()`与它相等、`fingerprint()`等于它的规范哈希——
不是抄一个魔法哈希串（魔法串只能说明"和上次一样"，说明不了"和旧口径一样"）。

### 3.2 打包次序仍然是内容地址，而且**这次它是承重的**

0019把`fingerprint()`立成"次序的内容地址"，但那时没有任何代码消费它。
本片让它承重：`integrate_free_flight`**拿指纹当进函数的门**——
布局指纹与`RIGID_BODY_LAYOUT`不同即拒。次序换一下`dof_count`一样、
向量长度一样（spec/12第2.2节说的"多数测试不会发现"），指纹发现得了，
门当场红。有一条必红用例守着。

**一处自我推翻**：第一版的积分器内部写了`y[9:13]`这种字面量切片。
那是本页最容易犯的错——布局改了它不跟着改，而`fingerprint()`会照常变、
门会照常绿（因为门比的是布局，不是积分器里那个数）。
已改成从布局导出（`_slice_of` + `_ASSEMBLY`置换），并加一条**AST门**
禁止模块里出现任何带整数字面量的切片。
那条门的第一版写成正则，被自己文档字符串里"曾经写过`y[9:13]`"那句打红了——
判据本身也要被验，这就是它被验的方式。

### 3.3 能不能容纳"数量随构型变"的量（接触锚点）？**不能。**

明确回答，不含糊：

**本片对0033那条问题没有提供任何进展，一点也没有。** 理由是结构性的：

- `StateLayout.fields`是一个**冻结的元组**，`dof_count`是它的编译期常量，
  `fingerprint()`是这个定长形状的内容地址。姿态是定长的，所以它进得来；
  **接触锚点不是定长的**，构型一变活动接触对就变，它进不来。
- 更要命的是**语义**那一层：spec/12第2.1节写着"参考一变，能量的定义就变了，
  此时任何跨步的守恒量断言都不再成立"。如果按"每种构型一份布局"来做，
  活动集一变指纹就变——**本片这四层判据（全部是跨步守恒量与跨步相位积分）
  会在活动集变化的那一步全部失去意义**。这不是实现难度，是判据的定义域问题。

所以三条路今天都还开着，本片一条都没有关掉、也一条都没有选：

| 选法 | 代价 | 本片提供的证据 |
|---|---|---|
| 每种活动集一份布局（指纹随构型变） | 跨步守恒量断言在活动集变化时失效（spec/12第2.1节） | **无** |
| 引入可变长段（指纹寻址schema而非实例） | `fingerprint()`的语义要重定义：它今天寻址"这个具体形状"，那时要寻址"这类形状" | **无** |
| 锚点留在状态之外 | 0033已裁它是真历史、必须进状态并随状态被复现 | **无** |

**结论：本片的扩展只服务定长块。** 它的好处是没有制造新机制、没有预支通用性
（三前提第二条），也因此**没有替接触那一轮省下任何事**。
把这句写在这里，是为了接触内核落地时不会有人误以为"姿态已经把布局撑开了"。

**需要总指挥裁的**：0033那条要不要在接触内核之前先裁。我的判断是**不必**——
本片没有把它推进也没有把它变坏，而按本仓"不为想象中的消费方预支通用性"的纪律，
在真接触内核的形状清楚之前裁它仍然是预支。但**如果**接触轨道已经排上日程，
那三条路的取舍最好在写第一行接触代码之前定，因为第二条路要改
`fingerprint()`的语义，而那是0019的承重条款。

## 四、转动积分器：两个，各带五项出生声明

声明复用`integrate.IntegratorDeclaration`——**同一份五项契约**，
不给转动另开一套（另开一套就意味着有一天两套会长得不一样）。

| | `rk4_rigid_body` | `explicit_euler_rigid_body` |
|---|---|---|
| 适用域（不管什么） | 无接触/约束/关节/刚性；**不是辛的**，长时间守恒量单调漂移；姿态靠每步归一化不走李群指数映射 | 不管任何生产用途，只是漂移排序的对照组 |
| 形式阶 / 实测阶 | 4 / **4**（角动量漂移比16.1183与16.0617、动能15.6772与15.8690，隐含阶4.0106/4.0056与3.9706/3.9881） | 1 / **1**（漂移随步长减半降2.0016与2.0008倍） |
| 稳定性 | 显式条件稳定，`h < 2.785/|ω|_max` | 显式条件稳定，`h < 2/|ω|_max` |
| 耗散记账 | 无算法耗散，**也不宣称守恒**：漂移是O(h⁴)截断不是被建模的耗散，案例当收敛量测阶 | 无算法耗散；能量单调增长（反耗散） |
| 失败阶梯 | 无步长拒绝/二分；只有四元数范数那条单向护栏（第2.1节） | 同上，共用同一条护栏 |
| `production_ready` | **False** | **False** |

`production_ready`全False并有门守着（形制照0019第五节）。理由不是谦虚：
RK4非辛，接触/刚性问题上它和显式Euler都不该用——而接触正是场景③的另一半。

**数值形态**：一份公式源、两个求值后端（0016甲案）。导数是"调用方的代码"、
两个后端都用元组调它，`VectorOps`只承担RK4的线性组合——加速档边界与
`integrate.py`画在同一处（0019第2.2节的诚实边界）。逐字节对拍是构造保证的，
有门守着。

## 五、四层判据与实测

案例页`cases/rigid_body_free_flight/case.md`是正本，这里只记结论。

| 层 | 判据 | 闭式出处 | 实测 |
|---|---|---|---|
| 守恒量 | 惯性系角动量矢量 + 转动动能的**全程最大**相对漂移，及其随步长的阶 | 无参考自洽（spec/12第6.2节写法1） | 1.862e-09→1.155e-10→7.193e-12（阶4.01/4.01）；动能2.893e-10→1.846e-11→1.163e-12（阶3.97/3.99） |
| 轴对称闭式 | 体系`λ = ω3(Ia−It)/It`、惯性系`ψ̇ = |L|/It`，**都带符号** | Drake `free_body`（Kane 1983 §1.13/§3.1），经research/05第2.2节 | 扁体rel 2.886e-11/1.537e-11；长体rel 3.104e-11/4.843e-11（λ为**负**） |
| 中间轴定理 | 增长率`σ = Ω√((I3−I2)(I2−I1)/(I1I3))`；稳定轴振幅上界闭式；翻转次数整数 | 中间轴定理线性化（research/05第2.2节的定性判据被本片定量化） | σ rel 4.511e-05；上界rel 1.596e-07与9.315e-08；翻转2/0/0 |
| 四元数范数 | 归一化**前**的最大偏离 ≤ 1e-11 | 有界性声明 | 2.288e-12 / 7.006e-14 / 2.220e-15 |
| （补盲）常力矩 | `ω = τ·1000·t/I`，沿主轴精确 | Euler方程退化 | rel 2.043e-14 |

**核对过轨道简报给的进动率形式**：简报写`(I3−I1)/I1·ω3`，其中`I3 = Ia`（轴向）、
`I1 = It`（横向），即`ω3(Ia−It)/It`——与research/05抄自Drake的那一行逐字一致。
我另外从Euler方程独立推了一遍（`I1 = I2 = It`下`ω̇1 = −λω2`、`ω̇2 = +λω1`）确认形式，
没有自己发明判据。

**两条判据形制上的自我加码**（相对同行）：

1. 中间轴定理在MuJoCo/Bullet/PhysX/Newton四家都是**定性**的
   （`dzhanibekov.xml`看现象）。本片把它钉成三个可比的量：闭式增长率、
   闭式振幅上界、确定性整数翻转次数。
2. **稳定轴的振幅上界是一个数，不是"有界就行"**——
   绕最大轴时是`sqrt(I1(I3−I1)/(I2(I3−I2)))`，本例恰为`2/√3 = 1.1547005383792515`。

## 六、必红矩阵，以及**主动找出来的盲区**

七道门 × 五条注错，逐格实测，登记在测试里的`FAULT_MATRIX`，
测试断言**红门集合与登记完全相等**——多红一个也是失败，
因为瞎的地方必须诚实地记成瞎的。

| 门 ＼ 注错 | 陀螺项漏掉 | 叉乘次序反 | 四元数次序反 | 体系/惯性系搞反 | 惯量整体×1e6 |
|---|---|---|---|---|---|
| 惯性系角动量 | 红 | 红 | 红 | 红 | 绿 |
| 转动动能 | 绿 | 绿 | 绿 | 绿 | 绿 |
| 体系进动率 | 红 | 红 | 绿 | 绿 | 绿 |
| 惯性系进动率 | 红 | 红 | 红 | 红 | 绿 |
| 中间轴增长率 | 红 | 绿 | 绿 | 绿 | 绿 |
| 四元数范数 | 绿 | 绿 | 绿 | 绿 | 绿 |
| 常力矩斜坡 | 绿 | 绿 | 绿 | 绿 | 红 |

**四条典型错法没有一条能全身而过。** 但这张表要读的是绿的那些格：

- **转动动能整行全绿。** `½ωᵀIω`是无力矩Euler方程的严格不变量，
  对转动的**任何**写错都可能照样守恒。把它当主判据是危险的。
- **叉乘次序反时中间轴增长率`|σ|`不变**：整项变号等价于时间反演，
  线性化系数是两个变号因子之积。只有**带符号**的进动率抓得住它——
  这与`ballistic_free_flight`那条"同幅反号，判据必须带符号"是同一个教训的第二次出现。
- **四元数次序反与体系/惯性系搞反只被惯性系那两道门抓住。**
  这就是守恒量必须写在**惯性系**里的原因：体系里的`I·ω`本来就不守恒，
  而"体系里的量"这一整类判据看不见姿态错——姿态根本没进它们的表达式。

### 6.1 盲区（主动找的那条，按0029的教训找）

0029登记了"有限差分门验不了物理"，并留下两个活标本（一次1000倍、一次被抵消）。
轨道简报点名要我找守恒量门的同类盲区。找到的是这一条，**而且它比预想的更宽**：

> **无力矩的四层判据对惯量张量的整体缩放`I → c·I`全盲，而且是按定义全盲。**

`τ = 0`时`ω̇ = −I⁻¹(ω × I·ω)`对`I`是**零次齐次**的：`I⁻¹`降一次、`I`升一次，
`c`整体约掉。实测把`I`乘1e6，末态13个分量逐个只差舍入（≤1e-12相对）。
于是守恒量、两个进动率、增长率、振幅上界、翻转数、四元数范数——**一条都不红**。
而mm²↔m²恰好就是一个1e6的整体缩放，正是spec/14第五节盯着的那一族。

**这条盲区不是本仓独有的**：同行的Drake `free_body`与MuJoCo `dzhanibekov.xml`
都只跑无力矩，因此都有它。本片的处置是加两道**不在原简报要求里**的判据：

1. 判据表第一行——`geometry`算的惯量对教科书闭式（rel 1e-15）；
2. **常力矩斜坡**——`ω = τ·1000·t/I`，`I`一变它立刻红。它是本案例唯一带力矩的
   动力学判据，也是唯一钉住惯量绝对量级的动力学判据。

盲区本身写成了一条**正面断言**（`test_the_conservation_gates_are_blind_to_a_uniform_scaling_of_the_inertia_tensor`）：

### 7.1 顺手发现的一处口径不一致（登记，不自己改）

基线里记的`source_bytes.measured = 328273`（0041第二节），

## 八、本片明确不做的

- **不做接触、约束、多体、恢复系数。** 场景③的另一半（网格窄相+摩擦）是零，
  0040第二节C档第7—9条一条也没动。
- **不做辛/李群积分器。** RK4非辛，长时间守恒不保证；要长时间守恒得换积分器，
  那要先有消费方需求。
- **不做自适应步长。** 步长二分是抢救不是收敛证据（spec/12第4.3节）。
- **不做非对角惯量张量的动力学判据。** `_symmetric_eigenvalues`与`solve`在一般
  对称阵上有单元门，但**没有一条动力学判据跑在非对角张量上**（案例页第四节第8条）。
- **不动0033。** 见第3.3节：本片对它零进展，且没把它变坏。

## 九、案例阶梯的账（0040）

`rigid_body_free_flight`**不计入0040的分母**。分母是research/05第2.3节的
**C档13条**（杆梁族6、接触族3、光学族4），而本案例的判据来自第2.2节的**B档**。
按0040第四节的口径它属"引擎自己的门"那一类。**今天仍是13条过6条，没有变。**

**但有一件事值得总指挥裁**：本案例的判据源（Drake `free_body`的闭式、
四家独立实现的Dzhanibekov）**是同行公认的标准案例**，判据强度是research/05
第一节表里的第1档（解析闭式解）——它落在B档只是因为0040的分母是照
research/05第2.3节那一节划的。要不要把分母扩到"第1档判据强度的同行标准案例"
而不是"第2.3节那一节"，是一次口径决定，我不自己改分母。
