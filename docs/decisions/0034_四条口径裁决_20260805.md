# 0034 四条口径裁决（2026-08-05，用户授权按建议办）

状态：已裁决。用户口径："**其他的那些引擎该有的你都可以搬过来……
你第二大点问我的那些问题……你也可以搞一下。**"
plans/02第六节的第4—6项与spec/11第二之二节的法兰缺口，按下述办，逐条给理由。

## 一、Episode摘出spec/10的冻结前提

**问题**：spec/10的冻结条件是"六接口集齐 + 一个消费方实现过其全部门禁"，
而`Episode`已被明确裁决**不排期**（数据集先行，WDS design/24七之四）。
两条口径互相咬死——**按现口径spec/10永远冻不了**，而一份永远冻不了的规范面，
它的"草案"状态就不再有信息量。

**裁决：摘出。** spec/10的冻结前提改为**五接口**（Scene / MotionSource / Actuator /
Sensor / CollisionQuery）；`Episode`降为**登记在册的未排期接口**，
它自己何时实现、何时进冻结前提，由交互式环境需求真到来时另立决策。

理由：冻结的意义是"这一面稳定了、可以被依赖"。把一个明确不做的接口挂在前提里，
是拿一个永不满足的条件换一个永不到来的稳定——**那不是严谨，是自我瘫痪**。

## 二、`check_state`签名：改规范，认可位姿构造期冻结

**问题**：spec/10第五节写`check_state(state)`，而`collision.py`是`check_state(self)`——
位姿在`BroadPhaseCollisionQuery`构造时冻结。**规范与代码互相打架**，冻结前必须解。

**裁决：改规范，认可现状。**

理由不是"代码已经这么写了"，而是**构造期冻结对内容寻址更友好**：
查询对象一旦构造，它所依据的位姿集合就固定了，
这个集合可以被内容寻址（轴3）、可以进run package、可以声称指纹。
若签名收`state`参数，同一个查询对象在不同state上给出不同结果，
"这次查询依据的是哪一份位姿"就成了调用方的记账义务——而记账义务下放给调用方，
正是本仓一贯要避免的事。

**代价如实说**：随时间推进反复查询要每帧重建查询对象。
这在几十个体的规模上可接受；体数上百且每帧重建成为热点时，
按spec/13义务1（profile先行）另行评估增量更新，**那时才动签名**。

## 三、orchestration正本归属：认WDS为正本，引擎不造第二套

**问题**：WDS已有成熟的案例引擎（注册表→resolved_case→runner→原子发布→严格复读），
而引擎侧`orchestration`整格空白。引擎再造一套是重复劳动。

**裁决：WDS的runner是正本，引擎不造实现，只定接口与形制。**

理由：本仓的"代码三前提"第二条是"有真实消费方在用"。
orchestration的真实消费方只有WDS，而它已经有了一套跑通的。
引擎再写一套的唯一后果是**两套编排语义要长期对拍**，而对拍的收益是零——
它们服务的是同一个消费方。

引擎在这一格承接的是**形制**：案例页模板、oracle清单面、run package——
这三样已经落地（决策0020、0024），WDS采纳它们即可，不需要引擎再给一个runner。

**这一条改了plans/02第一节内核圈那一行的口径**：orchestration从"空白待补"
改为"**正本在消费方，引擎只定形制**"，与`motion`（WII边界）同型。

## 四、`FiniteCylinder`法兰缺轴向尺寸：本轮不改词汇，维持失败关闭

**问题**（spec/11第二之二节已登记）：声明了`flange_outer_radius_mm`却没有法兰轴向尺寸，
带法兰圆柱的质量分布**不由声明决定**——同一份声明对应无穷多个真实分布。

**裁决：本轮不动形状词汇，维持`geometry.mass_properties`的失败关闭。**

理由：两条候选修法（加轴向尺寸字段 / 把法兰声明成独立的第二个形）**都会改spec/11规则2的词汇**，
而那一页的冻结条件是"一个消费方实现过其全部门禁 + 另一个消费方评审"。
今天没有任何消费方在用带法兰的导轮——WDS碰撞预演批次未开工。
**在没有真实牵引时改词汇，正是本仓明令禁止的"为想象中的需求预支通用性"。**

失败关闭 + 错误消息点名缺什么，是这种情况下的正确行为：它不猜，
而且当真有人需要时，那条错误消息就是需求的入口。
`modelgen`的带盘生成器按同一纪律处理（决策0032）。

**触发条件写明**：WDS碰撞预演批次或case2给出带法兰导轮的书面需求时，
本条重开并另立决策记录。
