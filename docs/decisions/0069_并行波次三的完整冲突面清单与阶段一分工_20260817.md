## 五、收口（2026-08-17当日，E/F/G三条全部合入）

### 5.1 第三节那条中止线**写法有毛病**，虽然三条轨道都没触发

我写的是"**任一轨道**使实测越过1000000时停下来报告"。实跑：

| | 各自树内实测 | 净增 |
|---|---:|---:|
| 轨道E | 951899 | ＋37097 |
| 轨道F | 958355 | ＋43553 |
| 轨道G | 941667 | ＋26865 |
| **三条合并后** | **1022317** | **＋107515** |

**三条各自都在中止线之下，合并后越过22317。**

**这条与0064第7.2节那个"四十倍"是同一类错的第二次**：
把一个**共享**的预算按**单条**去判。三条各自离线还有4万多字节，
于是三条都不会停下来报告，而它们花的是同一份余量。

**订正**：下一次的中止线要写成"**合并后**的预估"，即
`当前实测 + Σ(各轨道申报的预估增量)`，且**各轨道开工时就要申报一个预估**。
今天没有这个申报字段——登记在此。

### 5.2 上限：**不抬**，而且这次它就该快响了

现状：实测**1022317**、上限1048576、**用量0.975**、余量**26259**、
`ceiling/measured = 1.0257`（0053那条调回线是1.6，远不到）。

**裁决不抬**，三条理由：

1. **门没破。** 1022317 < 1048576，`measured <= ceiling`成立。本仓的纪律是
   "**真撞破后抬**"，唯一的例外是0041那次为并行波预支——而0064第7.2节已经记下
   **我那次预支的分母算错了23倍**。今天没有下一个具体批次，预抬就是重犯那件事。
2. **26259字节的余量意味着下一件事就会撞它**——**那正是它的设计意图**
   （"增长必须是一次被记录的决定"）。0039那句话有两个方向：
   绊线长期不响等于被拆了；**而绊线快响了，不是要去把它挪开。**
3. 真要抬，该由**那个撞破它的批次**带着自己的理由去抬，而不是由收口方替它预支。
