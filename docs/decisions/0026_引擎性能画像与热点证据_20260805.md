# 0026 引擎性能画像与热点证据（2026-08-05）

状态：已落地。解决的是spec/13第一节义务1的一个空档——那条义务写着
"**没有火焰图/热点数据的优化提案不受理**"，而在本页之前，**本仓自己一条
热点数据都没有**。于是这条义务只能用来拒绝别人，不能用来指导自己：
下一步该把加速档做在哪一层，除了印象没有别的依据。

本页只做一件事：**产出证据**。它**不批准任何优化**。

## 一、决定：物理路径的测量进`tools/bench.py`，仍然不进门

决策0018第一节的裁决（墙钟不进门、确定性量进门）**未被本页改动一个字**。
本页新增的三组测量——能量装配、标度指数、积分推进——全部是墙钟量，
因此全部落在`tools/bench.py`产的`work/bench/latest.json`里，**不进
`tests/perf/test_budgets.py`**。

理由与0018同源，并且被本轮实测再次证实：同一台机器上负载从4.2涨到5.9的
过程里，**同一个测量的绝对秒数摆动约2倍**，而同一份profile的**占比只动了
不到1.5个百分点**。这正好说明两件事：

1. 墙钟绝对值做门是没救的（0018已裁，本轮复证）；
2. **profile占比才是那个可以据以决策的量**——它对负载不敏感，
   因为分子分母同时被拉长。spec/13义务1要"热点数据"而不要"更快的墙钟"，
   这是它对的地方。

## 二、新增的测量组（形制照0018）

`tools/bench.py`加三组进程内测量与三块cProfile热点：

| 组 | 测什么 | 规模 |
|---|---|---|
| `energy_assembly` | `EnergyRegistry.total`三档（能量／＋梯度／＋Hessian） | 2/8/32/128/512节点的链 |
| `scaling` | 对上面的中位数拟合`t ∝ N^p`，三个窗口 | 全域／≤321节点（对齐WDS口径）／32—512 |
| `integration` | `integrate`在两个后端下的耗时比，**分物理回调与常回调两种** | 8/128/512节点 |
| `hotspots` | cProfile前15：梯度装配、Hessian装配、积分路径 | 512节点 |

三条形制条款：

1. **每组记当时的1分钟负载**，不是只记开头一次。一次跑十几秒，中途负载会变；
   只记开头等于把"这组数是在什么环境下测的"记错。
2. **中位数与最小值都报**。最小值最接近无干扰时的真实成本，中位数是用户
   实际会遇到的；哪个都不能单独代表全部。
3. **不关GC**。`timeit`默认关GC，关掉测出来的是实验室数；用户拿到的是带GC的数，
   本脚本报后者。

`tools/bench.py`顶部"本报告不是回退测试"那句原样保留——本页扩的是它测什么，
不是它的地位。

## 三、拟合窗口为什么是三个，不是一个

标度指数`p`是本轮最重要的一个数（spec/12第8.1节记着WDS的0.59），
但**它只在给定窗口内有意义**。所以报三个：

* `all`（2—512）：全景；
* `le_321_wds_comparable`（≤321节点）：**对齐WDS的口径**——那条0.59测在
  ≤321节点上，不在同一个窗口里比是没有意义的；
* `upper_32_to_512`：固定开销不再主导之后的渐近值。

同时报`R²`。**这不是装饰**：`p`只有在数据真服从幂律时才有意义，
小规模上固定开销主导会把点压平，看的人必须能看见这件事。

## 四、结论落在research/06，不落在本页

三问的答数、前15个热点、两个后端的实测比值、按profile排序的候选清单，
全部写在[research/06 引擎自身性能画像](../research/06_引擎自身性能画像_20260805.md)。

**那一页里有一节叫"本页不是什么"**，写着它不是优化提案的批准。
这里重申一次，因为它是本决策的边界：

> profile数据是提案的**前提**，不是提案的**通过**。spec/13第一节四条义务
> 照旧全部适用——对拍义务分档、算法变更三件套（决策记录＋oracle重验＋
> 复杂度与收敛性说明）、不许静默改精度。有了热点数据只是**可以开始谈**，
> 不是可以开始改。

## 四之二、四个数（本页只列，解释在research/06）

| 数 | 值 | 为什么它重要 |
|---|---|---|
| 能量装配标度指数`p` | **1.02**（R²=0.9999） | WDS是0.59。**方向相反且两者都对**——描述的是两种实现，处方也相反 |
| Hessian装配标度指数`p` | **2.04**（32—512） | 画像里**唯一的复杂度问题**，其余全是常数因子 |
| 加速度回调占积分路径 | **89.30%** | 后端加速上限`1/0.8930=1.120×`；实测比值0.72—1.07，**NumPy加速档在积分路径上没有收益** |
| 边核重复求值 | **2.0×／3.0×边数** | `quantities`没有融合——spec/12第3.1节写着要避免的"重做三遍"，倍数恰好对上 |
