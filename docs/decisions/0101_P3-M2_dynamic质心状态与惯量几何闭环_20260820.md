## 一、问题不是“把dynamic拒绝删掉”

0100明确拒绝dynamic，因为当时三件事没冻结：状态原点、质心所在frame、几何位姿与积分状态的往返。
若只删掉拒绝，`SceneAssembly`会把dynamic体当成一个不动的`PosedBody`；外观是“装进去了”，物理上是static。

本批先以既有`rigidbody.RIGID_BODY_LAYOUT`为权威，再定交接，不新造第二套刚体状态。

## 二、冻结的dynamic frame约定

`DynamicStateFrame.CENTRE_OF_MASS_GEOMETRY_AXES`的完整含义：

1. `RIGID_BODY_LAYOUT.centre_of_mass_position_mm`是root/world frame下的质心位置；
2. `centre_of_mass_velocity_mm_per_s`在root/world轴表达；
3. `attitude_body_to_world_xyzw`的body轴与geometry resource frame平行；
4. `angular_velocity_body_rad_per_s`在该body/geometry轴表达；
5. `MassProperties.centroid_mm`是geometry frame中的COM坐标；
6. `inertia_about_centroid_kg_mm2`绕COM，但张量分量仍在geometry/body轴表达。

设geometry frame为G，COM/body frame为B，质心坐标为c，则G与B轴平行：

```text
G_from_B.translation = c
B_from_G.translation = -c
root_from_B = root_from_G ∘ G_from_B
root_from_G = root_from_B ∘ B_from_G
```

这两条必须往返回到同一个geometry位姿。故意把第二条的负号改成正号时，初始geometry x从10mm错成14mm，
对应必红当场失败。

## 三、输入与资源扩展

### 3.1 `DynamicBodyInitialState`

`PhysicsBodyBinding.dynamic_initial_state`只对dynamic合法，必填：

- `state_frame`：当前只接受上述COM+geometry轴约定；
- `centre_of_mass_velocity_mm_per_s`：root/world系线速度；
- `angular_velocity_body_rad_per_s`：body/geometry系角速度。

position和attitude不重复存：它们由模型参考位姿、`component_from_asset/shape`和质心唯一推导。
这是`physics_model_motion_input/0.1`draft的又一次破坏性修订；尚无外部消费方，P3.2前必须统一重审版本。
同批为每个material/mass-properties ID增加必填内容SHA；只对ID不对字节会让同名材料或惯量静默替换。

### 3.2 `MassPropertiesRecord`

质量属性不只有ID，装配时必须得到：

- `mass_properties_id`；
- 它所属的`geometry_resource_id`（asset或shape）；
- `expressed_in_frame_id`；
- `MassProperties`（体积、geometry frame内质心、质量、绕质心惯量）。

`MassPropertiesRecord`自内容寻址并带`EvidenceRef`。`SceneResourceCatalog`同时提供已密封的
`MaterialRecord`和已密封质量属性。binding ID/SHA、geometry resource ID、geometry frame ID任一不同都拒绝。
同ID但改密度/质心/惯量同样因SHA不同被拒绝。故意绕过resource ID门时，对应必红实际变绿而让测试失败，证明该门承载了真语义。

## 四、模块化实现

### 4.1 `dynamic_body`

新模块只管dynamic体交接：

1. 验材料、质量属性、resource和frame身份；
2. 用`RigidBodyInertia`复用对称、正主惯量和三角不等式门；
3. 从初始`root_from_geometry`推导13维COM状态；
4. 从任意后续COM状态反算`PosedBody`几何位姿。

### 4.2 `model_scene`

`model_scene`现在属力学域，因为它已经import`dynamic_body`/`rigidbody`/`State`，不再是纯scene基座编排。
装配时dynamic `SimBody`在`FinalizedScene`中保持identity声明位姿，真位姿只能经
`PreparedModelScene.posed_bodies_at_time(..., dynamic_states=...)`生成。缺状态、漏一个dynamic体或多一个未知body ID均拒绝。

dynamic只接受`time_s`计划；`planning_scale`没有物理时间，不能驱动积分器。

## 五、P3-M2案例

`cases/dynamic_model_scene_free_flight`：

- geometry原点初始x=10mm；
- geometry frame内COM x=2mm，故状态COM x=12mm；
- 质量1kg，惯量diag(1,1,2)kg·mm²；
- 世界系线速度0，体系角速度绕z为πrad/s；
- RK4以0.001s推500步，无外力/力矩。

独立闭式预言：0.5s后COM仍为(12,0,0)mm，姿态绕z转90°，geometry原点相对COM的
(-2,0,0)mm转成(0,-2,0)mm，故末态geometry原点为(12,-2,0)mm。金标生成器不import被验模块。

案例总数53→54；主能力17/42与端到端0/6不变。

三条均量三组、每组9次，表中取三组批中位的中位；load1为4.286—7.949。严格输入第三组有明显瞬时扰动，
所以91.364ms只是观察到的最大单趟，不是功能判据。dynamic装配仍是小对象和3×3张量；500步自由飞行是13维小状态串行推进。
两条都不是适合GPU的大数组核，当前CPU已是交互级。若以后同时推进大批互不依赖的dynamic体，先评案例级多进程，
再按spec/13三门槛评数组后端。

## 七、已知边界与下一步

1. 完成的是单体自由刚体，不是dynamic接触、约束、多体或力学—运动切换。
2. 质量属性记录是已命名输入；fixture不证明真实网格的质量分布。
3. `FinalizedScene`中dynamic体的identity pose只是声明槽，不是运行真位姿；运行代码必须经`PreparedModelScene`并提供精确状态集。
4. 无WII adapter、WDS采用、真实资产选择进入或现场标定。

触发条件：下一片把两个dynamic体与显式候选接进现有dynamic接触流水线，要求状态集每帧驱动几何、接触力/力矩再反馈状态，
并保留状态所有者唯一。WII仍不是该前置。
