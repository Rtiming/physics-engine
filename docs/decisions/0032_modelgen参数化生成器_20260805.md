# 0032 modelgen参数化生成器：spec/11规则2第二类的首个实现（2026-08-05）

状态：已落地。**资产圈的`modelgen`第一次有真实的"参数→形状"纯函数**——
在此之前它只有一个引用壳：`shapes.GeneratedShape`带`algorithm_id`+版本+参数元组，
却没有任何一个生成器往里填东西（plans/02第一节资产圈的原话："modelgen只有引用壳
无真实生成器"）。

进仓门：规范面 ✅ spec/11规则2第二类（草案面已登记）；消费方 ⚠️ 本仓案例
（与plans/02判断一致）；字节不变 ✅ 纯新增，既有产物指纹未动；预算申报 ✅ 见第七节。

## 一、交付

- `src/physics_engine/modelgen.py`——三个纯函数生成器（spec/11规则2点名的那三个）
  加一个装配件记录与一份声明指纹：

  | 生成器 | 参数面 | 产出 |
  |---|---|---|
  | `generate_spool` 带盘 | 特征长度 + 筒半径比/筒全宽比 + 法兰外径比/法兰厚比（成对可缺省） + 已卷层数/单层厚比 | 1件或**3件**`FiniteCylinder`：`barrel` + `flange_low` + `flange_high` |
  | `generate_roller` 导轮 | 特征长度 + 半径比 + 面全宽比 | 1件`FiniteCylinder`：`face` |
  | `generate_former` 骨架 | 特征长度 + **无量纲骨架点列** + 根半径比/梢半径比 | n−1件`Capsule`：`link_0`…，半径沿链锥度插值 |

  每件都是`GeneratedPart`（装配内部局部偏移 + `GeneratedShape`），
  `GeneratedShape.parameters`盖的是**整次调用**的完整参数表。
- `cases/generator_determinism`——A档、interactive，5条oracle，
  conformance在`tests/cases/test_generator_determinism.py`（6条）。
- `tests/test_modelgen.py`——43条拒收/形制门（每条失败关闭配一条必须红）。

**除`characteristic_length_mm`外没有第二个带单位的入参**，这是case2
`src/robot_links.py`§J1的形制（"一切长度均来自spec常量，本模块只写无量纲系数，
不出现任何连杆长度字面量"）搬进引擎的第一次。它在本仓有可执行判据，见第三节。

## 二、法兰：按0034的裁决办——不动词汇，在生成器层组合表达

spec/11第二之二节登记的缺口是：`FiniteCylinder`有`flange_outer_radius_mm`却
**没有法兰的轴向尺寸**，于是同一份声明对应无穷多个真实质量分布，
`geometry.mass_properties`对它失败关闭。**决策0034第四节已裁：
本轮不动形状词汇，维持失败关闭**——两条候选修法都要改规则2的词汇，
而今天没有任何消费方在用带法兰的导轮（WDS碰撞预演批次未开工），
无真实牵引时改词汇就是"为想象中的需求预支通用性"。
那一节并点名"`modelgen`的带盘生成器按同一纪律处理（决策0032）"，即本页。

本模块按那条纪律办，**词汇一个字没动、`shapes.py`与`geometry.py`一个字节没动**：
带法兰带盘在**生成器层**用既有原语组合表达——筒一件、两片法兰盘各一件，
全是既有的`FiniteCylinder`，`flange_outer_radius_mm`在本模块产出的任何圆柱上
**恒为`None`**。三条理由：

1. **组合表达不需要新词汇**。加轴向尺寸字段那条要改规则2、还会让WDS导轮的既有
   声明形制变，是0034压住的那件事；"一个形拆成三件既有原语"用的是行业惯例本身
   （primitives优先、组合表达复杂形），落在生成器里，不落在词汇里。
2. **这个分解是精确的，不是近似**。真实带盘实体
   `{r≤R_b, |z|≤W/2+w} ∪ {R_b<r≤R_f, W/2<|z|≤W/2+w}`
   与"筒(R_b,W) + 两片盘(R_f,w)贴在筒两端外侧"是**同一个点集**，
   且三件轴向区间互不重叠（筒占`|z|≤W/2`，盘占`W/2≤|z|≤W/2+w`）。
   不损失几何，只是把一个形拆成三件；体积可直接相加，惯量按平行轴定理合并。
3. **不这么办，"产的形是真形"这条判据就不可达**。带法兰的圆柱在`geometry`那头
   永远算不出质量属性，第三条判据会从"红"退化成"不可达"——那比红更坏。
   实测见第五节R5：把生成器改成产带法兰的圆柱，案例当场报
   `GeometryError: a flanged FiniteCylinder has no declared flange width…`。
   **0034说的"那条错误消息就是需求的入口"，在本轨道被实测触发了一次。**

0034的触发条件（WDS碰撞预演批次或case2给出带法兰导轮的书面需求）真到来时，
本模块是"独立第二个形"那条候选修法的一份**可用实现与一条精确分解的证明**——
是那场裁决的材料，不是对它的抢先。

**顺带一条给那场裁决的材料：法兰的两个尺寸不是本仓要发明的东西。**
WDS的`CylinderSurface`（`dynamic/cylinder_contact.py`）早就给法兰**两个**尺寸：
`flange_channel_width_mm`（两壁内侧面的轴向间距）与`flange_height_mm`
（壁高出接触面的径向高度）。本模块的`barrel_width_ratio`就是前者，
`flange_outer_radius_ratio − barrel_radius_ratio`就是后者。
**"法兰没有轴向尺寸"是引擎侧的缺口，不是消费方侧的**——消费方一直是有的。
真到了要加字段那一步，加的是WDS已经有的那两个，不是"再补一个宽度"。

## 三、确定性判据的逐字节对象，以及为什么进程内比两次不够

逐字节的对象是`declaration_bytes(parts)`：把产出摊成纯JSON结构
（件序=产出序、键序由`sort_keys`统一）再走`canonical.canonical_bytes`。
判据有三条，各抓一种不同的隐患：

1. **同进程两次调用字节相等**——纯函数的最低门。
2. **换`PYTHONHASHSEED`起两个子进程，SHA与本进程相同**。这条是必要的：
   同一进程里字符串哈希种子是同一个，**集合/字典迭代序即使参与了输出，
   两次调用也会一起错**，进程内比两次抓不到它。实测见第五节R2——
   把件序改成按`hash(part_id)`排，进程内判据仍绿，跨种子当场红。
3. **`-0.0`与`0.0`产同一份字节**。`-0.0 == 0.0`为真而`json.dumps`给出
   `"-0.0"`与`"0.0"`：同一个几何点两份声明。归一放在入口`_clean`做，
   因为符号一旦进了算式会顺着乘法传播到每一个坐标。

**判据刻意不冻结任何一份具体哈希**：声明指纹的形制不是已登记的面
（`engine_facets.py`里没有它，也不该现在有——它不落盘、不跨边界）。
把哈希冻进金标等于让一个未登记的字节形制长出依赖者，那正是面清册义务要拦的事。
判据因此全是**关系型**的（两份字节相等、22条扰动全部改变、40个长度逐位翻倍），
形制将来若要登记成面，金标不必推翻。

### 3.1 一位变化必反映——顺带撞出的一个事实

22条一位扰动（浮点走`nextafter`、`wound_layers`走`+1`、骨架点逐分量）
**全部改变声明字节**。但其中**恰有一条不改变形的几何**：
`spool.layer_thickness_ratio`。原因是`R_eff = 0.25 + 8t`这个加法：
`8×ulp(2⁻⁹) = 2⁻⁵⁸`远小于`½ulp(0.265625) = 2⁻⁵⁵`，末位被吃掉了。

所以"参数变一位则声明必变"**成立是因为参数表进了产出**——只看形的尺寸的话它不成立。
这不是一条可有可无的溯源装饰，它是判据本身的承重件。金标里冻的是**名单**
（`absorbed_perturbation_labels`）不是个数：名单变长意味着又有参数不再影响几何，
那是参数面该重审的信号，而不是一个可以顺手改的计数。

### 3.2 "系数化不写死毫米"的可执行形式

把`characteristic_length_mm`乘**2**，产出的40个长度**逐位**等于原值的2倍。
零容差是算出来的而不是乐观：2的幂缩放在IEEE-754二进制浮点下无舍入
（尾数不变、指数加1，除非溢出或落进次正规），所以这是位判据不是数值判据。
**任何写死的毫米量都会当场破它**——实测见第五节R4：给筒半宽加`+ 1.0`，
40个里3个不再逐位翻倍。case2那条§J1纪律至此在引擎里有了门，不再只是一句约定。

## 四、容差是算出来的，不是放宽到能过为止（0024第三节先例）

质量属性的容差取`rel = 1e-15`。它这样来的：oracle与`geometry.mass_properties`
**只差乘法结合次序**——后者先算体积、再用`scale = m/V`把质量乘回形状矩，
前者直接把质量乘进闭式。多出一次除法与一次乘法，界约`3×(eps/2) = 3.3e-16`。

逐条实测（相对偏差）：筒体积1.67e-16、筒质量1.62e-16、筒`I_zz`1.44e-16、
筒`I_xx=I_yy`**恰为0**；法兰体积与质量**均恰为0**、法兰`I_xx=I_yy`1.16e-16、
法兰`I_zz`**2.34e-16（最大值）**；装配体积0、质量1.70e-16、`I_xx`1.75e-16、
`I_zz`1.67e-16；导轮体积与`I_zz`**均恰为0**、导轮`I_xx=I_yy`2.09e-16；
骨架两段体积**均恰为0**。

1e-15 = 实测最大值的4.3倍、解析界的3倍。**把它收到2e-16实测即红**：

    oracle:modelgen/spool_mass_properties: assembly_inertia_diag_kg_mm2[2]
      expected 87398.81117715871, got 87398.81117715868 — exceeds abs=0.0 rel=2e-16
    oracle:modelgen/roller_mass_properties: inertia_diag_kg_mm2[0]
      expected 543.0486488257947, got 543.0486488257948 — exceeds abs=0.0 rel=2e-16
    2 failed, 4 passed

那些"恰为0"不是运气，是设定：入参刻意取二进制精确值（0.375=3/8、0.0625=1/16、
0.001953125=1/512、L取2的幂），"比值×L"这一步无舍入，剩下的差只有乘法次序。
把这件事写进案例页第一节，是因为半年后有人换一组"好看的整数"参数时，
容差会变松而没人知道为什么。

## 六、蒸馏来源对照（"蒸馏不发明"）

| 本模块的哪一条 | 来源 |
|---|---|
| 只写无量纲系数、一个特征长度入参 | case2 `src/robot_links.py`§J1 |
| 生成器带版本串 | case2 `SCHEMA_VERSION = "case2-kr240-links-2.1-…"` |
| 沿链插值的锥度（根粗梢细） | case2 `K["fo_h_el"] → K["fo_h_tip"]`（前臂竖长断面） |
| 有限宽圆柱的参数面（半径 + 面宽） | WDS `dynamic/cylinder_contact.py::CylinderSurface` |
| 法兰两尺寸必须成对给出或成对缺省 | 同上（`flange_channel_width_mm`/`flange_height_mm`的`(A is None) != (B is None)`拒收） |
| 带盘半径随已卷层数生长 | WDS `dynamic/winding_surface.py::WindingSurface.effective_radius_mm` |
| 骨架相邻点重合即拒 | WDS `dynamic/static_obstacle.py::CapsuleObstacle`（退化轴即拒） |
| 装配内部局部偏移与世界位姿分离 | spec/11规则3（形状不携带位姿；WDS的`RollerState`+`CylinderSurface`是先例） |
| 生成器身份带`algorithm:`前缀 | spec/11规则7，门已在`shapes.GeneratedShape`里 |

**确属增量的三条，显式标注**：

1. `GeneratedPart`——"一次生成产出多件、每件带装配内部局部偏移"。
   WDS/case2都是"一个对象一个形"或"整块B-Rep实体"，没有这层。
   本模块需要它，**只因为法兰走了独立形那条路**（第二节）；
   若将来规则2给`FiniteCylinder`加了法兰轴向尺寸，这层可以退化成单件。
2. `declaration_bytes`——声明指纹。WDS/case2都没有"同参数逐字节相同"这条门
   （case2有`strict_acceptance.py`但比的是几何量不是声明字节）。
   理由是引擎多一条约束：生成器是**纯函数**，而纯不纯只能用字节证。
3. 齐次性判据（λ=2逐位）——没有出处，是把case2的§J1纪律翻译成可执行门。
   case2靠代码评审守它，引擎靠门守它。
