## 一、裁决

### 1.1 物理基础设施的家

绕制偏差所需的公共物理基础设施进入本仓：

- 模型角色、单位、坐标系、内容身份与物理输入闭包；
- 杆/带材、接触、摩擦、输运、张力驱动和测量物理；
- 求解、观测量、证据等级、案例、oracle和run package；
- CPU参考路径与经过三门槛的可选加速后端。

不新建“绕制物理平台仓”，不把公共物理继续堆在WDS里，也不让上位平台提案抢走物理主线。

### 1.2 三仓所有权

| 仓 | 拥有什么 | 不拥有什么 |
|---|---|---|
| GCW | STEP/B-Rep、槽中心线、材料帧、assembled帧、制造/派生资产发布 | 物理求解、WDS结果、机器人时间线 |
| WII | 机器人/E1/工件运动学、路径、模型身份、official timeline、机器人-工位碰撞 | 带材接触力、张力传播、落位偏差和材料本构 |
| physics-engine | 模型物理角色校验、带材/接触/张力/测量/求解和物理案例 | B-Rep生产、IK/FK、路径搜索、领域UI |
| WDS | 选择工艺场景、只读消费上游产物与本仓API、组织代表窗口、输出偏差统计 | 改写GCW中心线、改写WII轨迹、复制公共物理实现 |

### 1.3 集成方式

跨仓只走版本化、内容寻址产物。禁止：

- WDS运行时import GCW/WII源码；
- physics-engine运行时调用WII碰撞服务；
- WDS反向写GCW/WII目录或结果；
- visual资产静默进入collision/physics角色；
- 把WII显示插值帧当物理时间线；
- 把一个LTS标量冒充T0—T4五段直接测量。

允许给上游补接口，但接口只发布上游拥有的事实，例如缺失的official timeline、frame、模型角色、SHA、单位与不确定度。不得要求上游实现本仓物理。

## 二、WII/GCW模型的直接使用边界

**可直接消费**：通过交付门的GCW中心线/sidecar、assembled帧、明确标成collision的网格资产、未来official `wii_motion_timeline.v2`及其模型身份。

**不可直接用于物理**：visual STL/GLB、当前工作台轨迹指针、WII碰撞报告中的距离结论、未声明单位/frame/用途的网格、整个机器人/工位大网格。

“直接消费”仍要经过本仓reader和角色门，不等于把上游JSON原样传进求解器。

## 三、第一条实现主线

第一条新物理基础设施不是再加一个孤立接触族，而是补齐张力测量链：

```text
两侧带材张力与方向
→ 测力轮矢量合力
→ 导轮自重与支承分配
→ LTS敏感轴投影
→ mV/零点/量程/ADC/时延
→ ATC600显示或控制输入
```

先以解析小场景验证，再接合成收放线，最后才接现场标定。现有`drives.TensionSensor`作为电气量化层种子保留，不把它当前的“输入已经是张力”静默扩义为完整测量模型。

## 四、为什么现在裁

1. 现有案例已经证明张力、输运、接触和控制片段能单独运行，但没有一条验证绕线机LTS为什么读出这个数；
2. 当前最危险的误差不是ADC台阶，而是包角、敏感轴和传感器位置把“真实张力”映射成另一个量；
3. WII/GCW已经有可复用的模型/中心线/运动产物种子，再另造物理模型格式会制造第二真源；
4. WDS当前只使用引擎单站能力，若不先固定调用边界，公共物理会继续在两仓重复生长。

## 五、代价与后果

- 本仓会增加新的实验档物理面和小场景，但每个跨边界字节形制仍须先登记facet；
- WII/GCW可能需要补发布字段或official产物，但它们不承担物理实现；
- WDS后续需要采用本仓API，但采用必须走WDS自己的冻结diff、回执和既有产物不变门；
- 真实LTS的单/双传感器、导轮质量、包角、敏感轴和VR451比例未确认前，结果保持`hypothesis_only`；
- GPU不进入第一批。测量方程与模型角色没闭合前，GPU没有正确的数学可加速。
