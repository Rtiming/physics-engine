## 一、清单面：`src/physics_engine/oracles.py`

面名与版本从`engine_facets.py`取（`engine_oracle_manifest` 0.1，T0已登记，
本轨道只import不改）。字节走`canonical`。零运行时依赖。

规则2要求的四样东西各有执行体：

| 规则2要求 | 执行体 | 破了会怎样 |
|---|---|---|
| 生成器身份 | `GeneratorIdentity`，含**脚本自身的SHA-256** | 改了生成器不重生成金标→读侧当场红 |
| 逐条expected+逐条tolerances | `OracleCase`，加载期强制`set(tolerances) == set(expected)` | 多一条少一条都拒收 |
| 数组双哈希 | `ArrayDigest`：raw级盖文件字节、语义级盖dtype+C序字节流 | 前者抓"文件被动过"，后者抓"换了存储形式而值该不变" |
| 清单自指哈希 | `manifest_self_sha256`，基准=去掉自指字段后的**规范字节** | 手改一个expected而不重生成→加载失败 |

三条本仓自己的加强：

1. **每个量都要有理由**。`tolerances`的每一条必须带非空`reason`，
   `abs=rel=0`的零容差也要写（"为什么可以是零容差"和"为什么是1e-9"一样需要交代）。
   这是把plans/02"判据表→量→rel/abs→**理由**"从文档义务变成**加载条件**。
2. **非数值量的容差必须是零**。`expected`里的bool/str/null按逐位相等比，
   给它们配非零容差直接拒收——那种声明本身就是没想清楚。
3. **`regenerated_by`必须指向存在的决策记录**。形制抄FEBio `acceptChanges.py`，
   加本仓硬约束：字段值必须以`docs/decisions/`开头且文件真的在。
   规则5"重生成金标必须走决策记录"从此有执行体，不再只是纸面规定。

**清单按`indent=2`落盘**，这是一处刻意的形制选择：清单的身份是**规范字节**的
SHA-256，与文件排版无关（正是轴3规范化的用处），所以文件可以排成人能读的样子。
理由是评审——金标改一个数时`git diff`只显示那一行，而规则5要审的正是这种改动；
压成一行则整份清单一起变，审无可审。`tests/test_oracles.py`里有一条测试
（重新缩进后自指哈希不变）把这个性质钉住。

写侧只开`write_manifest`一个口子，它落盘前把文档**喂回加载器**——
"生成器产出一份加载器拒收的清单"这件事因此不可能发生。

## 二、四条A档案例

全部`load_tier=interactive`、判据强度A档（research/05第一节最强一档）。

| 案例 | 判据 | 为什么是它 |
|---|---|---|
| `segment_distance` | `d = segdist − (r1+r2)`，abs 1e-12mm；11条oracle | `segment_segment_distance_mm`是全仓唯一在算实数值的内核。**先给唯一的内核建judge，再谈加内核** |
| `rotated_aabb` | 八角点枚举 对 Arvo中心-半边长闭式解，abs 1e-9mm；5条 | 第二个在算的内核。覆盖四元数次序、矩阵转置、平移漏加、圆角/法兰漏计四类典型错 |
| `broadphase_superset` | `separation<0 ⟹ AABB相交`，反例严格为0；120对固定种子语料 | 碰撞查询对外唯一的硬承诺，且是**可证命题不是拟合数** |
| `mesh_asset_integrity` | `sha256(资产)==声明`；逐轴`declared_min≤true_min`、`declared_max≥true_max`；均零容差 | **今天就必红**的一条（0017第四条那个真实缺陷至今没有门能发现） |

三处值得单独记的裁决：

**`test_narrow_phase.py`的判据搬家**。原先手算值（5.0/2.0/0.5/3.0/2.0）写死在
测试里，验的是"测试和内核是不是同一个人写的"，不是内核对不对（规则3明写
"不得在测试里复述oracle公式"）。搬进清单后同批补上**五条退化分支+一条一般路径**，
每条都由一次`sys.settrace`（开`f_trace_opcodes`）实测确认走到了`collision.py`
声明的那一条——第60行的三元表达式两侧同在一行，行级trace分不开，故按`dis`
给出的字节码偏移区分。原文件保留的是**没有金标数值**的那一类事实（可信度分级、
诚实降级），它们属接口诚实性不属轴7。**这不是规则5禁止的"删除测试"**：
是同一批判据的迁移+加强，覆盖面严格变大。

**独立性怎么做到**（规则4）。三个生成器各自带一份独立实现，都不import被验内核：
线段距离用**凸一维黄金分割搜索**（把二维最小化化成"点到线段距离"的一维凸最小化，
与Ericson的钳制-重算不是同一条路径），包盒用Arvo求和。注意分寸：
`segment_distance`的金标是**手推闭式值**（全部是可精确表示的整数），
搜索法只做1e-9的交叉验证防手算笔误——搜索法的精度不足以当1e-12判据的源，
把它当金标是自欺。

**合成资产入仓**（Chrono形制）。`examples/`那个KUKA连杆的STL在WII仓、不在本仓，
包盒保守性判据没有字节可查。所以自带`assets/tetra.stl`（284字节二进制STL）+
`assets/generate_tetra.py`（纯标准库、确定性输出、生成脚本一并入库）。
二进制STL解析放**案例侧**约25行`struct`，**不进`src/`**——引擎当前的设计是
"不解析网格字节、包盒由声明携带"，把解析塞进产品面等于顺手改了能力边界，
那是B档的裁决不是本案例的副产品。

## 三、案例页六必填字段与`tools/check_case_pages.py`

六个字段（物理/几何设定、参考解出处、判据表、已知失效清单、档位与负载级、
本案例不是什么）缺一即红，`tools/accept.py`的可选槽位**文件在就自动上膛**，
本批建完即进full档。外加三条结构校验：案例目录必须被`cases/README.md`索引到；
有`oracle.json`就必须过严格加载器；清单的`case_id`与`load_tier`必须在页里出现
（页与清单各说各话，pytest marker就会跟着错）。

第六个字段"本案例不是什么"（Drake形制）挡的是"绿了就以为万事大吉"。
本批四条案例的这一节各写了三到五条，其中两条特别要记住：

- **世界AABB不是SE(3)不变量**。"整场景旋转后事件集合相同"是**错的**判据——
  含`finite_cylinder`/`rounded_box`/`mesh`的对必然红。`broadphase_superset`
  在页里明写不写这种判据，将来也不要写。
- **`envelope`与`fitted`语义不同**。贴合形不承诺包住资产，包络保守性判据
  对它不成立、也不许套用；门遇到`fitted`**拒判**而不是判红（套上去会得出一堆假红，
  然后有人去放宽容差，最后包络判据一起废掉）。

## 四、每个门都红过（规则6）

实测记录（2026-08-05本机，每条实验后都恢复原状并复跑绿）：

| 门 | 怎么让它红 | 实测结果 |
|---|---|---|
| 自指哈希 | 手改一个expected不重生成 | 收集期`manifest self hash mismatch` |
| 容差比对 | 改错expected并补回自指哈希 | `branch_parallel: distance_mm expected 3.000000001, got 3.0 — exceeds abs=1e-12 by 9.99e-10` |
| 生成器SHA | 给生成器加一行注释 | 收集期`generator script changed without regenerating the oracle` |
| Arvo判据 | 四类典型错重算包盒 | wxyz误读最大偏差31mm、转置18.5mm、平移漏加40mm、直接对`hi`套式65mm，全部远超1e-9mm |
| 超集不变量 | 把世界包盒半边长×0.95 | `aabb_overlapping_pairs 93→88`红；缩到×0.40时反例数才从0变13——**冻结的计数比不变量本身灵敏**，已写进案例页 |
| 数组raw哈希 | 改`samples.json`一个字节 | 收集期`array 'samples' raw bytes changed` |
| 资产SHA | 改`tetra.stl`一个字节 | 两条场景的`sha256_matches expected True, got False` |
| 语料防篡改 | 把必红语料"修好"成合格包盒 | `语料场景文件被改过而清单没重生成` |
| 案例页六字段 | 删标题/去理由列/负载级不符/未进索引/删case.md/手改清单 | 六种破坏各自exit=2并指名问题 |
| 加载器全部拒收路径 | `tests/test_oracles.py` 34条 | 常驻门，不是一次性实验 |

## 六、留给后续的

1. `tools/accept.py`的ruff只扫`src tests tools`，**不扫`cases/`**——
   案例侧的生成器现在靠人工跑ruff保持干净。把`cases`加进那条命令是一行改动，
   但`accept.py`属别的轨道，本轨道不动别人的文件。
2. 轴1规则6的"金标重生成须版本跳变"联动门尚未实现；本批只做了
   `regenerated_by`必须指向存在的决策记录这一半。
3. 二进制STL解析要不要升进`src/`：**建议暂不**。理由是本仓至今没有任何
   消费方要求引擎解析网格字节（代码三前提第二条：不为想象中的需求预支通用性），
   且升进去就要一次性回答ASCII形、大端、属性字节、退化三角形、流式读取
   五个问题。真要升，触发条件应当是"某个消费方需要引擎自己算网格包盒"，
   那时连凸包与惯量一起做，属B档。
