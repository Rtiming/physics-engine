# 模块地图与域划分（v0草案，2026-08-04）

状态：**草案**。用户2026-08-04晚指示：本仓的定位是**物理引擎**——除物理域外，
还要装模型生成、物理性质（材料）、外观（颜色）等模块，分模块组织。
本页给目标模块图与各能力的现居地，是存量迁移（README阶段3）的底图。

## 一、目标模块图（四圈）

```text
┌────────────────────────────────────────────────────┐
│ 呈现与交互圈  render(离线/在线) · interaction        │
├────────────────────────────────────────────────────┤
│ 物理域圈  mechanics(力学) · optics(光学)             │
│           · [将来] thermal / electromagnetics       │
├────────────────────────────────────────────────────┤
│ 资产圈  modelgen(模型生成) · materials(物理性质)     │
│         · appearance(外观/颜色) · shapes(形状声明)   │
├────────────────────────────────────────────────────┤
│ 内核圈  contracts(契约) · provenance(溯源)           │
│         · verification(验收) · scene(场景装配)       │
│         · orchestration(案例/批量编排)               │
└────────────────────────────────────────────────────┘
```

> **环序已于2026-08-05纠正（决策0035）**：资产圈原本画在物理域圈**之上**，
> 与本页第四节第1条"物理域从材料记录取参数"直接矛盾——那是一条向上的边。
> 代码里同一件事也已发生（`scene`import`shapes`）。
> **图错、文本对**：资产圈按第四节第1条的定性是"数据与校验、不含求解器"，
> 它是物理域的**输入**不是消费者，一个不含求解器的层不可能在求解器之上。
> 原图大概是按"越抽象越靠上"排的，但本页纵轴的定义是**依赖方向**不是抽象层级。
> 这条矛盾从本页写下来就存在，是域隔离门（决策0031）上线当天抓出来的。

依赖只许向下：呈现依赖资产与物理，资产与物理依赖内核，内核不依赖任何上层。
**物理域之间互不依赖**（力学不import光学）；跨域耦合（如热-力）将来以显式
`couplings/`模块出现，不许在域内偷连。耦合三型与选用规则（research/03，
行业对照COMSOL/preCICE/Genesis）：**默认单向链起步，需要反馈才升分区
（黑盒交换、run package即交换面），单体（同矩阵联立）永远是最后选项**；
声学等新域进来即物理域圈平等公民，同一套规则。

## 四、三条边界（先立住，防散架）

1. **资产圈不做物理**：modelgen产几何、materials记性质、appearance记外观——
   都是**数据与校验**，不含求解器。物理域从材料记录取参数，渲染从外观记录取参数。
2. **引擎不吞专用工作台**：GCW/WII作为工作台继续存在，引擎抽的是其中
   域无关的形制（参数化生成、导出、校验门），不是搬迁整个应用。
3. **规范先行不因扩圈松动**：新模块进代码的前提仍是对应规范轴冻结+消费方
   产物指纹逐字节不变（README阶段阶梯不变，只是地图变大了）。
