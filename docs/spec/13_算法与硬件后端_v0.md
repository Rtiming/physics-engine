# 算法与硬件后端（v0.1草案，2026-08-05凌晨）

状态：**草案，不冻结**——后端适配层在本估算尚无实现（0.x纪律）。
但本页大半条款是**既有法律的汇编**：WDS的无状态纯函数约束与GPU三门槛、
Metal无fp64的实测、design/24七之二的一致性门——它们今天就有效，
本页只是把它们拧成一个轨道的规范。用户2026-08-05定此为开发计划之一：
**算法要足够优，硬件性能要吃满，做驱动/后端适配——规范先行，确保正确。**

## 一、算法侧：优化的四条义务

1. **profile先行**：没有火焰图/热点数据的优化提案不受理
   （本估算实测教训：同一问题三次归因全错）。
2. **对拍义务分档**：声称"结果不变"的优化附**逐字节对拍**；改变数值路径
   的优化附**分量声明容差**的对拍（轴7规则6的解析oracle+有限差分照跑）。
3. **算法变更三件套**：决策记录+oracle重验+复杂度与收敛性说明
   （新算法凭什么更优要写出来，不许"感觉更快"）。
4. **不许静默改精度**：fp64→fp32不是优化是**换物理**，归第三节的
   快物理框架管，配一致性门才准用于训练/交付。

## 二、后端侧：五条规则（草案）

1. **单一物理定义，多后端执行**（MJX形制，官方文档核实：同一数据模型
   与算法，CPU/GPU/TPU无缝切换）。后端只**执行**声明好的数学，
   永远不得重新定义物理——"后端≠第二套物理实现"是前端"不得重算物理"
   边界的算力版。
2. **数组API边界**：可迁移内核按"无状态纯函数+显式状态数组"书写
   （WDS既有法条，为libuipc/Warp预留的接入面就是本条），数值命名空间
   收窄到可替换（numpy↔cupy↔jax同形制）；不引入Taichi（官方停摆，
   既有裁决）。
3. **等价性门硬性**：CPU float64是**参照真值**；任何后端上线前过同一套
   解析oracle+跨后端对拍（分量容差声明）。降精度后端=快物理实例，
   **受design/24七之二一致性门管辖**——先有门，再有采用。
4. **三门槛立法**（升格WDS既有裁决为引擎法条）：只有
   ①profile证明主要热点可迁移、②CPU/GPU物理等价、③端到端三次中位≥2×
   提速，才评审任何加速后端原型。差一条都不动手——硬件适配是重资产，
   不许为"看起来快"预支。
5. **确定性分级申报**：每个后端声明确定性等级——
   `bitwise`（逐位可复现）/`same_hw_deterministic`（同硬件同序可复现）/
   `nondeterministic`（原子操作乱序）。轴3的复现指纹规则按级适用：
   bitwise级跑同种子逐位测试，其余级只做容差对拍且**产物必须标注等级**，
   不许拿nondeterministic后端声称指纹。行业在GPU原子加上栽的跟头，
   我们在规范里先挡住。

## 三、溯源延伸：驱动版本进run包

后端运行的产物，`runtime_environment`必须记录：后端名与版本、
驱动/工具链版本（CUDA/Metal/编译器）、BLAS实现、确定性等级。
驱动升级能在ULP层面改结果——**驱动版本是复现性元数据**（轴3的自然延伸，
FTS的dependency_fingerprint已是先例）。
