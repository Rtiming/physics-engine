# 轴6：验收预算与元门禁（v1.0，2026-08-04冻结）

状态：**已冻结**（决策记录[0006](../decisions/0006_冻结轴6至7_20260804.md)）。
版本语义按[轴1](02_轴1_分面版本冻结制_v1.md)。

证据：WDS `scripts/verify_project.py`（三轴正交回执、workspace指纹
`git ls-files --cached --others --exclude-standard`、竞争进程与负载资格、
30/120预算）与两套benchmark的执行树哈希；FTS `tools/accept.py`

## 一、六条规则

1. **双档预算冻结**：快档30秒、全档120秒。这组数两仓在互不知情时各自选中，
   本轴将其冻结为共同预算；改动须决策记录。**预算只裁决开发吞吐，不裁决
   物理正确性。**
2. **三轴正交裁决**：功能、计时（SLA）、资源资格三个verdict互不掩盖——
   功能失败不被计时绿掩盖；**超时归not_completed/not_evaluated，绝不pass**；
   资源不合格时计时判not_evaluated而非fail。
3. **验收期间仓库身份必须稳定**：已跟踪+未跟踪（排除ignore命中）文件的
   内容指纹，验收前后比对；变了→blocked/fail，即使功能全过。快照必须在
   互斥锁内、先于一切预检取得。
4. **资源争用拒绝裁决**：竞争测试进程、负载超限、验收锁争用→blocked。
   **blocked不是fail**——它是"拒绝在被污染的机器上给出无意义计时"，
   功能结论照常保留或标not_evaluated。
5. **性能回执绑执行树**：受验字节树=代码+锁文件+被测输入+金标+基准工具自身，
   排序路径+NUL分隔+内容字节单流SHA-256（排除`__pycache__`/字节码）；
   测量前后比对，不稳→性能裁决不予评估、整体fail；回执携带资源资格与
   功能verdict，**三者同绿性能才可裁决**。
6. **元门禁自身必须有测试**（"判据本身也要被验"）。最低集，每条至少一条
   常驻元测试：预算数值固定、超时不得pass、零执行命令不得pass、
   仓库漂移必须block、（若实现杀进程）超时必须杀掉整棵后代进程树。

## 二、验收判据（门必须红过）

规则6的最低集就是判据清单；采纳方逐条指认自己的元测试或登记缺口。
参考实例：FTS `test_elapsed_budget_overrun_cannot_be_reported_as_pass`、
`test_zero_executed_commands_can_never_pass`、
`test_repository_change_blocks_an_otherwise_passing_acceptance`。
