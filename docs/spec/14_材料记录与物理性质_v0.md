# 材料记录与物理性质（v0.1草案，2026-08-05）——七条规则已有引擎参考实现（materials.py，六条红例全验，决策0023），两个域各自用过之前不冻结

状态：**草案，不冻结**。多数条款是WDS材料记录三件套与FTS `Quantity`证据语义的
蒸馏，但"一份记录同时服务力学与光学"这件事在任何仓都不存在——WDS的
`tape_material`全是力学字段，FTS没有材料记录这一层——按0003纪律作为新设计0.x起步。

冻结条件（三条全满足才谈升档）：

1. 力学侧一个真实WDS材料记录经本形制走完其自身门禁，产物指纹逐字节可交待；
2. 光学侧至少一条FTS会用的材料字段进过本形制，且米制边界按第五节结算过一次；
3. 第三节的证据分级映射里"待收敛"两条有结论。

面登记：`engine_material_record` 0.1（draft，登记在`engine_facets.py`，
T0闸门一次登记齐）。参考实现`src/physics_engine/materials.py`，
门在`tests/test_materials.py`。

## 一、七条规则（草案）

1. **一份记录聚合多域字段，域是属性的标签不是记录的分块**。
   记录声明`applicable_domains`（力学/光学/热/电磁/外观），每个属性再声明自己
   服务哪些域；属性声明的域必须落在记录声明之内，越界即拒。
   **一个字段可以同时属于多个域**——`thickness_mm`既是力学的截面参数又是光学的
   程差参数，这正是聚合记录存在的理由：两个域读到的是同一个值同一条证据，
   不是两份会各自漂移的拷贝。分块形制表达不了这件事，所以不采分块。
2. **物理量带单位后缀，无量纲必须显式登记**（轴2规则3与规则5）。
   字段名以已知单位后缀结尾（`_mm`、`_n_mm2`、`_kg_m3`、`_per_mm`……），
   走`identity.assert_quantity_fields_have_units`；既不带单位又不在
   `dimensionless`清单里的字段失败关闭。`dimensionless`只能登记记录真有的字段，
   登记幽灵字段同样拒——留空装有与登记装有都是同一种病。
3. **每个参数带证据，且证据是参数级的不是记录级的**。
   形制取WDS `EvidenceRecord`：分级+证据ID+方法说明+源工件SHA-256。
   `method`必填非空——轴2规则5的"无出处可追也必须显式写出"落在这里。
   声称有外部出处的分级（measured/calibrated/derived/benchmark_constant/
   manufacturer）必须带源工件哈希；只有estimated与unset可以没有。
4. **未测量就没有值，不是零**。分级`unset`的属性其值必须是`None`；
   任何其他分级的属性必须有值。这一条采FTS的`E_UNSET_HAS_VALUE`/
   `E_VALUE_REQUIRED`而不采WDS的"占位零+`damping_status`旁注"——见第三节。
5. **长度制在记录上声明，同一条记录不许混用**（见第五节）。
6. **按已冻结轴执行**。记录是面（轴1登记，读侧按面版本失败关闭）；
   ID是`material/...`命名空间形（轴2规则1）且只增不改（轴2规则2）；
   引用按内容锁定、自指哈希自校验（轴3规则1与规则4）；
   规范化参数一面一份显式声明（轴3规则2：本面取`WDS_PROFILE`，
   `ensure_ascii=False`——材料记录带中文显示名与限制说明）。
7. **门必须红过**。最低红例集见第六节，**六条**。

## 二、记录的形状

```text
contract_type       engine_material_record（固定）
contract_version    面版本，读侧按轴1校验
material_id         material/<grade>__<geometry>__<basis>__<evidence>__vNNN
length_unit         mm | m
applicable_domains  记录服务的域，非空
dimensionless       显式登记的无量纲字段名
properties[]        name / value / domains[] / evidence{grade, evidence_id, method, source_sha256}
appearance          外观资产引用：asset_id + path_relative + sha256（可空）
content_sha256      自指内容地址，算哈希时剔除自身
```

`appearance`只带**引用**不带渲染参数——spec/01的appearance格写明"外观是资产属性
不是渲染实现"，材料记录负责把外观资产按内容锁住，渲染怎么用是渲染的事。

命名与生命周期直接沿用WDS `config/materials/README.md`：已被引用的记录只增不改，
参数变化新建下一`vNNN`；`derived`不等于成品实测；`benchmark`类记录禁止改名为
具体厂家产品。

## 三、证据分级：两个消费方的枚举与统一映射

WDS `evidence_status`（6档，力学侧实测在用4档）与FTS `ProvenanceStatus`（5档）
并不同构。逐条映射如下：

| WDS `evidence_status` | FTS `ProvenanceStatus` | 统一分级 | 备注 |
|---|---|---|---|
| `measured` | `measured` | `measured` | 两侧同义 |
| `calibrated` | （无） | `calibrated` | FTS无此档；标定与实测在证据强度上同级，故并列不合并 |
| `derived` | `derived` | `derived` | 两侧同义 |
| `benchmark_constant` | （无） | `benchmark_constant` | 见下方待收敛1 |
| `manufacturer` | （无，落在`EvidenceKind.EXTERNAL_REFERENCE`） | `manufacturer` | FTS把"厂家给的"归到证据**种类**轴而非**状态**轴 |
| `hypothesis` | `estimated` | `estimated` | 语义同义，取FTS命名——"估的"比"假设"更贴实际用法 |
| （无，用占位零+旁注状态字段） | `unset` | `unset` | 见下方待收敛2，本页采FTS |
| （无） | `illustrative` | **未采纳** | 见下方待收敛1 |

统一分级的强弱序（`weakest_grade`用，形制取WDS `EvidenceMap.weakest_status`）：
measured=calibrated（最强）＜ benchmark_constant=derived ＜ manufacturer ＜
estimated ＜ unset（最弱）。

**如实登记的两处不一致：**

- **待收敛1：`benchmark_constant`与`illustrative`不是一回事，不许合并。**
  WDS的`benchmark_constant`指"按定义精确"的解析基准常数（软件验证用，
  `rebco_generic__...__benchmark__v001`那条记录），FTS的`illustrative`指
  "编的但看起来像真的"。前者精确后者虚构，合并会把两种相反的可信度洗成一档。
  本页先只收`benchmark_constant`，`illustrative`未采纳——FTS若有材料字段用它，
  在其采纳声明里单独登记，不在这里替它决定。
- **待收敛2：FTS的证据种类轴（`EvidenceKind`：apparatus_fact/design_record/
  derivation/explicit_unknown/external_reference/internal_decision）本页没有对应物。**
  FTS把"怎么得到的"（status）与"来源是什么"（kind）拆成两个正交轴，WDS只有一个轴。
  本页先取一个轴（status形），`manufacturer`就是这个取舍留下的疤——它其实是
  kind轴的值被塞进了status轴。光学侧真正用起来之前不动它，动就是发明。

## 四、按域取字段

访问器`properties_for_domain(domain)`只返回声明了该域的属性；读一个记录没声明的
域失败关闭。`weakest_grade(domain)`按域报最弱证据——力学侧可以因为某个力学参数
是`unset`而拒跑，同时光学侧照常用它的字段，两个域的可信度互不牵连。

这条是聚合记录必须付的税：**记录整体的可信度没有意义，只有"某个域用到的那些字段"
的可信度有意义。**

## 五、mm制与米制的换算边界（在册的静默1000倍）

WDS全仓mm制（`UnitSystem.length = "mm"`固定），FTS全仓米制（`Unit.METRE`）。
同一条记录要服务两边，换算边界就是本面最大的风险点，处理分三层：

1. **声明**：记录带`length_unit`，取值`mm`或`m`。
2. **隔离**：同一条记录不许混用两制。mm制记录里出现`_m`/`_m2`/`_m3`/`_per_m`
   字段即拒，反之亦然。
   **例外是两制通用的SI复合后缀`_kg_m3`**——WDS的mm制记录里实测就带
   `density_kg_m3`，写法本身已把量纲钉死（kg/m³），它不是换算风险点，不进检查。
3. **不隐式换算**。消费方读字段时可以声明`expect_length_unit`；对不上就失败关闭，
   而不是悄悄给出差1000倍的数。跨制取值必须显式调`converted_to`，
   换出来的是**另一条记录**（字节变了，内容地址随之变，自指地址不跟着走）。

换算表**只登记纯长度量纲**：mm↔m、mm²↔m²、mm³↔m³、per_mm↔per_m。
`_n_mm2`（应力）、`_nmm`（力矩）、`_n_s_mm`（阻尼）这类复合量**故意没有登记**——
把N/mm²换到米制要先决定它是不是MPa，那是消费方采纳声明里的事，本面不猜因子，
碰上就报错并指路。这不是没做完，是把缺口摆在明面上而不是让它变成一个静默的乘数。

米制记录会用到轴2基础单位集里没有的后缀（`m2`/`m3`/`per_m`），
按`identity.py`明写的"调用方可传补充集"路径以`METRE_SYSTEM_UNITS`补入；
基础集一个不删。

## 六、最低红例集（六条，门必须红过）

1. **无单位裸量进记录** → 拒（轴2规则3）；
2. **属性声明的域不在记录的`applicable_domains`里** → 拒（规则1）；
3. **同一条记录混用mm制与米制字段** → 拒（规则5，静默1000倍的入口）；
4. **自指内容哈希被篡改** → 拒（轴3规则4）；
5. **被锁定的记录字节改一个字节** → 拒，且拒在解析之前（轴3规则1）；
6. **分级`unset`的属性却带着值** → 拒（规则4，占位零是伪装的声明）。

参考实现另有十一条失败关闭（无`method`的证据、外部分级缺源哈希、未知分级、
非unset却无值、ID不在`material`命名空间、面版本未登记、未知顶层键、
无量纲清单登记幽灵字段、读未声明的域、跨制读取未显式换算、
复合量纲无登记换算），逐条有测试。

## 七、明确不做的

- **不做材料数据库**。本面定的是记录形制与校验，不是厂家数据。
  研究候选与网页来源留在消费方（WDS `docs/research/materials/`是正本），
  本仓不进材料实体。
- **不做本构模型选择**。WDS的`constitutive_model`、`failure_model`、
  `plasticity`是力学域的契约，不是聚合记录的通用字段——聚合记录只承诺
  "把带单位带证据的量放在一起并按域分发"，本构归各域求解器。
- **不做单位换算引擎**。第五节的换算表刻意只覆盖纯长度量纲；
  通用量纲代数是将来契约基座（Quantity类型）的事，不在本面预支。
- **不做外观渲染参数**。只带内容锁定的外观资产引用（spec/01 appearance格：
  外观是资产属性不是渲染实现）。
