状态：**已冻结**（决策记录[0004](../decisions/0004_冻结轴2_20260804.md)）。
版本语义按[轴1](02_轴1_分面版本冻结制_v1.md)。

与轴1同法：五条规则全部蒸馏自两个创始消费方的已验证实践，不含发明。
证据：WDS design/15（四段案例身份+vNNN、材料ID含证据段）、`contracts/versions.py`

## 一、五条规则

1. **实体ID稳定且带身份结构**。命名空间前缀（`material/...`、`scenario/...`）
   或冻结的分段形制（`family__variant__subject__context__vNNN`）二选一；
   分段语义必须在对应契约中冻结。**ID是身份不是路径**——文件可以搬家，ID不动。
2. **物理输入变更即新版本，旧ID永不改写**。只增不改：一个ID一旦被运行或验收
   引用过，任何物理语义变化都建下一个`vNNN`，不原地编辑。
3. **物理量跨边界必须带单位**。机制二选一：字段名单位后缀（`*_mm`、`*_N`、
   `*_N_mm2`、`*_s`）或带单位的量类型（Quantity）。**裸float不得跨边界**——
   仓内内核可以裸（性能），出契约必须穿衣服。
4. **数量与拓扑是数据不是代码假设**。组件数、通道数、轮子数、接触体数都来自
   声明；代码里出现"恰好一个/恰好两个"的假设即为缺陷候选，须登记收敛计划。
5. **声明性输入携带证据边界**。参数从哪来（实测/厂商推导/文献/拍的）、
   适用域到哪、失败模型是什么，随记录走；**"无出处可追"也必须显式写出**，
   不许留空装有。（实例：WDS材料ID的`vendor_derived`证据段+适用域声明；
   FTS的AssertionRecord与explicit-unknowns证据文件。）

## 二、验收判据（门必须红过）

- 无单位裸量进契约：契约校验必须拒收（造一例验红）。
- 复用旧`vNNN`装新物理：绑指纹/哈希门必须红（两仓均已有此门）。
- 硬编码数量：无法全自动判，列为**评审判据**；已知实例必须登记在采纳台账
  并挂收敛计划，不许沉默。
