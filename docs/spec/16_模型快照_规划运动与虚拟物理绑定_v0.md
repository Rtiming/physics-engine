# 模型快照、规划运动与虚拟物理绑定（v0.1草案）

日期：2026-08-20
状态：**草案，P3.0输入合同与P3.1 static/kinematic场景装配首片已落地；dynamic、WII真实适配和第二消费方尚未完成，因此不冻结。**

裁决正本：[0099](../decisions/0099_模型快照_规划运动与虚拟物理绑定归本仓_WII后适配_20260820.md)。

## 一、目标与边界

physics-engine只定义自己需要的输入，不复制WII、GCW或任何CAD工具的私有schema：

```text
ModelSnapshot
+ PlannedMotion
+ ModelPhysicsRelation
→ PhysicsModelMotionInput
→ 物理场景装配
```

外部项目通过adapter生成本合同。当前首个明确适配方是WII；模型可以来自WII资产库、CAD导出、
人工包或GCW等任意生产者。生产者名称只进入`producer_id`与源SHA，不进入求解分支。

本合同不读取网格字节、不做IK/FK、不做路径搜索，也不声明模型已经适合物理。它解决的是：

1. 哪些模型字节存在；
2. 哪些对象怎样运动；
3. 哪个模型组件进入哪个虚拟物理体或虚拟工艺frame；
4. 哪些模型组件被明确排除，而不是被静默漏掉。

P3.1的`scene_resources`/`model_scene`是合同的第一个本仓消费方：它们另行重读资产字节、
接形状记录并装配Scene。输入合同本身仍然不承担网格IO，两层边界不合并。

## 二、ModelSnapshot

### 2.1 模型身份

`ModelSnapshot`包含：

| 字段 | 语义 |
|---|---|
| `model_id` | 本快照稳定身份 |
| `root_frame_id` | 所有根组件和运动track共同父frame |
| `producer_id` | adapter/生产者身份，只作溯源 |
| `source_manifest_sha256` | 适配前模型清单或源声明的精确SHA |
| `components` | 组件ID、显式component frame ID、层级、参考位姿和资产引用 |
| `content_sha256` | 规范化快照内容地址 |

一个快照可有多个根组件；父组件必须存在且层级无环。组件ID、component frame ID和资产ID
在快照内各自唯一。`parent_from_component`的child端就是该组件的`frame_id`，不是由名字猜的隐式frame。

### 2.2 资产引用

`ModelAssetRef`固定保留：

- `visual`或`collision`角色；
- 包内相对POSIX路径，禁止绝对路径、盘符、URI、反斜杠和`..`逃逸；
- 精确SHA-256、格式、单位、资产frame；
- `component_from_asset`显式刚体变换。

进入本合同前，长度统一归一化到mm。单位换算属于adapter边界，不在物理热路径进行。

visual与collision是两个独立槽。没有collision资产时，visual永远不自动回退为collision；若两者
确实引用同一字节，也必须各自以明确角色声明。

## 三、PlannedMotion

### 3.1 两种参数化

| 参数化 | 坐标单位 | 可用于什么 |
|---|---|---|
| `time_s` | `s` | 可转成`SampledPoseTimeline`，进入动态边界和采样/时延 |
| `planning_scale` | `1` | 只作准静态逐点/逐段规划；不能冒充物理秒 |

两类坐标都从0开始并严格递增。`planning_scale`必须在1结束。每个样点另带0—1的
`path_progress`，允许同一铺放进度上继续改变构型，所以它只要求不减，不要求严格增加。

### 3.2 track、源状态与送带

运动计划包含：

- 一个或多个绝对根frame下的motion track；
- 每条track自己的frame和五项显式插值语义；
- 源状态坐标声明与逐样点值，例如A1—A5、E1；physics-engine保留但不重算其运动学；
- `material_feed_length_mm`，从0开始且不减；
- `stage_id`；
- 至少一条源产物身份，包括role、artifact ID和SHA；
- 可选时间暂停区间；无时间计划禁止携带时间暂停。

每个样点必须给出全部track，不能在中途漏掉一个运动体。`as_time_source(track_id)`只接受
`time_s`计划；对`planning_scale`调用时明确失败，错误消息说明它没有physical time。

带`component_id`的track还必须满足`track.frame_id == component.frame_id`。否则`parent_from_track`
到底是组件位姿还是某个工具/载具位姿无法判定，装配必须失败，不由adapter或Scene猜一个。

## 四、ModelPhysicsRelation

### 4.1 三种物理体所有权

| behavior | 状态所有者 | motion track |
|---|---|---|
| `static` | 无状态，场景固定 | 禁止 |
| `kinematic` | 外部规划运动 | 必须 |
| `dynamic` | physics-engine状态/积分器 | 禁止 |

dynamic体还必须显式给出材料记录和质量属性身份。一个体不能同时由WII轨迹驱动又由物理求解器
积分；这不是数值选择，而是状态只能有一个所有者。

### 4.2 几何来源

物理体几何只有两条路：

1. `collision_asset`：组件必须真的声明collision资产；
2. `analytic_shape`：必须给出physics-engine shape ID。

没有“visual fallback”。绑定到不存在collision资产的visual-only组件会失败关闭。

### 4.3 虚拟frame与明确排除

process frame、tape-exit frame或传感器frame不一定是刚体。`VirtualFrameBinding`把这类track
绑定到有角色的虚拟frame，不给它伪造质量或碰撞体。

每个模型组件必须二选一：进入一个物理体，或进入`excluded_component_ids`。每条motion track
也必须三选一：由一个kinematic体消费、由虚拟frame消费，或进入
`excluded_motion_track_ids`。第三条专用于保留机器人/载具等显示运动而不让它进入物理；
它若绑定模型组件，该组件也必须被明确排除。同一track不能既被物理消费又被排除。

## 五、跨边界输入包

唯一外层facet：

```text
physics_model_motion_input / 0.1
```

外层嵌入模型、运动和关系三份内容寻址文档，并记录EvidenceRef。关系必须引用嵌入模型和运动的
精确内容SHA；外层再对整包计算SHA。严格reader按顺序执行：

1. 严格JSON、精确键集、facet版本和外层哈希；
2. 重建并复核模型组件/资产/层级与模型SHA；
3. 重建并复核运动track/样点/源产物与运动SHA；
4. 重建关系并复核关系SHA；
5. 检查root frame、组件、track、显式排除、geometry和状态所有权闭包；
6. 检查整包资格固定为`hypothesis_only`。

`EvidenceRef`只说明模型尺寸、adapter变换或规划产物的来源证据。本facet承载的是
`PlannedMotion`，即使部分模型已实测，也不能把整包升格为`calibrated_model`。实际运动测量/
状态回放将来必须用独立版本或facet，不能伪装成规划。

只改排除列表、绑定关系或派生SHA再重算外层哈希，仍会在所有权闭包处被拒。

## 六、WII适配规则

WII以后只需实现adapter，不修改本仓合同：

1. 模型清单、选中工件/场景资产与安装变换→`ModelSnapshot`；
2. time-based official timeline→`PlannedMotion(time_s)`；
3. 当前无时间新算法的已接受路径→`PlannedMotion(planning_scale)`，不得把ξ或τ填入秒；
4. workpiece/carrier等moving component→kinematic body；
5. process frame→virtual frame；
6. WII源run、模型manifest、运动学、selected plan等SHA→`source_artifacts`；
7. 模型快照SHA与运动计划中引用的模型身份必须由adapter交叉核对。

`source_bundle_id`、GCW bundle或其它上游包名可以由WII保存在自己的provenance里，但本合同没有
GCW专用字段，也不按它们分支。GCW不在physics-engine运行时调用链中。

## 六之一、P3.1本仓场景装配

P3.1不改本facet字节，只增加进程内消费层：

1. `pose_math`组合组件层级与`component_from_asset/shape`；
2. `scene_resources`从包根重读collision资产字节/SHA，同时要求显式AABB、凸性和保守方向；
3. `model_scene`按绑定声明顺序装static/kinematic体、虚拟frame和调用方显式给出的接触/允许对；
4. `time_s`计划进`MotionSource`；`planning_scale`只能经无量纲采样API；
5. 候选对直接进既有`BroadPhaseCollisionQuery`，不自动全体两两生成。

dynamic本片失败关闭：在状态position是组件原点还是质心、质心在哪个frame、初始位姿如何交给积分器三件事
冻结前，不得把dynamic当static装进Scene。

## 七、已知限制

1. 没有WII真实adapter和official产物，本批只验证合成输入。
2. 不读取资产字节，故不证明SHA对应的网格闭合、凸性或物理适用性；后续资产选择门负责。
3. P3.1已实例化static/kinematic `Scene`/`SimBody`，dynamic仍明确拒绝。
4. analytic shape当前只保存shape ID，没有把shape文档嵌入输入包。
5. 模型材料与质量属性只到ID；真实记录由materials/geometry层复读。
6. R1真实离带切点、活动导轮和现场标定不由模型快照自动推断。
7. 没有第二消费方评审，因此facet保持draft。

## 八、验收标准

- visual冒充collision必须红；
- dynamic体带motion track必须红；
- kinematic体缺track必须红；
- 未绑定/未排除组件必须红；
- 未消费motion track必须红；
- 同一motion track既被物理消费又被排除必须红；
- component motion track的frame与component frame不同必须红；
- 无时间计划转物理时间必须红；
- 实测级外层证据不得把规划运动升格为已标定物理；
- 改关系后重算所有哈希仍须因所有权不闭合而红；
- time-based中点位姿对独立线性/SLERP闭式；
- 100份严格复读保持交互级；
- WII/GCW/WDS本批零改动。
- 改动资产字节后重用旧SHA必须红；
- 缺资源、visual资源或资产安装变换丢失必须红；
- dynamic被静默冻结成static必须红；
- 显式一对候选必须以一对进CollisionQuery，不得自动平方扩张。
