## 一、场景装配 `Scene`

**解决"要算什么"与"怎么算"的分离。** 四家同行（PyElastica/Chrono/SOFA/libuipc）
与FTS收敛出的同一形状：

1. 场景是带类型的系统容器：组件/端口/连接用稳定版本化ID声明（FTS聚合根形制）；
2. 交互**按对声明**，不设全局表：`declare_contact_between(A, B)`只记账；
3. **延迟实例化**：组装期只登记，`finalize()`统一实例化并做类型校验——
   整个场景在跑第一步之前被完整校验，配错当场炸（PyElastica形制）；
4. 数量与拓扑全部来自声明（轴2规则4）；
5. 物理律是可换组件，与几何分离（libuipc的Geometry/Constitution正交）。

首个落地候选：WDS design/23的多体接触方案（`penalty_context`单数改元组）——
方案已定、故意未实施，等其第3段需求开工。

## 二、运动来源 `MotionSource`

**"路径从哪来"与"物理怎么算"解耦。** 外部只写位姿、不写力
（MuJoCo mocap形制）：

    pose_at(t_s) -> Pose
    horizon_s() -> float
    is_replayable() -> bool   # 不可重放的来源禁止进入需要确定性的运行

WII位姿时间线是第一个实现候选；解析轨迹是第二个；将来的控制器是第三个。
`is_replayable`与轴3规则5（复现指纹）联动：不可重放来源的运行不得声称指纹。

## 三、驱动器 `Actuator`

**把控制量变成物理作用。** 张力机放线端是第一个实现候选（WDS用途4）：

    command_space() -> Space
    apply(command, state, dt_s) -> ActuationResult
    delay_s() -> float

时延不是可选项——真实控制回路有延迟，没有时延训练出的策略上真机会翻车
（MuJoCo环形缓冲形制）。FTS侧对应物：`ComponentKind.ACTUATOR`（其scene.py:84），
参数经Quantity声明——两域的驱动器将来同名同义。

## 四、传感器 `Sensor`

    observation_space() -> Space
    read(state) -> ndarray
    delay_s() -> float

**硬约束：传感器只能读物理上真测得到的量。** 带材每个节点的精确位置不是
传感器——真机上没有这个量；把它塞进观测空间训练出的策略无法迁移。
这条要写成门（首个"必须红"用例：声明一个读全场状态的传感器，校验必须拒）。

## 五、碰撞查询 `CollisionQuery`

    check_path(source: MotionSource) -> tuple[CollisionEvent, ...]
    check_state() -> tuple[CollisionEvent, ...]     # 位姿在构造期冻结，见下

`CollisionEvent`至少带：发生在哪（弧长/时刻）、谁和谁、侵入多深、**可信度**。
可信度不是修饰——broad phase命中与narrow phase确认是两回事，混报即缺陷。
（WDS用途3；其上游只给路径，撞不撞由引擎判。）

**签名口径（决策0034）**：`check_state`**不收state参数**，位姿在查询对象构造时冻结。
理由不是「代码已经这么写了」，而是**构造期冻结对内容寻址更友好**——查询对象一旦构造，
它依据的位姿集合就固定，可被内容寻址（轴3）、可进run package、可声称指纹。
若收state参数，「这次查询依据哪一份位姿」就成了调用方的记账义务，而记账义务下放给调用方
正是本仓一贯要避免的事。代价如实说：随时间推进反复查询要每帧重建查询对象；
体数上百且重建成为热点时按spec/13义务1（profile先行）另行评估增量更新，**那时才动签名**。

> **实现进度（v0.2，决策0009、0058）**：`collision.py`已有AABB broad phase和
> 球/胶囊族narrow phase；窄相事件带精确`penetration_mm`，其余形状仍诚实保留
> `confidence="broad_phase"`与空穿透。查询可接有序候选池，并返回候选/broad/narrow
> 三段确定性计数。力学域`contact_pipeline.py`已把`FinalizedScene.contact_pairs`
> 作为稳定候选身份，每帧重建查询对象，且只让球-球narrow事件进入罚势与dashpot。
> 查询对象仍按本节内容寻址口径逐帧重建；0058只在对象内部复用每体窄相几何，并对
> 单位姿态AABB与球心使用逐值等价快路径，没有把可变state塞进`check_state()`签名。
> 解析平面、非球窄相、摩擦历史和`check_path`（沿MotionSource扫掠）尚未进入这条流水线。

## 六、步进契约 `Episode`

    reset(*, seed) -> (Obs, Info)
    step(action) -> (Obs, reward, terminated, truncated, Info)

形状对齐Gymnasium；`terminated`与`truncated`必须分开（RL自举算法靠此区分）。
**已摘出冻结前提（决策0034）**：本接口是登记在册的**未排期**接口。
数据集先行裁决（WDS design/24七之四）下，它等交互式环境需求真到来再实现，
而spec/10的冻结**不再等它**——把一个明确不做的接口挂在冻结前提里，
是拿一个永不满足的条件换一个永不到来的稳定。`reset(seed)`与轴3规则5联动。
