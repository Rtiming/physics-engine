# R25塑性history单站采纳计划（2026-08-16）

> 状态：执行计划，尚未形成实现、验收或发版证据。跨仓范围与阶段门以本页为准；
> WDS侧的文件级实施细节见其

## 零、结论先行

下一片不做“整根带材迁入引擎”，而做一个可证伪的最小闭环：在WDS新增命名案例中，
把R=25mm卷绕的一处**固定材料站点**交给`physics-engine 0.6.0`的64纤维理想弹塑性
easy-axis截面；Newton和线搜索期间只读已提交history，每个被WDS continuation接受的
平衡点提交一次候选history，被拒候选不得改变任何history。站点进入活动拓扑后保持同一
材料顶点身份，不再沿用线弹性v1“每个feed步重选活动段中点”的办法。

本片完成后允许声称：R25真实半径下，WDS有一处稳定材料站点真实消费引擎逐纤维塑性
history，并且提交、回滚、growth携带和结果回传有机器门。

本片完成后仍不允许声称：整杆塑性、多站迁移、真实商品批次定量精度、连续喂料极限、
snap过程中的真实塑性路径、轴向N、hard-axis、扭转、动态、压扁、翘曲、层合REBCO或
十几匝端到端已经完成。

## 一、为什么先不改physics-engine

只读核验表明，0.6.0已经公开提供本片所需的局部能力：

1. `ElasticPerfectlyPlastic1D`与`RectangularFiberSection`已经实现逐纤维理想弹塑性；
2. `evaluate_section_response`和`KirchhoffFiberSectionBending.trial_response`不修改输入
   history，而是返回`next_state`；
3. `KirchhoffSectionVertexLayout`可以把全局站点history投影成与参考标架无关的局部截面
   state，也可以把局部history装回当前站点布局；
4. 受保护的单站全局求解器已经证明“收敛才提交、失败保留旧提交态”，但WDS自己的全杆
   continuation尚未接这条提交语义。

因此第一执行点在WDS消费仓，不预支引擎新API，也不预设0.7.0发版。开工后的第一个探针
必须证明上述公开API足以在WDS侧完成局部history携带；若探针失败，立即停止消费侧扩写，
先在本仓建立新决策记录，说明缺失的公开能力、兼容面和必须红用例。只有确需修改引擎
源码时才进入0.7.0候选；0.6.0的tag、wheel和已发布字节保持不可变。

|---|---|---|

| trial与committed history的语义 | physics-engine | 保持“输入不变、显式返回next state” |
| 材料站点身份、feed/growth拓扑 | WDS | 绑定固定名义材料顶点，控制启用时机 |
| continuation接受、拒绝、二分与snap分支 | WDS | 成为唯一提交权限方 |
| WDS全杆Newton、接触、摩擦、stretch、hard-axis、扭转 | WDS | 不迁移；既有路径保持原所有权 |
| 新案例、插件、运行产物与history回执 | WDS | 新身份出生，不原地改变1.0/1.1案例 |
| 消费方登记与版本事实 | physics-engine | WDS验收闭合后更新，不提前报完成 |

若两页文字冲突，冻结spec与决策记录优先于本计划，本计划优先于WDS文件级任务表；发现
冲突时先修计划，不允许由代码静默裁决。

## 三、开工前必须冻结的五条语义

### 3.1 固定材料站点，不用移动中点冒充history

线弹性v1每个feed步按当前活动节点数重选中央内顶点。线弹性没有演化history，这样重建
只是在不同位置做一次无状态求值。塑性不能照搬：活动段中点从一个材料顶点移动到下一个
时，把旧history带过去等于把一块材料的塑性应变交给另一块材料；不带过去则每个站点都
永远从初始态开始，history闭环同样不存在。

新案例必须在输入闭包中钉死一个名义材料顶点索引。该顶点尚未成为活动内顶点前，全部
站点走WDS原线弹性路径；它具备左右两条活动边后建立零history；此后每个feed步仍使用
同一索引。growth只允许在尾部追加节点，既有前缀索引不得改名。任何站点重编号、删除、
历史跨索引转移或以“最近中点”替换固定身份都必须失败关闭。

### 3.2 history与运输gauge分离

持久对象保存局部截面state，而不是保存某一次WDS参考标架下的完整Kirchhoff全局state。
局部state只承载稳定点序中的塑性应变和累积塑性应变；每次求值再用当前WDS位置、gamma、
预应变参考和重运输后的d1/d2建立临时全局布局，并把已提交局部history装入。

允许变化的只有已声明的每步预应变变换和d1/d2与gamma成对重运输。材料顶点索引、截面
几何、求积规则、点数、材料模型、屈服应力、名义自然曲率与名义静止边身份均须绑定。
非声明漂移不得通过“重建站点”洗掉。

### 3.3 continuation接受点是唯一commit权限

一次候选求解的生命周期固定为：

```text
已提交state/reference/friction/section history
  -> Newton与线搜索反复trial，只读同一份committed history
  -> 候选不收敛：丢弃候选history
  -> 候选收敛：计算candidate history
  -> 先在临时变量中完成friction提交、history提交和reference重运输
  -> 全部成功后一次替换四份已提交对象
```

原`_accept`要改成事务式更新：所有候选对象先构造完，再统一赋给`current`、`reference`、
`friction`与station history，避免后一步抛错后留下半提交状态。二分产生并被接受的中点是
真实接受点，应提交且成为下一小段起点；原目标被拒时只回滚原目标候选，不回滚已经接受
的中点。一个feed步最终失败时立即停止新塑性路径，不得继续增长拓扑并发布收敛结果。

### 3.4 不混合两套不等价的塑性

WDS原生塑性把残余set写入全杆`RodReference.natural_kappa1`；引擎塑性保存逐纤维塑性
应变与累积塑性应变。两者不能相互翻译，也不能在目标站点叠加。

新引擎塑性案例中，WDS的`bending_plasticity`必须为`None`。目标站点的原生easy-axis
弹性项仍按现有接缝显式减去，再加入引擎弹塑性项；其余站点的easy-axis以及全杆
hard-axis仍走WDS原生**线弹性**。这是一处塑性站点的采纳门，不是整杆塑性案例。

### 3.5 snap_relaxation单独过门

严格准静态continuation先行。现有`snap_relaxation`是为跨折叠使用的伪动力算法，而引擎
截面共享项明确声明`supports_dynamics=False`。更关键的是，若只在伪动力终点做一次
return-map，就没有记录snap路径中可能出现的塑性峰值。

因此新引擎塑性模式初始必须拒绝`snap_relaxation`。完成固定站点与准静态提交后，对R25
案例实测是否遇到折叠：

- 不需要snap：继续准静态验收；
- 必须snap：停止在物理裁决门，另立决策选择“仅终点history的算法近似”或“沿伪动力
  路径增量提交”。未裁决前不得沿用WDS原生塑性案例的开关，也不得把终点近似写成真实
  瞬态塑性。

## 四、输入与产物身份

以下名称是开工决策的拟冻结值；实现前由WDS契约测试把它们钉死：

| 对象 | 拟定身份 |
|---|---|
| 输入契约 | `spool_wrap_case 1.2.0` |
| scenario kind | `spool_wrap_quasi_static_engine_plastic_section` |
| plugin | `scenario/spool-wrap-quasi-static-engine-plastic-section` |
| bending model | `physics_engine_elastoplastic_single_station_v1` |
| 新案例 | 由现有R25 `ep10n v001`派生新的只增不改版本 |
| 站点选择 | 输入显式给出`material_vertex_index`，64点求积由模型版本固定 |
| history产物 | 独立`engine_section_history.json`回执，不改写既有result 1.0字节 |

history回执至少包含：案例与运行身份、固定材料顶点索引、名义弧长位置、截面与求积规则
指纹、材料模型和参数来源、点数、最终逐点塑性应变、最终累积塑性应变、接受提交次数、
最终history内容哈希以及“单站、假设材料、非整杆塑性”的限制。旧`SpoolWrapRunResult 1.0`
保持不变；新插件以伴随产物发布history，运行manifest继续负责文件哈希和原子发布。

材料记录里的屈服值仍是候选资料，不是该商品批次实测曲线。新案例必须保持
`hypothesis_only`，不能因引擎return-map更细就升级为实际机器证据。

## 五、实施波次

### 波次0｜红门与API充分性探针

1. 在WDS测试中用0.6.0公开API构造一个固定站点，加载、卸载并跨参考重运输；
2. 证明局部history能从旧评估布局提取并装入新评估布局，点序和数值逐位不变；
3. 先写“移动中点携带history必须红”“失败候选提交必须红”“旧history装入异截面必须红”；
4. 若任何一步必须访问引擎私有字段，停止并回本仓立新决策，不在消费仓复制实现。

### 波次1｜WDS并行塑性适配器

新增与线弹性v1并列的塑性站点对象，不把现有`EngineEasyAxisStation`原地扩成含糊的双模式。
新对象保存固定材料身份、`ElasticPerfectlyPlastic1D`、矩形截面和局部committed state；
`quantities`保持纯求值，另提供接受点生成下一committed对象的显式入口。旧线弹性站点的
默认、类型限制、求值次序与案例字节保持不变。

### 波次2｜continuation事务式提交

在WDS自己的continuation内携带塑性站点对象，并将接受点的state、friction、reference与
section history作为一个事务更新。`RampResult`返回最后已提交站点；失败结果返回最后稳定
提交态用于诊断，但不得被runner发布成收敛结果。覆盖普通接受、Newton失败、目标拒绝、
二分中点、最终零tether和异常中止。

### 波次3｜growth与固定材料身份

feed开始时解析一次全长名义材料顶点。站点未激活时不接引擎；激活后从零history出生并
在所有后续feed步携带。append-only growth后重新求值当前gauge，但不更换材料索引、不
重置history。新塑性路径遇到不收敛feed步立即停止；既有原生与线弹性v1路径逐句保留。

### 波次4｜新契约、案例与history回执

建立1.2输入、新plugin身份、R25命名案例与伴随history回执。runner同时验证：目标站点
确实激活、至少一个纤维点发生屈服、累积塑性应变不减、最终history哈希与内存提交态一致。
若站点全程未屈服，该案例不能作为塑性采纳证据，应显式换一个已声明站点或改为受控失败，
不能只把测试阈值放宽。

### 波次5｜跨仓收口

WDS先完成定向门、既有案例双版本门、V1/V2/VA与性能门；随后本仓只做消费方登记、交接页
和CHANGELOG事实更新。若0.6.0源码无需变化，不构建新wheel、不打新tag；若确需引擎改动，
则按本仓完整发版门走0.7.0，并让WDS重新绑定新wheel的SHA与RECORD字节。

## 六、验收矩阵

| 编号 | 必须证明 | 必须红的错误注入 |
|---|---|---|
| H1 | 同一材料顶点跨多个feed步保持同一身份 | 恢复`active//2`移动选择器 |
| H2 | energy/gradient/Hessian重复求值不改变committed history | 在`quantities`内写回trial history |
| H3 | 收敛候选恰提交一次 | 同一接受点提交两次 |
| H4 | Newton失败、线搜索拒绝和目标拒绝均不提交 | 将最后trial当committed返回 |
| H5 | 二分中点接受后提交，后半段从该提交态继续 | 对整个原目标做错误的全量回滚 |
| H6 | d1/d2与gamma成对重运输前后曲率、响应和history一致 | 只换reference不换gamma |
| H7 | growth只追加拓扑，旧站点history逐位保留 | append后重新建立零history |
| H8 | 异顶点、异截面、异点数、异材料或静态参考漂移失败关闭 | 只按向量长度接受旧history |
| H9 | 目标站点由WDS native easy减项加引擎项，其余物理所有权不变 | 同时启用WDS原生塑性 |
| H10 | 加载—卸载的逐点应力、弯矩、切线与残余history对独立oracle | 只检验“出现非零值” |
| H11 | 相同终态几何、不同加载路径可得到不同history | 每次从virgin state重算 |
| H12 | 15个既有案例按各自既有状态逐例一致 | 原地修改1.0/1.1身份或旧结果schema |
| H13 | history回执严格复读、哈希自洽且与最终内存态一致 | 改一个纤维值但不改manifest |
| H14 | 未裁决snap时失败关闭 | 让塑性站点静默进入`snap_relaxation` |

梯度与Hessian差分点必须避开恰好屈服的不可微切换点；屈服点本身用分支、力界和一致切线
语义检查，不用一个不成立的中心差分门冒充验证。

## 七、批末与交付门

### 7.1 physics-engine未改源码时

1. WDS定向塑性history门全部绿；
2. WDS 15个既有案例逐例兼容，新R25案例单独记账；
3. WDS `verify_project.py general`、`standard_full`与`actual_validation`按分层执行；
4. 新路径做本机profile，记录64点单站给每次Newton装配增加的时间与内存；
5. master隔离环境安装现有正式0.6.0 wheel，以绑定SHA验证消费方；
6. 本仓更新消费方登记和交接事实，不运行release.py。

### 7.2 physics-engine确需改源码时

1. 新决策记录说明为什么0.6.0公开API不够；
2. 引擎新门先红，再做最小API；
3. `.venv/bin/python tools/accept.py full`与可移植性检查通过；
4. WDS以候选wheel完成独立采纳门；
5. 取得用户发版授权后才运行`tools/release.py`，版本为0.7.0或当时合法的新版本；
6. WDS重新绑定正式wheel，重跑全部消费门。

## 八、停止条件与完成定义

出现下列任一情况立即停在裁决门，不继续堆代码：

1. 固定材料站点无法在现有append-only growth中保持身份；
2. rejected candidate会通过任一路径改变history；
3. R25必须依赖snap，而snap塑性路径尚未裁决；
4. 候选材料参数被误写成商品批次实测值；
5. 旧15案任一身份、解析字节或既有物理指纹发生无解释漂移；
6. 为接单站而被迫预建多站网格、N/M或动态框架。

本片只有同时满足“固定材料身份、接受点事务提交、拒绝回滚、growth携带、独立物理oracle、
history伴随产物、旧案例兼容、分层验收”八项才算完成。只让R25案例跑出一个数，或只看到
非零塑性应变，都不算完成。
