# 子系统补充计划（2026-08-06立，正本）

本页回答用户的问题："**缺的那些系统——积分系统、网格系统之类——该怎么补？**"

依据是**五份**并行调研（时间积分、网格与几何、场求解与跨域耦合、同行碰撞库、恢复系数与辛-接触），
**全部要求实测优先于推断**。下面凡是数，都标了是**本仓实测**、**代理实测**
还是**同行出处**；凡是没核实的，标"未核实"。

## 零、这四份调研改掉了什么——先说被推翻的

**一份计划的价值，先看它推翻了什么。** 这五份推翻了六条我们原本写在仓里的话——
**其中最后一条推翻的是本页自己的初稿**：

## 一、三个子系统今天的真实位置

### 1.1 时间积分：**已经通了，只是没被声明**

五个积分器（三个平动+两个刚体），`production_ready`全为`False`，五项出生声明有门守着。

**本仓实测**：用现成件（`UniformGravity` + `PenaltyNormalContact` + `acceleration`桥 +
`velocity_verlet`）直接跑弹跳球**跑通了**，且闭式对得住：

| 量 | 闭式 | 实测（k跨五档） |
|---|---|---|
| 接触时长 | `t_c = π/ω`，`ω = sqrt(1000k/m)` | 比值0.9995—1.0011 |
| 最大穿透 | `δ_max = v_in/ω` | 比值1.0000—1.0010 |
| 恢复系数（无阻尼） | `e = 1` | 偏差1.9e-06—5.3e-06 |

**缺的不是子系统，是阻尼**。而阻尼不能单独加——见1.4。

### 1.2 网格与几何：**三条缝，接触的几何被各自硬写**

**本仓实测的依赖图**：

```
contact  → energies, state        ← 不import shapes/collision/scene/rigidbody
scene    → shapes, motion, ...    ← 不import collision/contact/energies/solve
collision→ shapes
rigidbody→ energies, geometry, integrate, shapes, state
```

后果三条：
1. **`FinalizedScene.contact_pairs`造出来了，下游一个消费方都没有**；
2. 接触的几何是**每个能量项各自硬写的裸元组**（`PenaltySphereContact`吃的"半径之和"
   是个裸float，不是`Sphere`）——research/11点名的"四个能量项各自带一套硬写的离散"
   **正在接触层重演**；
3. **`shapes.py`里`Plane`是0个**，而spec/11规则2明文点了它——半空间住在`contact.py`的
   裸元组里，**规范点了名、实现没有，于是几何长出了第二套**。

### 1.3 场求解与耦合：**两个域全是标量求值，零离散未知量**

**代理实测**：光学与电磁两域共76个签名，**69个返回`float`，没有一个返回数组**；
`grep complex|fft|numpy|mesh|grid` 在源码里**零命中**（只命中文档里的负空间声明）；
全域只有8处`for`，全是级数或AGM的项循环，**没有一处是网格遍历**。

`couplings/`目录不存在。**代理实测**：在真实包的临时拷贝里造一个耦合模块，
六条域隔离门**全绿**——建目录不用改任何门。

**但完备性门对它是空的**（我复核确认）：`ring_of`对`couplings.*`是**纯前缀匹配**，
连不存在的模块名都自动归位。spec/15第三节规则5"每个模块都必须登记"
**对耦合子模块事实上不成立**。

### 1.4 三条会咬人的物理事实（全是实测，不是推断）

**(a) 稳定界`h < 2/ω_max`是必要而远远不够。** 代理实测同一次撞击：

| 步/接触 | `dt/(2/ω)` | 实测`e`（理论1） | 偏差 |
|---|---|---|---|
| 2 | 0.785 | 1.1433 | **14.3%** |
| 20 | 0.0785 | 0.99984 | 1.6e-4 |
| 40 | 0.0393 | 0.99999 | 8.0e-6 |

**在声明的界内侧0.785倍处，恢复系数已经错14%。** 而O'Sullivan & Bray 2004的
`Δt ≤ 0.17·sqrt(m/K)`换算过来是约18.5步/接触——**同行经验数与本仓实测落在同一格**。

**(b) 加dashpot不是一行代码。** `velocity_verlet`在速度相关力下**掉到一阶**
（**本仓实测**：无阻尼2.0000、ζ=0.1时0.41→0.95）。病根在`_velocity_verlet_step`
拿旧速度算新时刻的加速度——**积分器的声明里早就诚实写了这一条，本轮把它测成了数**。
所以阻尼要连带一个能吃速度相关力还保住二阶的积分步，**那是积分器变更，要走五项声明**。

**(c) 纯Python在3维小向量上用NumPy是净亏损。** 代理实测：`np.cross`三元素
**8.45 µs**、纯Python元组版**118 ns**——**慢72倍**。`accel`档要么批量化到
所有pair一起算，要么就是负优化。

### 1.5 恢复系数的闭式有**两个**，取哪个是一次裁决不是一次抄写

`e = exp(−ζπ/sqrt(1−ζ²))`（`ζ = c/(2·sqrt(m_eff·k))`）**只在"接触结束 = 重叠归零"
这个约定下精确**。本仓实测在该约定下确实精确（四档ζ，最细档偏差2.9e-5—1.1e-3）。

**但那个约定本身被同行质疑过**：Schwager & Pöschel（*Granular Matter* 2007，
"Coefficient of restitution and linear dashpot model revisited"）指出，
在重叠归零那一瞬**阻尼项让合力变成拉力**，因而这个广为使用的式子
"**因为碰撞时长定义错误而定性地不正确**"。他们把判据换成**力归零**，
得到分段的闭式；低阻尼分支是

    e = exp[ −(ζ/sqrt(1−ζ²))·(π − 2·arcsin ζ) ]

**临界阻尼下它给`e = exp(−2) ≈ 0.135`，而不是0**——这是定性的分歧，不是精度差别。

**两条都在生产代码里**：LIGGGHTS的`limitForce`与LAMMPS的`limit_damping`都提供力截断，
**而两家都警告截断会破坏标定**——LIGGGHTS原文："使用`limitForce`时，
声明的恢复系数只是近似的。**对低恢复系数这会变成问题**，如Schwager与Pöschel所示"；
不截断则"可能导致颗粒与壁面之间出现吸引力"。

**对本仓的含义**：阶段2的第1档判据**必须先声明用哪个约定**。
两条都对，**钉错了会把一个正确实现判红**。这条已在阶段2的"先裁"里，
本节给它补上出处与另一条闭式。

**顺带一条对本仓有用的**：生产代码实际实现的是**反解式**——
给定目标`e`求阻尼系数：

    c = 2·sqrt(m_eff·k)·(−ln e)/sqrt(π² + ln²e)

LAMMPS `pair_granular`、Chrono `ChContactSMC.cpp`、EDEM线性弹簧**三家逐字相同**
（源出Schäfer/Dippel/Wolf 1996）。**阶段2该实现的是这一式，不是正解式**——
使用者声明的是`e`，不是`ζ`。

### 1.6 罚接触加显式积分**会涨能量**，这是有文献的

Acary（*ZAMM* 2016）摘要原文："**直接套用Newmark或generalized-α这类标准格式
会导致能量爆炸**"。另有基准实测：罚法的能量误差在1e-5—1e-7处形成平台
（**刚度越大越差**），而非光滑格式是约1e-12且**与步长无关**——差约七个数量级。

**这条把"引擎自己报耗散"从欠账升成必需**：一个会静默涨能量的路径，
如果连"这一步的能量是多少"都只有案例自己去梯形积分，
**那么涨了也没人看得见**。

**另一条要写进积分器声明的**：向后误差分析要的是**解析性**不只是光滑性。
线性罚势是`C¹`（力`C⁰`），Hertz势是`C²`（力`C¹`）——
**线性罚对积分器的阶严格更差**。Tao & Jin（2021）对不连续势明说
"**辛性是否还带来好的长时间表现已不清楚**"，并推荐他们那个**非辛**的可逆自适应方法。

两份报告的纯Python GJK实测**差76倍**：

## 三、同行的三条共同分母（抄这三条，不抄具体算法）

**(a) 没有一家只用一个通用算法。** 解析特例数：MuJoCo 11、FCL 22、Chrono 12、
Bullet默认6。闭式在Python里是几十纳秒，通用算法是几百微秒——**差三到四个数量级**。
本仓球/胶囊闭式（**本仓实测1.24 µs**）已经在这条路上。

**(b) 受约束的架构会放弃通用凸-凸。** **MJX（MuJoCo的JAX版）里根本没有GJK/EPA**，
它用无分支SAT + Gauss map + Sutherland-Hodgman裁剪 + 固定4点最大面积归约，
**每个碰撞器的接触点数在编译期固定**。这是与本仓（纯Python、要能批量化）
最贴合的先例。

**(c) 耦合的调度与耦合的物理必须分开。** COMSOL用"建模面/求解面正交"、
preCICE用"库不解物理"、MOOSE用"MultiApp与Kernels分家"、Abaqus用"CSE配置文件"——
四家形态不同，**分界线是同一条**。

## 四、两条矛盾的裁决

### 裁决一：耦合缺口的判据——**分两步，不合并**

spec/15第七节冻结条件1要"**形制被走过一遍**"（哪怕单向链）；
plans/06第五节要"**物理上真是耦合**"（双向）。**两者都对，但它们是两个目标。**

**裁**：拆成两个判据，各自独立。

- **形制判据**（spec/15冻结条件1）：`couplings/`落地过一次，第四节四条进仓条件
  被走过一遍。**单向链算数。**
- **能力判据**（plans/06第五节）：一个**双向**耦合案例。**单向不算数。**

**理由**：合并的后果是"建目录、定声明形制、上门"这三件形制工作，
和双向强耦合的物理难点，全挤进一个批次。**这两件事失败的方式完全不同**——
前者失败是形制没定好，后者失败是物理没算对。

**plans/06第五节那句"单向的不算"要加限定**：它说的是**能力判据**，不是形制判据。

### 裁决二：`max_points_per_pair`的分母——**改成自由度种类**

0050第一节把它挂在**形状族**上。**实测分母是自由度种类**：接触体是3自由度质点，
质点没有力矩，给一对分配4个锚点槽只会把切向刚度乘4，**不多算任何物理**。

同行的物理理由是同一条（MuJoCo文档原文）："通用凸-凸算法总是返回单点，
**这对面接触场景是有问题的**（如箱体堆叠）"，失败现象是"滑移或摇晃"。
根因是**单点接触不能对接触斑块产生任何约束力矩**。

**裁**：`max_points > 1`的前置是**接触体有转动自由度**，不是网格窄相。
0050第一节按此订正。**这条会改0050的承重条款，走独立决策记录。**

## 五、分阶段计划

**总排序原则**：**能让主分母（用户六场景端到端）动的优先**。
从分母（同行C档）涨过好几次而主分母一直是0/6——这一天反复指向同一件事。

### 阶段1｜把"瞬态罚接触"从既成事实变成被声明的能力

**做什么**：弹跳案例（C档第9条前半，无阻尼`e=1`）；给三个积分器的`step_bound`
补第二段（稳定界 + **接触分辨界**，今天写的`h < 2/ω_max`在0.785倍处就错14%）；
**步长顾问**——一个纯函数，把`step_bound`那个**字符串**字段变成**可计算的数**。

**判据**（全第1档，全部已实测）：`t_c = π/ω`、`δ_max = v_in/ω`、无阻尼`e=1`、
步数与`|e−1|`的单调表。

**必红**：把`δ_max`判据写成准静态的`N/k` → 刚度换一档必须红（**专防第零节那条口径混用**）。

**先裁**：步长顾问放哪个模块（`integrate.py`今天**不import包内任何东西**，
这条独立性有价值，破它要走决策）；`production_ready`要不要动
（建议先不动，但要把"凭什么全是False"从谦虚改成一句可核对的话，
否则它会变成永不翻的死字段）。

### 阶段2｜阻尼与耗散记账（C档第9条落地，6/13 → 7/13）

**做什么**：一条速度相关力的通路（`Acceleration`回调签名**已经收了`v`**，
只是桥忽略它）；一个能吃它还保住二阶的积分步；**引擎自己报耗散**
（plans/07登记的欠账——今天耗散靠案例去梯形积分）。

**判据**（全第1档，代理已实测）：`e`的闭式——**但先按第1.5节裁定用哪个约定**，
重叠归零约定下是`exp(−ζπ/sqrt(1−ζ²))`（四档ζ，最细档偏差2.9e-5—1.1e-3）；
`t_c = π/ω_d`；总弹跳时间`sqrt(2h/g)(1+e)/(1−e)`
（Physics LibreTexts有逐字出处，且弹跳次数无穷而总时间有限）；
`e`与入射速度无关（跨三个量级实测偏差恒定，**注意：带重力时这条不再成立**）；
**新积分步在阻尼下实测阶=2**（对照组是今天的1.005）。

**先裁三条**：耗散项进不进`EnergyRegistry`（进就破了"注册表里全是势能"这条不变量，
不进就要第二条装配路径，而装配是唯一的性能主战场）；换哪个积分步、旧的怎么办；
**LSD在分离瞬间的拉力截不截断**——见第1.5节，这条现在有出处也有第二条闭式，
**且两家生产代码都警告截断会破坏标定、低`e`时尤甚**。

**实现的是反解式**（给定`e`求`c`），不是正解式：使用者声明的是恢复系数。

### 阶段3｜场景③的可算版本（**主分母第一次动：0/6 → 1/6**）

**做什么**：平面围成的漏斗（半空间已有）+ 球落进去。**只用阶段1、2的零件。**

**必须提前申报的预算**：代理实测 k=1e4、m=1g、512粒子、20步/接触
→ **一个物理秒要2895秒（48分钟），服务器级**；64粒子也要399秒。
**"落漏斗"在纯Python核心上今天落在服务器级，这个数要进预算申报，不能等撞上。**

**而`accel`档在这条路上实测只值1.00—1.02倍**——`integrate.py`那条"加速档只向量化
积分器自己的算术、不管加速度回调"的诚实边界意味着99%的时间在边界之外。
**要让DEM跑得动必须把加速档边界移到能量装配上**，那是比加dashpot大得多的一件事。

### 阶段4｜截面积分点（"体积与厚度"第一步，**不是网格**）

**为什么不是网格**——三个实测数字：

| 构型 | 自由度 | 一次线性求解 |
|---|---|---|
| 今天（256节点链） | 768 | **10.6 ms** |
| 每站2×2截面网格 | 3072 | 286 ms（27×） |
| 每站4×4截面网格 | 12288 | **12.3 s（1157×）** |

而`solve.py`自己申报的上限是"交互级约200自由自由度、本机批级约1536"——
**4×4截面网格是那条上限的8倍，第一步就撞穿自己申报的天花板**。
截面积分点**不加自由度**（Abaqus原文：截面点是求积点），
只把装配乘个常数，而research/06实测装配里真正算物理的只占1.89%。

**判据现成**：plans/06给"体积与厚度"定的判据是"截面上的分布量有自由度、被解出来、
对住解析基准"，而`superconductor.sheet_current_density_a_per_m`**就是那条沿带宽的
截面分布**（Norris闭式，50位十进制参考，rel 1e-12，4条oracle在跑）。
**缺的只是让`K(x)`从"抄出来的"变成"解出来的"。**

**一条陷阱**：截面积分点对**线弹性是恒等变换**（EI就是EI）。
**第一条案例若做线弹性梁，会全绿而且什么都没验。** 必须做材料非线性
（超导幂律或塑性）或截面上有真实分布的问题。

### 阶段5｜光学FFT（C档第13条，6/13 → 7/13的另一条路）

**代理实测**：纯Python二维FFT，512²一次**322 ms**、1024²**1.49 s**，标度与N²logN一致；
**Parseval守恒3.6e-16、往返可逆1.6e-15**——**机器精度**，
意味着三件套里两件可按零容差量级立判据。

**先裁两条**：复数怎么落盘（**代理实测**复数今天过不了`oracles`/`canonical`/`State`
三道关，`ARRAY_DTYPES`只有float64/int64；建议实虚拆两条float64数组，**零面变更**，
但它定的是本仓所有复数量的约定）；场要不要登记面（倾向不要——
第13条三件套全是标量判据，但要**显式裁**，否则会像`cli.py`那样悄悄写一个未登记的面）。

**Mie可以先于FFT单独落地**（一维级数+复数递推，不需要网格不需要FFT），
判据是严格级数解 + 瑞利极限退化`Q_sca → (8/3)x⁴|(m²−1)/(m²+2)|²` + 消光佯谬`Q_ext → 2`。

### 阶段6｜`couplings/`第一个模块（形制批，单向链）

**做什么**：`couplings/lorentz_load.py`——载流圆环间的洛伦兹力 → 力学域端载荷。
**这是COMSOL明写的形制**（把电流感生的洛伦兹力作为体载荷施加），不是编的例子。

**判据（第1档链）**：同轴圆环轴向力`F = I1·I2·dM/dh`，`M`用已有Maxwell闭式、
`dM/dh`解析微分；与数值微分对拍（第2档）；远场退化到偶极；牛顿第三定律（零容差）；
下游接`PointLoad`（0046已验）。

**开工第一件事必须是验`dM/dh`的解析式**——代理明确标注它**未核实出处也未数值验证**，
而整条第1档判据建立在它上面。本仓已有的`complete_elliptic_k/e`与Neumann一维求积
就够验它。

**先裁**：本页第四节裁决一（形制判据vs能力判据）；`CircularLoop`要不要升进`shapes.py`
（0042登记的欠账，触发条件是"非电磁消费方需要圆形回路"——**耦合模块就是那个消费方，
开工即触发**）。

### 阶段7｜盒/凸包窄相 + 对拍面扩容

**代理实测的一条硬发现**：**FCL在圆柱上不可靠**（盒-圆柱径向分离最坏偏差3.56e-04，
1983组里9组>1e-6），而盒-盒是1.42e-14、球-圆柱7.11e-15。
**含义**：圆柱对**不许**用FCL做第3档判据（容差要放到1e-3才不误红，那时判据什么都不判），
必须走第1档闭式；**盒-盒与凸包-凸包在FCL上是机器精度的，第3档完全成立**。
这是仓内案例页已记两条FCL缺陷之外的**第三条**。

**另一条**：代理自己实现的GJK+EPA实测 **5937组里30组（0.51%）EPA静默返回0穿透**，
最坏真实穿透15.96 mm，**而布尔门全绿**。这与`peer_fcl_distance`第六节记的
"J1（数值）与J2（布尔）必须并列、不能互相顶替"**是同一个形态**。
**阶段7的必红用例就用它。**

**先裁**：`Plane`/`Halfspace`进形状层后，`PenaltyNormalContact`的裸元组要不要改成吃它
（改是对的——消灭第二套几何——但破实验档API）；EPA还是MPR
（**用数字裁不要用原则裁**：先量MPR的近似误差与罚刚度柔度误差谁大，
而后者本仓已实测是`O(1/k)`且收敛阶10.00/10.50）。

## 六、明确**不做**的三件

**(a) 隐式积分族——现在不做。** 三条实测理由：

1. **今天没有消费方**。隐式在杆梁上净收益95×—17877×（代理实测），
   但要**瞬态杆梁问题**才兑现。今天走完整条路的案例全是准静态梁，
   瞬态侧只有无接触的弹道与振子。**收益乘以零还是零。**
2. **接触上是负收益**。要`e`对就得分辨`t_c`（约20步/接触），无条件稳定买不到更大步长；
   而DEM式邻接的半带宽实测N=80时已是120，`2b+1 < m/3`全部失败 → 掉回稠密`O(m³)`，
   而0030实测交互级边界约200自由自由度。
3. 阶段2的收益更大更便宜。

**重开条件（四条任一）**：第一个瞬态杆梁的**书面**消费方需求；接触刚度被迫提到
`k ≈ 1e6 N/mm`（代理给的对照：160段悬臂的结构界3.12e-5 s与之同量级）；
准静态路径要穿过动态snap-through；多槽位同时迭代落地后仍不收敛且诊断指向惯性缺失。

**真到那天，第一个做Newmark平均加速度**（γ=1/2、β=1/4）：代理实测`ρ`到`Ω=1e4`
仍是1.000000、阶2.000、零算法耗散，**是唯一不需要在"稳定"与"守恒"之间先取舍的**；
且它是HHT-α在α=0的退化，第二块是参数化扩展而非第二套机械。

**(b) 自适应时间步——不做。** 四条理由，前两条是本仓自己的：
spec/12第4.3节已立法"步长二分是抢救不是收敛证据"（有WDS活标本）；
**轴3的复现纪律——自适应让轨迹依赖误差控制器的浮点比较，逐字节对拍当场作废**，
而那是进仓门。替代品是阶段1的步长顾问。

**(c) 通用四面体网格生成——不做。** TetGen是**44890行C++**（代理源码统计），
精确几何谓词单独4710行且是正确性地基；纯Python生态**没有可用实现**，
全是包C++。**便宜的那条是拉伸网格**：2D截面×层数，连通性靠索引偏移闭式给出，
**数百行**——而且Abaqus/COMSOL都明说扫掠网格在薄结构上**质量还更好**
（四面体算法会把长宽比往1上拉）。**它正是场景①⑤的几何。**

## 七、那条张力的裁法（plans/06第一节遗留）

张力：同行绕开HTS长细比的主流是T-A薄带与H-φ薄壳，**把厚度降维掉**，
而定位是"三维带厚度"。

**裁法：把"厚度"拆成两件事——它今天被混在一起。**

| | 几何厚度 | 厚度方向自由度 |
|---|---|---|
| 是什么 | 体在空间里真的占那么厚 | 场量沿厚度有分辨率 |
| 谁需要 | 场景⑤（匝叠匝、半径生长、接触在哪发生）、场景⑥（蹭边） | 场景①的某些工况 |
| 本仓今天 | **部分已有**（`modelgen.generate_spool`的半径生长就是层厚驱动的） | **零** |
| 同行降维掉的 | **不降**（T-A降的是场的分辨率，几何厚度仍在`δ`里） | **降** |

**"我们是三维带厚度的"这条定位，真正不可让的是第一列。** T-A把厚度收进`Je = J·δ`，
几何厚度并没有消失——它只是不再有自己的自由度。**这与用户定位不相抵。**

降维的收益是硬数（T-A review，500带线圈）：自由度56万→2万、时间1/128、误差<1%。
不可表示性也要写清楚：T-A里**面外电流分量不存在**，那不是精度问题是表示能力问题。

**通则（要走决策记录）**：任何一维被降维，**必须在案例页声明降的是哪一维、
长细比是多少、以及"什么时候必须退回全三维"的触发条件**。
仓里其实已经诚实地站过一次队——`cases/norris_thin_strip`第六节写着
"**不是'三维带厚度'的答案，反而是它的反面**"——**只是没人把它升成通则**。

**同行的实际答案不是二选一，是混合**（COMSOL原文：薄的区域用壳、某些位置更三维的
用实体，混合能显著减小模型）。**这正是research/12点名过的SOFA形制的另一个面**：
一个对象三套表示+映射。**降维与不降维不是形状层的二选一，是同一个体的两套表示+
一个映射**——而本仓今天`shapes`只有一套且`collision`直接吃它。
**那才是这条张力的真正落点，不是"要不要画厚度"。**
