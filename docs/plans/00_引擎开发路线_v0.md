## M-E1：契约与清册基座（第一批代码）

**内容**（全部是已冻结轴的参考实现，无发明）：

1. `physics_engine.facets`：面清册记录（名称、版本、状态frozen/internal/draft、
   已测minor上限）+失败关闭的读取端兼容检查——轴1参考实现，形制取
   WDS `assert_reader_compatible`加状态字段；
2. `physics_engine.canonical`：规范化JSON（参数显式声明）+严格解析
   （拒重复键/NaN/Inf）——轴3规则2的读写对；
3. `physics_engine.identity`：单位后缀校验、四段ID/命名空间ID解析、
   `vNNN`工具——轴2参考实现。

**自吃药**：同批建本仓自己的验收器（quick 30秒/full 120秒，轴6）、
规则6最低集元测试、以及每个模块的"必须红"用例。**引擎仓从第一批代码起
就吃自己冻结的药，不许例外。**

**消费方衔接**：WDS批次A按操作单**先在自己仓内实现**（避免过早引入跨仓
依赖的回执成本）；批次B切换为import本仓时，以"两实现输出逐字节一致"为
切换门。新项目（case2评估通过后）可直接用本仓。

## M-E2：溯源参考实现

原子发布原语（no-replace改名的跨平台封装：macOS `renamex_np`/Linux
`renameat2`/不支持即失败关闭）、严格复读器骨架（四点签名+初末目录签名）、
run package装配与生命周期校验——轴4/轴5参考实现。落地门：
用WDS的既有运行目录做只读回放对拍，复读判定与其`load_verified_case_run`
逐例一致。

## M-E3：场景装配与六接口首实现

跟第一个真实场景需求走，候选顺序：

1. `Scene`装配容器+按对声明+finalize校验（WDS design/23多体方案是首个
   落地场景，等其第3段开工牵引）；
2. `MotionSource`（WII时间线适配是现成第一实现）；
3. `Actuator`/`Sensor`（张力机进仿真时）；`CollisionQuery`（碰撞预演需求时）；
4. `Episode`不排期（数据集先行裁决）。

每个接口首实现落地→spec/10对应节从草案升已验证→集齐后spec/10冻结v1。
