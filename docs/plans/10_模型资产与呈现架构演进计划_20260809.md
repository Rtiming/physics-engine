# 模型资产、呈现与硬件适配演进计划（2026-08-09）

状态：**平台子计划，未批准实施**。研究正本见
[research/14](../research/14_多表示模型资产与硬件适配架构_20260809.md)，架构入口见

> **2026-08-09顺序校正**：本计划只管理多表示模型、资产编译、Blender/VTK等端点和三类
> backend专项，不再代表整个工程设计与计算平台的开工顺序。上位产品架构与总路线见
> [platform/README](../platform/README.md)和
> [platform/03](../platform/03_演进路线与仓库边界_20260809.md)。平台应先冻结自有协议，
> 用FTS+WII只读纵切反证runtime/Studio，再接WDS与GCW；不能直接从STEP→GLB或Blender桥
> 开始，把工具链误当产品核心。下列“阶段0—6”仅是本子系统内部编号。

本计划**不替代**[plans/08](08_子系统补充计划_20260806.md)阶段1—3，也不改变
[plans/09](09_交接_20260806.md)的当前物理主线。它是可与物理主线并行的规范/资产基础设施
轨道；没有用户后续授权，不创建新仓、不改代码、不引入依赖、不迁移消费方。

## 一、目标与非目标

### 目标

1. 同一工程对象的设计、物理、碰撞、proxy、render、实测与动画表示可被明确登记和切换；
2. CAD/资产转换可增量、可缓存、可复读、可在本地或master执行；
3. GCW/WII/WDS/FTS共享身份、单位、坐标系、资源生命周期和硬件能力描述；
4. 在线Web、Blender离线动画、VTK场可视化都消费同一权威结果绑定；
5. 低端单机有基线路径，高端CPU/GPU按显式profile加速，物理定义不变。

### 非目标

- 不把GCW/WII/WDS/FTS吞进physics-engine；
- 不统一四项目的领域renderer、picking、布局和物理；
- 不把GLB、USD、Blender或任何GPU设为必需设施；
- 不允许视觉模型自动充当碰撞、制造或物理权威；
- 不为尚未出现的外部消费方预支完整插件生态。
- 不承担平台的工程模型、工程工作流、工作区、命令系统和设计系统；这些由上位平台拥有；
- 不让Blender、Three.js、VTK或任何交换格式成为平台对象模型与用户工作流的权威。

## 二、阶段0：固定场景、身份链与基线（只读/文档优先）

### 工作

1. 为research/14的S1—S4各选一个可长期复验的代表输入；
2. 记录输入规模、格式、SHA、单位、坐标系、许可/隐私与预期输出；
3. 给S1—S7定义测量入口：冷/热构建、首帧、帧更新、内存/显存、帧渲染；
4. 修订WII时间线schema方案，使其能携带`source_identity`；
5. 盘点四仓所有绝对路径、大资产、转换器版本与缓存位置。

### 退出条件

- S1—S4代表输入有明确权威源，不含未经授权的第三方资产；
- 每个输入能由另一个读者复述“什么是真源、什么只是显示”；
- GCW→WII五个交叉面都能报告同一来源身份；
- 基线工具不声称尚未测量的硬件收益。

## 三、阶段1：表示清单草案（先消费方、后引擎）

### 工作

1. 从引擎`MeshAsset/SimBody/AppearanceRef`、WII `ModelAssetRef`、WDS前端manifest、
   FTS模型manifest蒸馏字段；
2. 在已登记消费方WDS和FTS各做一份**仓内草案适配**，不先让physics-engine依赖它们；
   WII作为上游运动/资产形制的种子，可并行做管线适配，但不冒充本仓消费方；
3. 冻结候选角色、来源类型、单位/坐标系、转换边和误差字段；
4. 证明新增清单不改变两个消费方既有运行产物字节；
5. 满足两消费方后，再申请physics-engine实验facet登记。

### 退出条件

- 已登记消费方WDS与FTS同意同一核心字段；
- 未知扩展能保留，核心错字段/错单位/错SHA失败关闭；
- visual/collision混用、反向权威转换各有必红用例；
- facet未登记前，不存在跨边界落盘的“临时正式格式”。

## 四、阶段2：内容寻址资产编译器

### 第一条真实链

优先`STEP/B-Rep→OCCT/XCAF→GLB+实体映射+回执`，原因是GCW/WII已有真实CAD与浏览器
资产需求，且不依赖Blender即可形成最短工程链。

### 工作

- preview/standard/final三档三角化；
- 转换DAG、缓存键、staging、原子发布与严格复读；
- 资产质量、误差、单位、坐标系、源/产物SHA和工具版本回执；
- 实体/语义锚点到GLB node/primitive的版本内映射；
- 可取消、可恢复、单机顺序实现；master只是可选执行器。

### 退出条件

- 输入和recipe不变时`rebuilt_nodes=0`；
- 改任何源SHA、单位、frame、工具版本或误差参数都会失效对应缓存；
- preview和final可切换但身份一致；
- 输出GLB从未被碰撞/制造路径静默采用；
- Windows、macOS至少完成结构复读；Linux执行器按真实需要补，不预报通过。

## 五、阶段3：Web运行时公共层与领域适配器

### 公共层只拥有

- 表示清单读取、资源生命周期、LOD/quality选择；
- scene node身份、单位/frame变换；
- 材质/可见性/相机preset的中性数据；
- 时间轴游标、精确帧/显示插值标记；
- 资源释放、context loss恢复和可观测性能计数。

公共层只交换中性声明与状态，不暴露或共享Three.js/WebGL/VTK的对象树；renderer对象、
shader、GPU buffer与picking索引由各适配器所有。

### 领域适配器保留

- GCW：CAD面/样本picking与分析覆盖层；
- WII：求解器FK结果、连杆bind pose、碰撞裁决；
- WDS：自定义WebGL舞台、FramePacket和证据模式；
- FTS：光学拓扑布局、光束和仪器状态。

### 退出条件

- WII刚体播放几何重建数=0、每帧网格上传字节=0；
- WDS适配不补造物理帧、不复制renderer实现；
- FTS/GCW模型替换不改各自物理/分析结果；
- 静态场景空闲时不持续无意义重绘；
- WebGL2基线可用，可选WebGPU不能成为启动前置。

## 六、阶段4：Blender离线桥接与动画导出

### 两个必须同时过的样板

1. **刚体样板**：WII时间线+逐连杆GLB→Blender→帧序列/视频；
2. **形变样板**：WDS FramePacket→Alembic或USD time samples→Blender→帧序列/视频。

### 工作

- 钉Blender LTS、脚本/插件版本和渲染recipe；
- 导入GLB/USD/Alembic，绑定稳定ID、frame和时间；
- 材质、灯光、镜头模板；
- 先PNG/OpenEXR帧序列，后独立编码视频；
- 分帧状态、失败重试、缺帧检查和产物回执。

### 退出条件

- Blender脚本没有FK、接触、OPD或其他物理重算；
- 中断后只补缺帧，不重渲已验证帧；
- 输出绑定源资产SHA、run package SHA、recipe与Blender版本；
- `.blend`只作作者工作区/缓存，不作跨项目权威契约；
- 两样板都过之前，不宣称“通用动画导出已完成”。

## 七、阶段5：硬件执行面与性能自适配

### 工作

1. 定义只陈述事实的`capabilities`：OS/架构、核数、内存/显存、后端/驱动、精度、限制；
2. 定义显式`execution_profile`：baseline/interactive/batch/render，不让探测结果暗改物理；
3. 求解、资产编译、渲染分别建立backend registry；
4. 建本地执行器与可选远程执行器，共用可序列化、幂等、可恢复作业描述；
5. 建端到端计数器与墙钟报告，确定性结构量才进功能门。

### 退出条件

- 没GPU/没master/没网络时，基线功能仍成立；
- 数值GPU后端满足spec/13的profile、等价和≥2×三门槛；
- 低硬件只能降低**显式视觉质量档**，不得降低物理精度或证据等级；
- 驱动、工具链、BLAS、后端与确定性等级进入产物环境信息；
- 平台相关缓存分命名空间，不跨平台误命中。

## 八、阶段6：按真实牵引接生态端点

| 端点 | 重开条件 | 首个验收场景 |
|---|---|---|
| OpenUSD | 同一设备出现复杂引用、variant、proxy/render或长序列组合 | 多配置工位+长动画 |
| VTK/vtk.js | 第一个真实网格/标量/矢量/体场需要交互检查 | 场切片/等值面/时间序列 |
| URDF/SDF | WII或新机器人消费者需要跨模拟器交换 | link/joint/visual/collision往返核对 |
| Godot | 明确要离线桌面/移动模拟器 | 固定帧率交互回放 |
| Unreal | 明确要高写实实时/影片且接受平台成本 | 宣传/评审影片 |
| Omniverse/Isaac Sim | 明确要USD原生协作、NVIDIA机器人或合成数据 | USD机器人/传感器支线 |

未满足重开条件的端点只登记，不实现。

## 九、总验收矩阵

| 轴 | 必须证明 | 不能拿来代替 |
|---|---|---|
| 身份 | subject/source/revision/frame/units贯穿 | 文件名相同 |
| 物理 | 前端/转换/渲染不重算、不降精度 | 页面看起来合理 |
| 转换 | 有向、有损性、误差与工具recipe可复读 | “格式能打开” |
| 缓存 | 完整键、严格复读、零重建计数 | 第二次更快的印象 |
| 运行时 | 静态/动态分离、零重复上传/分配计数 | 一台高端机器帧率 |
| 硬件 | CPU基线+后端等价+环境溯源 | 检测到GPU |
| 动画 | 帧完整、来源绑定、可恢复 | 成功导出一个MP4 |
| 跨平台 | 相对路径、平台命名空间、结构复读 | 单机绿色 |

## 十、需要单独裁决的决策点

| 改动 | 所有者 | 谁批准/按什么门 |
|---|---|---|
| physics-engine实验facet | 本仓 | 用户明确授权+新决策记录+面清册+两消费方证据 |
| WDS/FTS仓内适配 | 各消费方 | 各仓自己的ADR/design、冻结diff与全量门 |
| WII上游资产/时间线适配 | WII | WII自己的契约与验收，不冒充本仓消费方 |
| 平台代码仓与资产子系统落点 | 尚未指定 | 用户明确裁决平台仓名、所有者、远程与资产策略 |
| 数值硬件后端 | physics-engine/领域内核 | spec/13等价与性能三门槛+单独决策记录 |
| Blender/渲染端点 | 拟议平台adapter子系统 | 对应固定场景验收；不得改变物理与消费方权威 |

本计划本身没有批准上述任何一项；表中批准材料齐全前，只能继续只读研究或文档草案。

1. 上位平台是否按platform/03建议建独立monorepo、仓名和首批所有者；
2. `model_representation_bundle`是否进入physics-engine、稳定性档位与版本；
3. WII时间线v2身份字段的精确schema；
4. S1—S4代表输入及其分发许可；
5. Blender LTS和首个动画缓存格式；
6. 哪个真实性层级允许人工视觉精修；
7. 何时满足OpenUSD或非CPU数值后端重开条件。

任何一项未裁决，不用“先写着以后再定”的代码绕过。
