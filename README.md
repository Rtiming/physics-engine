# physics-engine

rtime的**物理引擎**：多域物理（力学、光学、电磁，将来热）+ 模型生成 + 物理性质
（材料）+ 外观（颜色）+ 溯源纪律的仿真引擎仓。2026-08-04用户裁决建立并定位
（原名twin-engine，同晚更名）：走共同仓库、深度融合、接口规范统一。

创始消费方：`winding-deviation-sim`（力学，绕制偏差）与`fts-digital-twin`
（光学，傅里叶光谱仪）；潜在第三个消费方`case2-digital-twin`（专利装置数字样机）。
**用户级定位（decisions/0014）**：目标机器状态永远未知——单机冷启动性能是第一指标
（import、场景校验、quick/full验收与wheel体积的预算/实测正本都在
`benchmarks/engine_budgets.baseline.json`，有门守着陈旧度，不在README复制易漂移墙钟）、
功能操作不因宿主负载拒绝或变形、零设施假设是承诺。

### 案例穿过引擎哪几层

33个案例不是一类东西。走完`state`→`energies`→`solve`整条路的**9条**
（两条悬臂+Euler屈曲+**五条接触**：静置阈值、历史迟滞、多体金字塔、绞盘张力比、
绕线链路端到端；外加导轮偏斜横漂那条梁-弦边值问题）；
1条走`state`→`sections`→`section_beam`→`energies`→`solve`（WDS运动学单站全局回弹）；
1条走`state`→`rod`→`energies`→`solve`**外加一层retransport循环**（整杆双轴弯曲＋扭转，**唯一一条求解入口被包了一层的**）；
1条走`state`→`sections`→局部截面平衡（弹塑性分布与自由回弹）；
3条走`state`→`energies`→`integrate`（两体弹簧、单次弹跳、十球漏斗）；
3条走时间推进不碰能量装配与求解器；
1条只验`energies`协议层；**5条是闭式计算器，不碰引擎的任何一层**（三光学+两电磁）；
6条验几何查询、资产治理与模型生成。

**波次二新开了三条各自独立的层，一条也不走`solve`**——这一点本身是要读出来的：
1条走`transport`自带的输运推进（张力由速度差生成，状态是两个标量不进`State`）；
1条走`motion`→`laydown`的纯运动学（落位点在槽的哪里、槽标架朝哪、要放多快，
**一个自由度都不解**）；1条只走`contact`的切向本构层（各向异性摩擦椭圆的
return-map，**它不在上面任何一行是因为步进器今天接不上椭圆映射**——
那一行是**欠账的位置**，不是一个新的分类成绩）。

**9+1+1+1+3+3+1+5+6+1+1+1 = 33。** 逐案例标注见[cases/README.md](cases/README.md)第一节之二。

**波次三又开了一条跨两个模块的层**（`laydown`→`transport`的扰动通道，
`cases/span_disturbance_channels`，决策0071）：臂动经落位点几何变成收线端速度、
人手横向触碰让直线段变折线。**它仍然一个自由度都不解**，所以不进上面任何一行。
它同时正面否掉一条错误因果——0066写着"真机上跨长逐样点变"，而plans/14第3.3节
订正后的场景里自由跨两端都是世界系固定的，**`L_geo`是常数**；臂动改的是落位点的
几何不是跨长。
⚠ **上面那个33与那条加法式子没有把波次三的新案例算进去**：本波次三条轨道并行，
**计数由收口时一次点清**（同一个数字被三条轨道各改一次必然对不上，
而`cases/README.md`两张表不一致这件事波次二已经发生过一次，0064第7.4节登记）。

**"验公式"与"验引擎"是两类，混在一个计数里计数就不再有意义**（0048第三节）。
本仓的验证纪律强度在同行里罕见（research/12实测：NVIDIA 237个样例里带定量容差的
只有1个，SOFA是474:1），**但验证纪律不是物理能力**——把前者当后者是这个仓
最可能犯的错，因为它是从治理层长出来的。

### 逐模块的能与不能

**能做**：声明形状与材料（`shapes`/`materials`）；算解析原语的质量属性——体积、
质心、绕质心惯量张量（`geometry`）；查碰撞——broad phase全域 + 球/胶囊族narrow phase
（`collision`/`scene`，其余族诚实保留`broad_phase`可信度）；装配能量项——均匀重力、
轴向拉伸、小挠度弯曲、**几何精确（DER）弯曲**、**点载荷**（`energies`）；求准静态平衡——
牛顿+回溯线搜索+稠密LU／带状求解，并可判平衡是不是极小（`solve`）；推时间积分——
显式Euler／半隐式辛Euler／velocity Verlet／`velocity_verlet_damped`
（`integrate`）与刚体姿态积分（`rigidbody`）；
**算接触**——罚法向（半空间、球-球、**有限长圆柱侧面**、**法兰内环面的单边限位**）、
粘着弹簧、库仑return-map与**各向异性摩擦椭圆**（欧氏最近点投影＝关联流动，
决策0068）、准静态步进器（**单槽位与多槽位同时迭代两条并列路径**，两条都可选椭圆
屈服面，``μ_∥ = μ_⊥``时**逐位**退化回圆，**默认仍是圆**，决策0072）、
线性法向dashpot与全阻尼恢复系数标定，**多体成立、锚点是真历史、瞬态阻尼碰撞也通**
（`contact`，决策0050、0055、0062）；
**算张力驱动链**——磁粉离合器电流→扭矩（截断饱和＋零阶保持的精确一阶磁滞）、
卷径换算`T = M/R(n)`、理想PID（积分双边限幅）、LTS式传感器（满量程截断＋ADC就近量化）
与包角换算，时延经`actuators`的环形缓冲进环（`drives`，决策0062；
**不复现ATC600**——真机回路是拿不到参数的黑箱）；控制器是**协议**不是具体类
（`TensionController`，决策0070），用户能把自己写的环插进来；
**把张力环接到对象上算**——`transport`的跨段-放线盘与`drives`的离合器-PID-时延
串成一个多速率零阶保持的真闭环，绞盘比进环（`tension_control`，决策0070；
**不新增任何物理**）。**它算出来的第一个结论是一个否定**：额定磁粉离合器比跨段
谐振慢19倍（`ω_n·τ = 18.98`），于是闭环把10%线速度阶跃的响应**变坏**
（峰值×1.073、ISE×1.389），而四阶闭式预言了它——**真机上压住这条谐振靠的是
摆杆/储带机构，本仓没有摆杆模型**；
**喂着料算**——节点预算声明期定死、布局定长，已喂/未喂是向量里的一个值，
未喂边的贡献逐字节为零（`feed`，决策0062；**不是材料注入**）；
**算局部截面响应**——矩形中点纤维的一维理想弹塑性、逐点历史、N/M与一致切线、
受保护Newton自由回弹（`sections`，决策0059；积分点不是独立全局DOF）；
**算一个WDS式截面站点的全局easy-axis弯曲**——3节点位置+2边扭角生成几何精确曲率，
纤维弯矩与一致切线经二阶链式法则进入`EnergyRegistry`/全局Newton，历史收敛后提交
（`section_beam`，决策0060；0061对应的WDS线弹性正式接缝已经进入main）；
WDS随后在R25固定材料顶点完成逐纤维塑性history事务，再完成对偶单元轴向应变、N/M与
2×2截面切线的消费侧单站装配；三者均默认关闭、使用独立案例/plugin身份，最终main为
`bef42882...`。这些闭环没有修改或重发引擎，也不等于整个力学域迁移完成。范围与停止
条件见[plans/12](docs/plans/12_R25塑性history单站采纳计划_20260816.md)与
[spec/90消费方登记](docs/spec/90_消费方登记.md)；
**算整杆的双轴弯曲与扭转**——平行输运材料帧（Rodrigues递推＋重新正交归一＋零依赖
相位解缠）、逐顶点`EI_easy`/`EI_hard`两个刚度（`κ1`配easy、`κ2`配hard，**配反即失败
关闭**）、边扭角`γ`与`0.5·GJ·(Δγ+m_ref)²/l̄`扭转项，外加**retransport外层循环**
（求解→重输运参考帧→重建context→再求解，写在`solve_equilibrium`之上）。
**槽壁接触已接上**（`PenaltyGrooveWall`，决策0072）：它是本仓第一个**同时索引
位置块与边扭角γ的接触项**——采样点取带材的两条材料边`x ± (w/2)·m̂2`，
而`m̂2`由相邻两条边的材料帧合成、因此依赖γ，于是带材一扭就有一条边压进槽壁。
给定强制帧扭转时**槽壁挡住多少、带材实际扭多少算得出来**（与一条独立闭式对拍，
差额是`O(1/k)`罚穿透，四档刚度整整齐齐差十倍）；张开槽壁时**整条状态向量逐位**
退回自由扭转的闭式`θ = M·L_eff/GJ`。
`rod`是**纯弹性的**：没有纤维塑性、没有轴向`N`，槽壁**只有法向没有壁上摩擦、
只做了半空间没做锥面**，与`sections`/`section_beam`那一片今天没有接口
（`rod`，决策0065、0072）。
四条闭式门在`cases/anisotropic_rod_twist`：螺旋线`κ`/`τ`二阶收敛且`κ2`是结构零、
易/难轴互换的挠度比、端扭矩`θ=M·L/GJ`、Gauss-Bonnet的`π/2` holonomy——
**最后一条的第三个期望值是个错误答案（不重输运时扭转能量恒为`0.0`），
那是「抄了公式不抄外循环」的分辨力本身**；
光学闭式（`optics`）与电磁闭式（`electromagnetics`）。

**不能做**：**没有隐式时间积分族**；**没有约束**——边界条件只有
"显式钉住某些自由度"这一种；**没有跨域耦合**（`couplings/`目录不存在；
0094裁了它将来的形状——**耦合是边不是域**，但**不建目录**：建它要有第一个真实的跨域需求）；
**没有偏微分场求解器**（静磁、涡流、静电Laplace一个都没有）。

> **2026-08-19订正一句已经不成立的话**：本段原文写的是"**没有场求解**——光学与电磁至今全是闭式，
> 没有网格、没有复数场、没有FFT"。**后半句从决策0086起就不成立了**：
> `optics/field.py`有二维复数场与基2 Cooley-Tukey（纯Python零依赖）、
> `optics/propagation.py`有角谱／菲涅耳／夫琅禾费三形制并显式声明采样判据、
> `optics/mie.py`有严格级数解、`electromagnetics/neumann.py`是数值求积不是闭式代入。
> **今天仍然没有的是"解偏微分方程的场求解器"**，那与"有没有复数场与变换"是两件事——
> 一句正确的结论配一个过期的理由，会把下一个人送上一条不存在的路。physics-engine原生`section_beam`只接了
**一个easy-axis三节点站点**，固定轴向应变；WDS消费仓虽已另做一处轴向—弯曲N/M单站，
本仓仍没有整杆多站、原生轴向全局项、hard-axis、剪切、扭转、翘曲、压扁、二维任意
截面或电磁截面场自由度。**扭转与整杆各向异性弯曲只在`rod`那一片**（决策0065），
而`rod`与`section_beam`两片今天没有接口：`rod`没有塑性与轴向，`section_beam`只有一个站点。
球-球动态检测到响应的接线已落；0062又落了圆柱侧面与法兰内环面两个**接触项**
与多槽位同时迭代——**但接触项不是窄相**：那两个几何是**声明**进来的，不是检测出来的。

> **2026-08-19订正两处**（决策0083的M1、0090）：
> ① 本段原文写"`collision.py`至今没有圆柱/盒/网格族的窄相"——**圆柱与盒那两族已经有了**
> （0090），**而"网格"那两个字仍然一个都没兑现**：`MeshAsset`不带几何，连输入都没有。
> 同批落了距离场探针，但**它进不了接触管线**——域隔离门不许`collision`（基座圈）
> import`contact.field`（力学域圈），**答案是协议不是import**，那条协议还没裁；
> ② 本段原文写"今天是质点+半径、**没有力矩**"——**从plans/16的M1起不成立**：
> `contact_dynamics`把`τ = r×F`装起来了，翻倒与无滑滚球两条案例都在跑它。
> **仍然对的是**：导轮不自旋（那要转动自由度接进那条链路，不是接进接触）。

**接触仍缺**：网格窄相（缺的是输入）、候选空间索引、动态平面统一接线、
载荷控制失败后的真回退、**一个窄相对只给一个接触点**（与0082"底面是一组物质点"方向相反，
**同行也只给一个，抄不到，要新裁**）。带材在接触里**没有宽度**（只有一个用于定位边缘的半宽偏移）。
**"槽壁挡住多少、带材实际扭多少"（plans/14第2.3节）现在算得出来了**（决策0072），
但那是`rod`的直杆最小构造＋半空间槽壁，**不是真实工件的锥面槽**，
而且**槽壁上没有摩擦**——`PenaltyAnnulusLimit`那一族仍然维持"无扭转假设"。
六个积分器（四个平动+两个刚体）的`production_ready`**全为`False`**且有门守着。

源码里**零个**`TODO`与`NotImplementedError`——未做的事全靠这一段与
`src/physics_engine/__init__.py`的同名段落记账，`import`进来的人从API面上读不出
"哪些能力不存在"。**两段必须同批改**。

## 本仓是什么

两个消费方在互不知情的情况下长出了同构的骨架纪律（契约版本冻结、输入内容寻址、
写后严格复读、验收预算30/120秒、"已知不成立"清单）。本仓把这套共同纪律先做成
**规范**，再逐步做成**共享代码**：

- `docs/spec/` — 统一接口规范：七条轴（02—08，v1.0已冻结）+ 模块地图（01）
  + 内核接口草案（10，场景装配与六接口，v0）+ 形状表示草案（11，模拟形状
  非制造实体，v0）+ 消费方登记（90）
- `docs/research/` — 调研正本（01：成熟引擎与五仓形状表示盘点）
- `docs/architecture.md` — 仓内依赖图与产品级工程设计/计算平台拓扑的总入口，不覆盖spec正本
- `docs/platform/` — RTime工程设计与计算平台愿景；工程模型、科学计算、工程工作流、
  视觉交互四个内核+Engineering Studio，设计系统、资产、插件、部署、仓库迁移与纵切路线；
  均为候选架构，未声明已实现
- `docs/plans/00_引擎开发路线_v0.md` — 继续开发从哪下手（M-E1契约基座→
  M-E2溯源→M-E3场景与接口）
- `docs/migration/` — 两个消费方的迁移操作单（各自会话自足执行）
- `docs/decisions/` — 本仓自己的决策记录（0001—0063，编号有缺口见0049第八节）
- `src/physics_engine/` — 共享引擎代码；进入前提见包文档字符串三条

**规范先行、代码后置**：任何一段代码进入本仓的前提，是对应规范已冻结、
且两个消费方的既有产物指纹在采纳后逐字节不变。

## 怎么跑：入口一页表

**想验证某件事、跑哪条命令、期望看到什么，全在
[`docs/entry_points.md`](docs/entry_points.md)。**
那一页立于2026-08-18，理由是实测出来的：入口散在`tools/`、`validation/`、`cases/`
与四个环境变量里，而**没有任何一个地方能让人一眼看完**——
后果是有三条选择进入的通道**从来没有被整体跑过一次**，
而`accept full`只会报skipped，**skip在回执里看起来和pass一样绿**。

最常用的两条：

```bash
.venv/bin/python -m pytest tests -q -m "not batch and not serverclass"   # 本机快档，约32秒
bash tools/master/run_accept_on_master.sh full                            # 全档验收（墙钟以master为准）
```

## 安装与调用（舰队wheelhouse链路，decisions/0010）

```bash
git clone ts-orangepi:wheelhouse.git ~/wheelhouse   # 每台机器一次，更新=git pull
uv add "physics-engine==0.8.0" --find-links ~/wheelhouse
```

上面是**最新已发布版**。已发布版本在wheelhouse中永久共存；更新依赖时仍须钉精确版本
并由消费方自己的回归门验证，不能仅因存在新版本就被动漂移。

调用示例：

```python
from physics_engine import FacetRegistry, canonical_sha256, verified_bytes_snapshot
from physics_engine.run_package import publish_package, read_verified_package
```

数据层入口（场景文件+一条命令，装完即有）：

```bash
pe-scene check-collisions 场景.scene.json --out-dir runs
```

API分两档（见包docstring）：稳定倾向=facets/canonical/identity/provenance/
run_package；实验档=shapes/collision/scene。**0.x语义：minor可破坏兼容，
patch只含兼容修复且不回port；消费方钉精确版本、经自己门禁自觉升级。**

**老版本共存（decisions/0012）**：wheelhouse已发版本永不覆盖、永不删除——
钉住旧版的程序永远装得上同一份字节；同机多版本靠各自venv隔离并行，
引擎不装共享Python。随手脚本用PEP 723内联声明+`uv run`（每台机器设一次
`UV_FIND_LINKS=~/wheelhouse`后全自动）：

```python
# /// script
# requires-python = ">=3.11"
# dependencies = ["physics-engine==0.8.0"]
# ///
```

稳定倾向档弃用给一版缓冲；变更必须写[CHANGELOG](CHANGELOG.md)（发版脚本
强制检查）。发版：`.venv/bin/python tools/release.py`（干净仓+accept全绿+
CHANGELOG条目才发，版本不可覆盖；有github远程时自动镜像推送）。
公开镜像：github.com/Rtiming/physics-engine（MIT）。
