# case/spool_winding_growth——卷径随匝数生长与喂料前沿的材料守恒

守能力位**S5.3**（线圈盘几何与半径随匝数生长）与**S5.4**（喂料与移动前沿）
里"匝数与半径生长的接线"那一条。裁决记录：
[0093](../../docs/decisions/0093_卷绕堆积律住哪与材料守恒记在整数上_20260818.md)。

## 一、物理/几何设定

场景⑤（plans/04第八节）："一个平面的带有一定的厚度，然后一点一点地绕到
我们的线圈盘里面，多绕个十几圈。"本案例只取其中**几何与记账**的那一半：
匝数怎么变成半径、喂进来的材料去了哪。**力、接触与自接触不在本案例内**（见第六节）。

单位：长度**mm**、角度**rad**、时间**s**（本仓口径）。

### 1.1 卷绕堆积（`oracle:winding/radius_ladder`与`concentric_material_length`）

| 量 | 值 | 说明 |
|---|---|---|
| 筒半径`barrel_radius_mm` | 64.0 | 空盘时的有效半径``R₀`` |
| 带厚`tape_thickness_mm` | 0.5 | 材料本身的厚度``t`` |
| 堆积因子`packing_factor` | 0.5 | 材料占层厚的比例 ⟹ 有效层厚``t_eff = t/packing = 1.0`` |
| 每层匝数`turns_per_layer` | 1与4 | 盘香式取1、排绕式取4 |
| 层推进`layer_advance` | `continuous`与`stepped` | 盘香式／排绕式 |
| 匝数阶梯 | 0／1／2／3／4／6.5／7／8／13／100 | 见`generate_oracle.py`的`RADIUS_LADDER` |

**入参全部取2的幂之和**（``64 = 2⁶``、``0.5 = 2⁻¹``），乘加全程无舍入——
这是第三节里三格能判**零容差**的前提，不是随手挑的数。

### 1.2 收敛阶阶梯（`oracle:winding/concentric_versus_archimedean_order`）

筒半径64.0mm、匝数12.0**不动**，带厚逐档减半：
``0.5 / 0.25 / 0.125 / 0.0625 / 0.03125 / 0.015625 / 0.0078125``mm，
于是无量纲小量``ε = t/R₀``从``7.81e-3``降到``1.22e-4``，共七档。

### 1.3 喂料段账（`oracle:winding/feed_front_material_balance`）

| 量 | 值 |
|---|---|
| 节点预算`node_budget` | 1400 |
| 静止段长`rest_length_mm` | 4.0（二进制精确） |
| 自由跨距`free_span_segments` | 3段（喂料口到落位点之间悬着的材料） |
| 筒半径／带厚 | 32.0 ／ 0.5 |
| 取样`fed_count` | 2／4／5／200／500／900／1400 |

喂满1400个节点时盘上**23.469匝**、有效半径**43.735mm**（从32.0长起来）。
`fed_count = 2/4/5`三档专门取在**落位前后**：跨距3段时``fed_count = 4``
盘上恰为0段、``fed_count = 5``盘上恰为1段。

## 二、参考解出处

**闭式解**，三个来源，全部在`generate_oracle.py`里推过且该脚本**不import
`physics_engine.winding`**：

1. **半径与同心圆长度**——手推。``R(n) = R₀ + t_eff·m(n)``的期望值是手算整数
   （生成器注释里逐条列了推导）；长度用机械手册里卷料估长的**平均直径式**
   ``L = π·n·(D_out + D_in)/2 = π·n·(2R₀ + t·n)``；

2. **真阿基米德螺线的弧长**（本案例最硬的一条）——螺线``r(θ) = R₀ + aθ``、
   ``a = t/2π``，由``ds² = dr² + r²dθ²``得

       L = (1/a)·∫_{R₀}^{R₁} √(u² + a²) du
         = [ u√(u²+a²) + a²·asinh(u/a) ] / (2a)   from R₀ to R₁

   标准结果，见 Gray, *Modern Differential Geometry of Curves and Surfaces*,
   2nd ed., §1.5 "Arc Length"（极坐标弧长一节，任何微积分教材同）；

3. **二阶这个期望值本身是解析结果不是实测**——把``√(u²+a²)``展开
   ``u(1 + a²/2u² + …)``，一阶项积出来恰是同心圆式，丢掉的首项是
   ``(a/2)·ln(R₁/R₀)``，相对于``L ≈ 2πnR₀``是``O((t/R₀)²)``。

**生成器入库**：`cases/spool_winding_growth/generate_oracle.py`，
SHA-256钉在`oracle.json`的`generator.sha256`字段。

### 2.1 一次被抓到的假独立（2026-08-18）

`_concentric_length_mm`第一版写的是``2π·(R₀n + t·n²/2)``——与
`winding.radius_integral_mm`**逐字符同构**，于是"金标 vs 被验"实测相对偏差
恰为``0.0``。**那个零不是精度好，是两边根本是同一支笔**，这条oracle当时验不了
任何东西。改成平均直径式之后两边代数恒等而结合次序不同，零变成了真的舍入
（``1.58e-16``）。**相对偏差恰好为零，往往是金标出了问题而不是实现特别好。**

同一轮还抓到第二个：``spiral_arc_length_mm``原本住在``expected``里，
而引擎**有意不算**螺线弧长，于是测试只能拿冻结值对它自己。已挪进``inputs``——
``expected``的语义是"内核应当产出什么"，参照量不属于那里。

## 三、判据表

| 量 | rel | abs | 理由 |
|---|---|---|---|
| `effective_layer_thickness_mm` | 0 | 0 | **零容差判逐位**：``0.5/0.5``在IEEE754下无舍入，期望恰``1.0``。它是下面14个手算半径成立的前提 |
| `radius_mm`（14档） | 0 | 0 | **零容差判逐位**：入参全为2的幂之和，``R₀ + t_eff·m``乘加无舍入，期望是手算整数/半整数。**这一格不该有容差**——有容差就意味着有一步没算清楚是哪来的 |
| `layers`（14档） | 0 | 0 | **零容差**：台阶式整数、连续式``n/tpl``且二进制精确。单列它是因为**半径对了不代表层数对了**（``t_eff``与``m``可以一个偏大一个偏小而乘积不变） |
| `wound_length_mm`（6档） | 1e-15 | 0 | 平均直径式 vs 半径积分式，代数恒等而结合次序不同。2026-08-18实测最坏``1.5794e-16``，取1e-15留约6.3倍 |
| `per_turn_circumference_sum_mm`（5档） | 0 | 0 | **零容差，且这个零是结构性的**：本脚本每匝写``π·D``、内核写``2π·R``，``D = 2R``而**乘2在浮点上精确**，两式是同一个实数的同一次舍入。代价：这一格验不了结合次序；换来的是**求和次序被钉死**（spec/12第3.3节：求和次序是形制）。它真正的分辨力是对"半径更新早一匝还是晚一匝"敏感——差一匝时两边差``2π·n·t_eff/2``，13匝那档``≈408mm`` |
| `turns_recovered`（6档） | 1e-14 | 0 | 期望值就是入参那列匝数本身（**独立by construction**，脚本一个字没算）。实测最坏``1.3158e-16``，取1e-14留76倍——余量大是因为**这档入参恰好精确，真机参数下相消更重**，不能拿它当反解精度的一般结论 |
| `concentric_length_mm`（7档） | 1e-15 | 0 | 同`wound_length_mm`，实测``1.58e-16``量级 |
| `relative_deviation`（7档） | 1e-5 | 0 | **容差由条件数定，不由实测定**：偏差是两个约``4830mm``的数相减，最细一档差值只有``9.1e-7mm``，而``4830``的一个ulp是``9.1e-13mm``——**任何一次重结合都会把这个差搅动约1e-6的相对量**。实测恰为``0.0``（两式在精确入参下逐位相同），但**拿那个0当容差是自欺** |
| `observed_order`（6档） | 0 | 1e-4 | 由上一格取``log₂``得出，容差**由上一格推来而不是另立**：``log₂``把相对扰动压成``Δd/ln2``的绝对扰动，两档各1e-5最多约``2.9e-5``，取1e-4留3.4倍。**两格容差必须自洽**——第一版写成1e-5配1e-6是一对互相矛盾的声明 |
| `segments_fed` / `segments_in_free_span` / `segments_on_spool`（各7档） | 0 | 0 | **整数，零容差**。三格相加是本案例的材料守恒恒等式。守恒记在段数上而不是浮点长度上，正是为了让这三格能判``==`` |
| `length_on_spool_mm`（7档） | 0 | 0 | **零容差**：``段数 × 4.0``，静止段长二进制精确，一次乘法无舍入。**换成``0.1``就不再是零容差**——`tests/test_winding.py`量过：1392个喂料档里**373档**浮点长度逐位不守恒 |
| `turns_on_spool`（7档） | 1e-14 | 0 | 长度反解匝数。本脚本走``ℓ/π``、内核走``2·(ℓ/2π)``，同为有理化式子而结合次序不同。实测``0.0``（这组入参下两路给同一个数）。1e-14是**给将来换写法与非精确入参留的，不是今天量出来的余量**——这句话必须写，否则半年后有人会以为这里量出过1e-14 |
| `radius_on_spool_mm`（7档） | 1e-14 | 0 | ``R₀ + t·n``，误差随``n``进来。这一格是**S5.4那条"匝数与半径生长尚未接在一起"的兑现** |

### 3.1 清单里没有、也不该有的四条关系型判据

它们不是冻结的数，写在conformance测试里（`tests/cases/test_spool_winding_growth.py`）：

1. **逐档偏差单调下降**——0087："逐档差不单调就是没进渐近区，那个阶不许当收敛阶引用"；
2. **逐档阶``≥ 1.9``**；
3. **阶本身单调递增**（实测 1.9354→1.9670→1.9833→1.9916→1.9958→1.9986）；
4. **阶从下方逼近2且最细一档与2的差``< 0.01``**——从上方逼近说明展开的次项符号与推导相反。

外加一条：**盘上的段数任何时候不为负**。它补的是一个真空门——
守恒恒等式对"两边同时错了一个常数"是**盲的**（详见第四节）。

## 四、已知失效清单

1. **半匝（``n = 13.5``）那一档不进`per_turn_circumference_sum_mm`**。
   "每匝周长之和"这个量对非整数匝没有定义（半匝不是一匝）。
   长度与反解两格照常覆盖13.5，只有求和那一格跳过它。
   **解封条件**：若将来要判部分匝的长度，那要先裁"半匝算不算一匝的一半周长"——
   在同心圆理想化下算，在真螺线下不算，那是一次新裁决；

2. **`turns_at_length_mm`数值稳定写法的验收不完整**。必红实测里
   "取``(−R₀+√…)/c``那一支"这个变异体在本案例只红1处、在
   `tests/test_winding.py`红2处——**两处的参数都还没进到严重相消区**
   （``R₀/(cS)``不够大）。真正会把它打红的是**极薄带+极少匝**那一角
   （``t/R₀ < 1e-6``且``n < 1``），本案例没扫到那里。
   **解封条件**：S5.6（张力沿带材传递）要用到起绕瞬间的匝数时补一档薄带扫描；

3. **`relative_deviation`与`observed_order`两格的实测偏差恰为``0.0``**，
   于是它们声明的容差（1e-5／1e-4）**今天一次都没被行使过**。
   它们是按条件数给的预算不是量出来的余量，第三节已逐条写明。
   **解封条件**：任何一次改动让这两格出现非零偏差时，回来把实测值补进理由列；

4. **没有跨平台逐位声明**。``asinh``与``hypot``走libm，本仓不对跨平台
   逐位相同做声明（spec/13后端确定性分级）。本案例的零容差三格**不含**
   这两个函数（它们只出现在螺线金标里，而那一格的容差是1e-15）。

**没有静默skip**：上面第1条是唯一一处"少算了一档"，它由生成器显式挑出整数匝
（`integer_turns`）而不是在测试里`if`跳过。

## 六、本案例不是什么

* **不是力学案例，一个力都没有**。``T = M/R``在`drives.SpoolTension`，
  本案例只给``R``。"半径长了所以同扭矩下张力掉了"这句话本案例**推不出来**——
  它要`drives`那一侧的判据（`cases/free_span_tension_step`）；

* **不是自接触（S5.2）**。新绕上去的一匝压在已绕的匝上会**压扁**、会让
  实际堆积因子随张力变——本案例的``packing_factor``是一个**声明期常量**，
  它不随张力变。绿了不代表引擎知道匝会压匝；

* **不是真的螺线几何**。本案例的``L(n)``是**同心圆理想化**（每匝一个闭合圆），
  第三条oracle量的正是这个理想化的误差预算（二阶，``ε = 7.81e-3``时``7.06e-7``）。
  **要真螺线的落位点坐标，本案例给不了**——那是`laydown`的中心线语义（S1.3）；

* **不是欧拉式材料注入**。喂料前沿是**拉格朗日**的：每个节点始终是同一块材料，
  喂料只是往前接长度。**带材从轮面上流过、边界随材料移动**（WDS `research/05`
  第三节那条"当前最大的单项缺口"）本案例与`winding`模块都给不了；
  横漂稳态、绞盘全滑同样给不了。绿了**不能**推出引擎能算这些；

* **不是"绕线机能跑通"**。本案例不判张力控制、不判导轮、不判排线机构，
  也不判绕出来的形能不能装进法兰（那条在`modelgen.generate_spool`里，
  是溢出即失败关闭）；

* **`relative_deviation`那两格的容差不是精度声明**。它们是按条件数给的预算，
  实测偏差恰为0——**不要引用它们当"引擎算长度精确到1e-5"**，
  长度的精度声明在`wound_length_mm`那一格（实测1.58e-16，判1e-15）。
