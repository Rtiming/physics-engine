# groove_sweep_wall — 外倾锥面槽壁 vs 平面环带

决策[0075](../../docs/decisions/0075_扫掠槽壁接触_两段外倾锥面与冻结帧的代价_20260818.md)，
兑现[0074](../../docs/decisions/0074_真实网格进接触_碰撞归本仓_距离场是根本形制.md)第六节阶段一（轨A），
守[plans/15](../../docs/plans/15_从这里到真机介入的分阶段计划_20260817.md)第2.2条：

> 真实槽几何：槽底宽8.000 mm、**两段外倾锥面**槽壁（现有`PenaltyAnnulusLimit`是平面环带，形制对不上）。
> 判据：锥面给的是**逐渐爬升的回正力**，平面环带给的是硬碰；两者在同一横移量下的力必须显著不同。

**本页把"显著不同"换成了数**，并且顺带订正了那句话的一个前提——见第六节第1条。

## 一、物理/几何设定

单节点、罚接触、准静态。全部量在**工件系**，长度mm、力N、刚度N/mm。

| 量 | 值 | 出处 |
|---|---|---|
| 槽底半宽 `w/2` | 4.000 mm | plans/15第2.2条"槽底宽8.000 mm" |
| 带材边缘半偏移 `r` | 2.000 mm | 4 mm宽REBCO带材 |
| 壁外倾角 `α` | 10.000° ⟹ `tanα = 0.1763269807` | **声明的设计参数，不是量出来的**（见第四节第1条） |
| 罚刚度 `k` | 5.000e3 N/mm | 与`cases/winding_line_endtoend`同档 |
| 槽深窗 `[v_min, v_max]` | `[−1.000, 6.000]` mm | 壁只在这一段存在；窗外力为零 |
| 压紧力 `F_hold` | 3.000 N | 把带材按在槽底的法向载荷（第三组用） |
| 槽底接触 | `PenaltyNormalContact`，同刚度、半径0 | 第三组用 |
| 帧 | `s = (1,0,0)`、`n = (0,0,1)`、`t = (0,1,0)` | 轴对齐，判据与朝向无关 |
| 中心线不变量（第四组） | `R = 145.6 mm`、帧扭率 `τ = 2.550 °/mm`、弧长 `a = 37.0 mm` | plans/14第2.2节`v2-01-bracket`实测 |
| 求值点（第四组） | `u = 2.300 mm`、`v = 0.800 mm` | 带材边缘刚顶上壁的一档 |

自由度约束：横向`u`与沿槽`t`两个方向钉死（`fixed_indices = {0, 1}`），
**深度`v`在第二组里钉死、在第三组里自由**——这两组的分界就是本页的主结论。

## 二、参考解出处

**闭式解**，全部是初等代数，生成脚本入库：
[`generate_oracle.py`](generate_oracle.py)（SHA-256钉在`oracle.json`的
`generator.sha256`字段，`load_manifest(root=…)`每次运行都重算并比对）。
推导写在该脚本的模块docstring里，逐条是：

* 间隙 `g_σ = w/2 + v·tanα − (σ·u + r)`，罚势 `U = ½k g²`；
* 力拆到两轴：`F_横向 = k|g|`（**与`tanα`无关**）、`F_举升 = k|g|·tanα`、`|F| = k|g|·secα`；
* 深度自由 + 压紧力下的深度平衡：`k|g|·tanα = F_hold` ⟹ **`F_横向 = F_hold/tanα`，与横移量无关**；
* 逃逸阈值：`u_逃逸 = w/2 + v_max·tanα − r + F_hold/(k·tanα)`；
* 冻结帧残差（决策0075第四节）：`∇g_精确 = ∇g_冻结 − A·t`，
  `A = τ(tanα·u + σ·v)/(1 − u·κ_s − v·κ_n)`。

**实测数不作金标**（spec/08规则1）：上面每一条都是先手推、再让内核去撞。
第四组另有一条**独立的数值腿**——对解析帧做中心差分独立求出`κ_s`、`κ_n`、`τ`，
与闭式那条互不引用；`tests/test_contact_groove_sweep.py`里对"活最近点"的间隙
直接做中心差分，实测**二阶收敛比4.0000/4.0000/4.0000/3.9998**。

## 三、判据表

| 量 | rel | abs | 理由 |
|---|---|---|---|
| `gap_mm` | 0 | 0 | **零容差**：一次减法一次乘法，金标与内核走同一串IEEE-754基本运算，无求积无迭代无开方。写成非零容差等于承认不知道这条是不是恒等式 |
| `plane_lateral_force_n`（深度冻结档） | 0 | 0 | 同上。`k·(u + r − w/2)`，全部是精确可表示的十进制小数之间的加减乘 |
| `cone_lateral_force_n`（深度冻结档） | 0 | 0 | **本页最要紧的一条零容差**：它钉住"深度钉住时锥面与平面的横向力**恒等**"。这不是数值巧合，是`∇g`的`s`分量与`tanα`无关这一条代数事实。另有一条`float.hex()`逐位断言并列，见conformance第127行 |
| `cone_lift_force_n` | 1e-14 | 0 | 带一次`tan`求值；超越函数**不在IEEE-754的正确舍入承诺里**，故不写零容差。单次求值误差≤1 ulp（≈2.2e-16），留两个数量级余量 |
| `cone_over_plane_magnitude` | 1e-14 | 0 | 同上，另带一次`cos`。理论值恒为`secα = 1.0154266119`，与横移量无关——**三档横移给同一个数**本身就是一条判据 |
| `plane_lateral_force_n`（深度自由档） | 1e-9 | 0 | 这一档是牛顿解出来的平衡。**位置带`O(1/k)`的罚柔度误差、力不带**（0050第二节：平衡时`k·δ`精确等于理论法向力）。1e-9 = 牛顿残差判据`1e-11 N`除以本构型力尺度（17—5000 N）再留两个量级 |
| `cone_lateral_force_n`（深度自由档） | 1e-9 | 0 | 同上。理论值`F_hold/tanα = 17.0138455 N`，**五档横移给同一个数**；另有一条判据判"极差 < 1e-9 N"——逐点比对漏得掉"它是不是常数"这件事 |
| `cone_depth_mm` | 1e-6 | 0 | **与力不是同一个精度档**。深度是位置量，同一牛顿残差经`1/(k·tanα)`放大后落在1e-6·6mm这一档。两个档写在一起才不会被人抄错 |

## 四、已知失效清单

1. **`α = 10°`是声明的，不是量出来的。** GCW的22列导出里有`left_*`/`right_*`与`width`，
   但那给的是槽口两侧的点，**由它反解外倾角要先知道槽深**，而槽深不在这22列里。
   本页与内核的每一条判据都写成`tanα`的函数，换一个角度全部照样成立。
   解封条件：工件CAD（或带槽深的sidecar）进来，那时把`α`改成实测值并重跑本页。
2. **本页没有读过一行真实`centerline.csv`。** 第四组的不变量取自plans/14第2.2节的
   **实测数**，但曲线本身是"圆弧 + 绕切向按`τ·a`自转的帧"这条解析构造。
   这样做的理由写在生成脚本里：真工件的`κ`与`τ`是**两个不同向的量**（plans/14第2.2节末段），
   而螺旋线会把两者锁死成一个比值。解封条件：`tools/model/centerline_csv.py`的真实语料
   进仓（0074第六节阶段二）。
3. **逃逸之后求解器报`SolveError: singular`，本页把它当判据而不是当故障。**
   带材爬出槽口后这面壁不再存在，深度自由度不受任何能量项约束，
   Hessian确实奇异——**问题失去良态是物理，不是数值失效**。
   但它也意味着本页**没有**给出"跳槽之后会怎样"的任何结论：那需要相邻匝/法兰/另一条槽，
   属0074第六节阶段二。
4. **摩擦一点没进。** 本页只算法向。锥面把一部分法向力转成举升分量，
   而真实带材爬壁时切向摩擦会顶住它——**所以第三组算出的"爬到多深"是一个上界，不是预测值**。
   解封条件：`contact.friction`的椭圆return-map接到本项上（决策0068已有形制）。
5. **冻结帧的代价被量出来了，但没有被修掉。** 实测`|A|/|∇g| = 5.3707%`、力方向偏
   `3.0743°`（plans/14最扭的那一档）。本页判的是"这个数是多少"，
   不是"这个数足够小"——**后面那句话本页没有资格说**。解封条件见决策0075第四节末段。
6. **单节点，不是一根杆。** 没有轴向张力、没有弯曲、没有相邻节点耦合。
   本页验的是接触项本身的形制与静力学，**不是带材在槽里的行为**。

## 五、档位与负载级

清单身份：`case_id = case/groove_sweep_wall`，`load_tier = interactive`。

**A档、interactive**（与`oracle.json`的`load_tier: "interactive"`逐字一致，
无pytest marker）。实测耗时：`tests/cases/test_groove_sweep_wall.py` 11条 **0.07 s**；
配套单元门`tests/test_contact_groove_sweep.py` 37条 **0.08 s**。
最重的一条是逃逸阈值那条（60步二分×每步两次牛顿），仍在毫秒量级——
本项的Hessian是常数、活动集一步就定，牛顿两三步收敛。

## 六、本案例不是什么

1. **它不是"锥面的回正力更软"这句话的证明——那句话缺一个前提。**
   plans/15第2.2条写的是"锥面给的是逐渐爬升的回正力、平面给的是硬碰"。
   **深度被钉住时这句话是错的**：那时两者的横向力`k|g|`**逐位相同**，
   差别全在锥面多出来的举升分量上。"回正力变软"是**深度自由**时那个举升分量
   反过来改变平衡位置的结果，不是间隙公式给的。
   本页因此拆成两组分别判，而不是拿一组去证一句含混的话。
2. **它不是槽壁接触的精度声明。** `PenaltyGrooveSweep`把最近站点的帧冻结进声明，
   梯度里少了一项`A·t`；本页量出它是5.3707%。**5.3707%不是误差上界**——
   它是这一个构型、这一档不变量下的值，换构型要重算。
3. **它不判位置。** 罚接触的穿透是`O(1/k)`的模型自带量（0050第二节）。
   第二组判力与间隙，第三组的`cone_depth_mm`判的是**平衡深度**（一个物理量），
   不是穿透量。**判力与阈值，不判穿透**。
4. **`secα = 1.0154`这个比值不能读成"锥面接触更狠"。** 它是合力大小之比；
   回正方向上的分量一点没变。把它当成"锥面把带材夹得更紧"是反的——
   锥面做的恰恰是**把带材往外推**。
5. **逐位退化那一条不在本页，在`tests/test_contact_groove_sweep.py`。**
   本页判的是"锥面与平面不同"，那边判的是"`tanα = 0`时两者**逐位相同**"。
   两条判据方向相反、缺一不可：只有前者，实现可以偷偷换掉整个平面档；
   只有后者，锥面那一档可以是死代码。
6. **它不覆盖多节点、多站点的扫掠装配。** `groove_sweep_walls`逐节点定位站点这件事
   由`tests/test_contact_groove_sweep.py::test_the_builder_emits_two_walls_per_node_sharing_one_station`
   守，本页一个节点。
