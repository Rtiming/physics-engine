# sdf_contact_convergence —— 距离场接触的收敛

决策[0074](../../docs/decisions/0074_真实网格进接触_碰撞归本仓_距离场是根本形制.md)阶段四、
[0085](../../docs/decisions/0085_网格与距离场_窄带块稀疏与三次B样条_20260818.md)第三节。
判据正本是`oracle.json`，闭式出处在`generate_oracle.py`的模块docstring。

**这条案例回答一个问题**：把接触的``g``从解析式换成可查询的场之后，
**位置精度由谁决定？** 答案是分辨率，不是罚刚度——本页第三节那个**6.37倍**就是它。

## 一、物理/几何设定

一个节点被恒力按在固定障碍上，横向自由度钉住、只留``z``。

| 量 | 值 |
|---|---|
| 障碍甲：半空间 | 过原点、外法向`(0, 0, 1)`；``φ(x) = (x − p)·n`` |
| 障碍乙：球 | 球心在原点、半径`10.0 mm`；``φ(x) = \|x\| − R`` |
| 节点半径 | `0.5 mm`（本仓罚接触的半径是**显式参数**，质点写0.0） |
| 罚刚度`k` | `5000 N/mm` |
| 下压力`F` | `25 N`，方向`(0, 0, −1)`，由`PointLoad`加载在0号节点 |
| 状态布局 | 两个节点各3个自由度；**1号节点全钉在原点**，只为让`PenaltySphereContact`两端都有自由度（那一项两端都是自由度，钉死一端即得"固定球障碍"） |
| 固定自由度 | `{0, 1, 3, 4, 5}`，自由的只有0号节点的``z`` |
| 节点质量 | `1e-9 kg`（准静态，质量不进平衡方程；给一个非零值只为满足`EnergyContext`的正性校验） |
| 重力 | `(0, 0, 0) mm/s²`——**刻意关掉**：本案例判的是接触与场，不判重力 |
| 残差容差 | `1e-9 N`（`solve.py`申报的参考取法是总载荷的1e-9到1e-10；总载荷25 N） |
| 场：栅格间距`h` | 球那一档`1.0 / 0.5 / 0.25 mm`；半空间那一档`2.0 / 1.0 / 0.5 mm` |
| 场：包围盒 | 球`±13 mm`、半空间`±10 mm`，节点数由``h``定 |
| 场：窄带半宽 | 球`max(3.5, 2h√3·1.05) mm`；半空间`8.0 mm`。下限`2h√3`是三次B样条支撑宽度的要求，`sample_narrow_band`按它失败关闭 |
| 场：块 | `8³ = 512`个节点/块，按块坐标哈希（OpenVDB叶节点同尺寸的简化版） |
| 插值 | **三次B样条**，采样值直接当系数（不做预滤波） |

单位口径：长度mm、``g``mm、``k``N/mm、``U``N·mm、力N——与`contact/penalty.py`逐字相同。

## 二、参考解出处

**②生成脚本入库**：`cases/sdf_contact_convergence/generate_oracle.py`，
SHA-256钉在`oracle.json`的`generator.sha256`字段（由`oracles.write_manifest`落盘时算）。

脚本里的三条闭式全是初等代数与一次泰勒展开，本可以直接写在本页上；
入库是为了让那些数**有一个被SHA钉住的出处**，不是因为它们算不出来。逐条：

1. **平衡位置**：``k·|g| = F`` ⟹ 半空间``z* = r − F/k``、球``z* = R + r − F/k``；
2. **场把``z*``推到哪里去**：三次B样条拟插值的展开是
   ``S(x) = φ(x) + (h²/6)·∇²φ(x) + O(h⁴)``。
   那个``1/6``是三次B样条二阶矩``Σ_k (k − t)²·B(k − t) = 1/3``的一半，
   **与胞内相位``t``无关**（`tests/test_contact_field.py`对四个``t``各验一次）。
   于是半空间（``∇²φ ≡ 0``）**误差恒为零**、球（``∇²φ = 2/|x|``）给
   ``Δz = −h²/(3z*)``；
3. **它与罚穿透的比**：``k·h²/(3·z*·F)``。

**实测数不作金标**（spec/08规则1）：内核的数拿来撞这里的数，不是反过来。

## 三、判据表

| 量 | rel | abs | 理由 |
|---|---|---|---|
| `plane_equilibrium_z_mm`（解析项） | 0 | 0 | **零容差是代数保证的**：活动接触段的``U = ½k(z−c)² − F·z``对``z``严格二次，牛顿**一步走到精确解**，那一步就是一次除法``F/k``。实测`diff = 0.0`、迭代次数1。这条一旦在别的平台上红，红的是"牛顿那一步在那台机器上不是精确的"，**而那本身值得知道** |
| `sphere_equilibrium_z_mm`（解析项） | 0 | 0 | 同上；球在轴上``\|x\| = z``所以也严格二次。用的是`PenaltySphereContact`把1号节点钉在球心——**仓里本来就有这个解析球** |
| `contact_gap_mm` | 0 | 1e-16 | **这一条不是零容差**：内核算``(x−p)·n − r``（一条减法链），闭式算``F/k``（一次除法），**两串运算不同**，逐位相等没有理由成立。实测差`4.337e-18 mm`（5 ulp），留两个量级 |
| `normal_force_n` | 1e-12 | 0 | 力在平衡处精确等于外载（0050第二节：``k·δ = N``与``k``无关），但它是牛顿迭代出来的、带残差容差`1e-9 N`。1e-12相对＝`2.5e-11 N`，**比残差容差还紧两个量级**——这条能过说明收敛得比判据要求的更深 |
| `plane_field_h_*.equilibrium_z_mm` | 0 | 1e-12 | 仿射函数被三次B样条**精确重构**（一阶矩为零），场与解析项解的是同一个方程。实测三档``h``跨4倍全部差`2.220e-16 mm`（1 ulp）。留四个量级。**不写零**：两条路求和次序不同（点积 vs 64项B样条求和），逐位相等没验过 |
| `plane_field_h_*.normal_force_n` | 1e-9 | 0 | 同上；力经``k·g``放大，1e-9相对＝`2.5e-8 N`，仍比残差容差紧 |
| `sphere_field_h_*.equilibrium_offset_mm` | 5e-3 | 0 | 闭式二给的是**主项**，实测还带`O(h⁴)`余项。实测主项与实测之差`−1.1164e-04 / −9.8074e-06 / −1.3220e-06 mm`，主项本身`−3.176e-02 / −7.940e-03 / −1.985e-03 mm`——最差那档余项占**0.35%**。5e-3覆盖它并留一档。**不按绝对判**：绝对容差会让粗档松细档紧，量不出"主项抓对了没有" |
| `sphere_field_h_*.equilibrium_z_mm` | 0 | 1.588e-4 | 同一条判据的绝对写法（最粗档主项×5e-3）。**两种写法都留着**：偏差那一列判"主项抓对了没有"，位置那一列判"算出来的还是不是同一个平衡"——后者挡得住"偏差对了但基准位置整体挪了" |
| `position_error_order_ratio` | 2.5e-2 | 0 | **收敛比是区间不是恒等于4**（`cases/harmonic_oscillator`同源：4是渐近值）。2.5e-2相对＝`[3.9, 4.1]`，与本仓其余二阶门同一个窗口。实测**4.0091 / 4.0023** |
| `gradient_finite_difference_ratio` | 2.5e-2 | 0 | 中心差分对能量的二阶收敛，实测比**恒4.0000**。窗口同上，但**判的不是同一件事**：上一条判场的分辨率误差随``h``的阶，这一条判梯度是不是所实现能量的导数 |
| `field_error_over_penalty_penetration_at_coarsest` | 1e-2 | 0 | 闭式三是初等代数，但内核那一侧的分子是**解出来的**位置误差、带那条`O(h⁴)`余项（h=1时占0.35%）。1e-2覆盖并留一档。**这条数是本案例最要紧的一个**：`6.3746`倍 |

## 四、已知失效清单

**无静默skip**——本案例的11条门全部无条件执行。以下四条是**已知的限制**，
写在这里是因为它们决定了这些绿意味着什么：

1. **窄带外没有判据**。场在带外**失败关闭**（0085第五节裁的），
   本案例的所有查询点都在带内，所以它**一条也没验带外的行为**。
   带外那一条的门在`tests/test_contact_field.py`（三条，含必红）。
   **解封条件**：背景符号瓦片进来之后，带外从"抛"变成"按符号外推"，
   那时本案例该加一条"物体被推到带外仍然给出正确的接触"。
2. **只验了轴上的一维平衡**。横向两个自由度是钉住的，
   所以`∇²g`那一块（曲率刚度）**只在Hessian的门里被验过，没有在本案例里驱动过位置**。
   **解封条件**：转动自由度那一片（0074阶段三）落地后，
   一个被顶得转起来的刚体才会真正用到那一块。
3. **球是解析采样的，不是从三角网格烘的**。烘焙那一条在
   `tools/model/sdf_bake/`（pcu，独立venv），它的数在`sphere_probe.report.json`。
   **两件事分开是有意的**：本案例量的是"场进接触之后精度怎么变"，
   把三角化误差混进来会让阶量不出来。
4. **没有真实件**。`e1_carrier`（336三角）是0074点名的第一个真实语料，
   本案例用的是解析球。**解封条件**：真实资产落到本机时。

## 五、档位与负载级

**A档 / 交互级**（无pytest marker），与`oracle.json`的`"load_tier": "interactive"`逐字一致。
清单的`case_id`是`case/sdf_contact_convergence`——**页与清单不许各说各话**，
`tools/check_case_pages.py`第三条结构校验判的就是这两行。

实测耗时**0.67秒**（11条门，本机2026-08-18）。其中最贵的一档是``h = 0.25``那次烘焙
（0.48秒，827904个窄带节点）。三条门共用同一个``h``，
所以测试侧对场做了`lru_cache`——**那是测试的优化不是内核的**：
场不可变，同一档``h``烘出来的字节相同。不缓存时是1.90秒。

**本机墙钟不作性能结论**（AGENTS.md性能条款）：上面那两个数是给"这条案例贵不贵"
这个调度问题用的，不是性能判据。

## 六、本案例不是什么

* **它不是"SDF接触能用"的证明**。它证明的是一件更窄的事：
  在**一维、凸、光滑、活动集不翻转**的构型上，场引入的位置误差有闭式主项且二阶收敛。
  凹面、棱、活动集翻转、多点接触，**一条都没碰**；
* **它不判位置精度绝对值好不好**。``h = 1 mm``那一档物体沉进去`0.0319 mm`——
  这个数是好是坏取决于用途，本案例只说它等于`h²/(3z*)`；
* **"把``k``提十倍"不能改善它**。第三节那个6.37倍的分母才是罚穿透。
  这条是本案例最容易被读反的一句：**看到"位置误差比穿透大六倍"就去调``k``是白费力气**，
  ``k``提十倍只把分母缩十倍，分子一动不动；
* **它不说三次B样条比三线性"精度高"**。两者的差别在本案例里根本不出现
  （这里判的是阶，不是光滑性）。三线性被否掉的理由是**C⁰违反`solve.py`第29行
  申报的适用域**，那条的实测出口在`tests/test_contact_field.py`
  （胞界上三线性的``∂g/∂x``跳幅恒为`5.082e-02`、与``ε``无关）；
* **它不能推出"SDF在真实件上也是二阶"**。真实件的``φ``在棱与角上不光滑，
  而二阶的推导要``φ``四阶可导。**在不光滑处阶会掉，本案例量不到那件事**；
* **它不是内存或速度的判据**。窄带存了多少、块粒度吃掉多少节省，
  那条账在`tests/test_contact_field.py`
  （`h = 0.5`、带3.5 mm、8³块时存下**0.9010**，几乎没省）。
