# real_centerline_invariants — 本仓第一条读真实工件的案例

决策[0078](../../docs/decisions/0078_活站点的扫掠槽壁与第一条读真实工件的案例_20260818.md)，
兑现[plans/15](../../docs/plans/15_从这里到真机介入的分阶段计划_20260817.md)阶段二第2.1与2.3条：

> 2.1 读GCW的`centerline.csv`（22列规范格式）。判据：读进来的曲率/扭率与plans/14第2.2节那张表**逐档对上**。
> 2.3 在真中心线上算hard-way应变分布。与闭式`ε_edge = (w/2)·|κ_s|`并排；**差额就是扭转吃掉的那部分**。

**本仓36个案例没有一个读过真实工件，这是第一条。** 于是本页的重心与别处不同：
**"读进来的数对不对"比"力算得多准"更要紧**——本页一个力都不算。

**而它第一次读就读出了一条对不上的**，见第四节第2条。

## 一、物理/几何设定

三档，全部在**工件系**，长度mm、角度按标注。

| 量 | 值 | 出处 |
|---|---|---|
| 金标一：圆弧半径 `R` | 145.6 mm | plans/14第2.2节`v2-01-bracket`的`ε_edge` p100那行 |
| 金标一：帧扭率 `τ` | 2.550 °/mm | 同一份导出的`τ_max`。**与`R`不同向，是独立的量**（plans/14第2.2节末段） |
| 金标一：求值弧长 `a` | 36.000 mm | **必须在四个细化步长上都是站点**（见第四节第4条） |
| 金标一：细化步长 | 2.0 / 1.0 / 0.5 / 0.25 mm | 收敛阶那一档 |
| 金标二：采样步 `h` | 2.000 mm | 与GCW真实导出同一档（实测1.9994—2.0016 mm） |
| 金标二：一段内转角 `Δ` | 0.050 rad | 尖峰幅度，闭式里整个约掉 |
| 带宽 `w` | 4.000 mm | **plans/14那张表用的数，不是工件自己的槽宽**（见第四节第3条） |
| 中心线语义 | `hermite_tangent` / `reorthonormalised_linear` / `open` / `clamp_to_end` / 4 | 五条逐条声明，`CenterlineSemantics`不许有默认值（0067） |
| 差分取法 | `forward` 与 `central` **两档都判** | `laydown.ARC_DIFFERENCE_SCHEMES`，无默认值 |

**真实语料走选择进入**：设`PE_REAL_CENTERLINE_CSV`才跑第三档，不设明示skip
（决策0073裁决真实资产永不进仓；形制抄`tests/test_provenance.py`的`PE_REPLAY_CASE_RUNS`）。
仓内常驻那两档用的是**合成**站点表。

## 二、参考解出处

**闭式解**，全部是初等三角与代数，生成脚本入库：
[`generate_oracle.py`](generate_oracle.py)（SHA-256钉在`oracle.json`的`generator.sha256`，
`load_manifest(root=…)`每次运行都重算并比对）。推导写在该脚本模块docstring第五节，逐条是：

* 圆弧 `dT/ds = −径向/R`，模长 `κ_total = 1/R`；
* 帧 `n = cos(τa)·径向 + sin(τa)·ẑ`、`s = n × t = cos(τa)·ẑ − sin(τa)·径向`，故
  `κ_s = sin(τa)/R`、`κ_n = −cos(τa)/R`，**两者平方和恒为`1/R²`**；
* 帧扭率 `τ_frame = (ds/da)·n = −τ`——**带符号，而plans/14报的是绝对值**；
* 一段尖峰上两个差分模板：`forward` 给 `sinΔ/h`、`central` 给 `sinΔ/(2h)`，
  **比值恰好`1/2`，而两者的`∫|τ|ds`都等于`sinΔ`**。

**实测数不作金标**（spec/08规则1）：上面每一条都是先手推、再让`laydown`去撞。
第三档另有一条独立的腿——那批CSV的数由GCW产出、由plans/14在**另一个仓**里算过一遍，
本页在**本仓**重算，两条互不引用。

## 三、判据表

| 量 | rel | abs | 理由 |
|---|---|---|---|
| `curvature_total_per_mm` | 1e-6 | 0 | 站点差分，截断项`O(h²)`。`h=0.25`、`R=145.6`下`(h/R)²≈3e-6`，留一个量级 |
| `curvature_s_per_mm` | 5e-5 | 1e-9 | 同上，另加一条**绝对**地板：`κ_s = sin(τa)/R`过零，过零点上相对容差没有意义（与`scalar_diffraction_airy`那条"判绝对不判相对：J1有零点"同源） |
| `curvature_n_per_mm` | 5e-5 | 1e-9 | 同上，同一条零点理由 |
| `twist_per_mm` | 5e-5 | 0 | **初稿写的是1e-6并声称"恰好没有截断项"，那是错的**（见第四节第5条）。实测`h=0.25`时相对2.06e-5、比值恒4.000 |
| `curvature_quadrature_per_mm` | 1e-6 | 0 | 恒等式`κ_s²+κ_n²=κ_total²`。**判它是因为它对"两根轴被对调"有分辨力而单点没有**：对调之后两个数互换，平方和一点不变 |
| `twist_is_negative` | 0 | 0 | **布尔，零容差**。符号错了`PenaltyGrooveSweepLive`的接触力往反方向偏，而三根轴仍然正交、仍然都是单位向量——那是一个**安静的**错 |
| `edge_strain_at_probe` | 5e-5 | 1e-9 | `(w/2)|κ_s|`，继承`κ_s`的档；一次乘法不放大 |
| `scheme_agreement_relative_bound` | 0 | 0 | **它是判据的参数不是被判的量**，零容差逐字比。实测`τ`差4.16e-6、`κ_s`差1.25e-14，判1e-4留两个量级——而真语料上两者差2e-1，分辨力还有三个量级余地 |
| `forward_twist_peak_per_mm` / `central_twist_peak_per_mm` | 1e-15 | 0 | `sinΔ/h`。超越函数**不在IEEE-754的正确舍入承诺里**，故不写零容差；1 ulp≈2.2e-16，留一档 |
| `peak_ratio_central_over_forward` | 0 | 0 | **本页最要紧的一条零容差**。它不是数值巧合而是两个差分模板的代数事实，`sinΔ`在比值里**整个约掉**——写非零容差等于承认不知道这是不是恒等式 |
| `forward_twist_integral_rad` / `central_twist_integral_rad` | 1e-15 | 0 | **两者相同这件事本身是判据**：峰值差2倍而积分不差，正是真语料上实测到的形态 |
| `central_spreads_over_two_stations` | 0 | 0 | **布尔，零容差**。只判峰值比是判不出"摊到哪去了"的——一个把`central`整体乘0.5的实现照样全绿 |
| `r_min` / `twist_max` / `edge_strain_p100`（真语料） | 0.005 | 0 | 原表印三到四位有效数字（75.2、2.550、1.374%），0.5%宽出至少两档 |
| `above_006` / `above_004`（真语料） | 0 | 0.001 | 占比判**绝对**不判相对：那几格原表就是`0.0%`，相对容差在零上没有意义 |
| `geometries_matched` | 0 | 0 | **整数，零容差**。按内在几何归并只有5份不同——判它是为了让"语料变了"当场红 |
| `published_rows_without_a_file` | 0 | 0 | **整数，零容差**。把够不到的条数写成判据，比在散文里说一句"部分覆盖"诚实 |
| `rows_disagreeing_with_the_published_twist` | 0 | 0 | **整数，零容差**。"大体对上"不是一个可以被后来的人验的说法，"恰好两行对不上"是 |
| `the_two_disagreeing_rows_swap_into_each_other` | 0 | 0 | **布尔，零容差**。它把"原表对调了"与"我们算错了"分开——**算错不会让两个错数恰好互为对方** |

## 四、已知失效清单

1. **本页读的是GCW的`handoff_runs`，不是plans/14第2.2节那张表的正本。**
   那张表是在另一个仓（`packages/pose-solver/artifacts/workpieces/`）上算的。
   本页按**总弧长**认几何——它是那张表里最有分辨力的一格，五档实测偏差 `< 0.01 mm`。
   解封条件：正本进得来（0073裁决真实资产永不进仓，所以大概率永远走选择进入）。

2. **`τ_max`有两行与plans/14对不上，而且它们恰好互为对方。** 实测：

   | 几何 | 弧长mm | 本页实测`τ_max` | plans/14印的 |
   |---|---:|---:|---:|
   | `v1-coil-1` | 1966.3250 | **6.5686** | 6.648 |
   | `v2-coil-02` | 851.9355 | **6.6467** | 6.568 |

   **互换之后两行都对到四位有效数字。** 其余三行、以及这两行的`R_min`、
   `ε_edge` p100、两个占比**全部原位对上**。
   本页把它写成两条判据（对不上的行数恰为2、且两行互换后对上）而不是一句散文，
   理由写在判据表最后一行：**算错不会让两个错数恰好互为对方。**
   **本页没有资格改plans/14**（那是另一条轨的文件），只把证据摆在这里。

3. **`w = 4.0 mm`是plans/14那张表的假设，不是这批工件的槽宽。**
   实测各文件`width`列的中位数是**8.0075 mm**（`v1`/`test`组）与**9.995 mm**（`v2`组）两档。
   换成各自的槽宽后`ε_edge > 0.6%`的占比从0%—5.9%变成**13.4%—23.3%**，排序几乎被抹平
   ——plans/14第2.2节第3条自己写过这一条。本页沿用4.0**只是为了与那张表对得上**，
   `hard_way_edge_strain`因此**不给`strip_width_mm`默认值**。

4. **收敛阶那一档的求值点必须在每个步长上都是站点。**
   初稿取`a = 37 mm`，而37不是2.0的倍数——最粗那一档探针落到了`a = 36`，
   量到的不是截断误差而是**选站误差**，比值实测**300**而不是4。
   改成`a = 36`（`= 2·18 = 1·36 = 0.5·72 = 0.25·144`）之后四档全中。
   **这条登记下来是因为它是一个很容易再犯的错**：细化时"探针落在哪一站"会跟着变。

5. **`τ`的容差初稿写错了一个量级，理由也写错了。**
   初稿是`rel 1e-6`，理由"帧只绕`t`刚性自转，差分恰好没有截断项"。
   **那句话是错的**：`n`里的"径向"那一半自己随`θ`转，于是`ds/da`带一个`O(h²τ²)`的截断项。
   实测`h=0.25`时相对2.06e-5，比值恒为4.000。改成`5e-5`。
   **写下来是因为"我以为它是恒等式"这个错本身有形态**——0075第五节那道空门同源。

6. **两种差分取法在真语料上差19%—25%，本页不裁哪一种对。**
   实测（`τ_max`，`forward` 对 `central`）：6.5686/4.9594、2.5496/2.0589、
   6.6467/5.0734、2.1837/1.6901、3.1458/2.3568，比值0.70—0.81。
   而`∫|τ|ds`两种取法差 `< 1%`。
   **这不是哪一种错了，是那些峰在2 mm采样下没有收敛**——金标二把这个机理量成了
   一条零容差恒等式。于是plans/14那张表里的`τ_max`读作
   **"这个几何在2 mm采样下的峰"**，而不是曲线的性质。
   解封条件：更密的导出，或上游给出`τ`的解析式。

7. **`∫|τ|ds`没有进判据。** 本页实测（`forward`、按弧长权、开曲线口径）
   657.18 / 417.93 / 386.85 / 317.27 / 365.91 度，plans/14印的是
   657 / 418 / 387 / 317 / 366——**五档全部对到印刷位数**。
   没设门是因为**接缝怎么处理没定死**：开曲线与绕接缝两种口径差0.2%—0.6%，
   而原表用的是哪一种没有写。**知道它对得上，但不知道对的是哪一条口径，所以不设门。**

8. **"扭转吃掉了多少硬弯"本页没有算，一个数都没有。**
   plans/15第2.3条要的是"差额就是扭转吃掉的那部分"。本页给的是
   `ε_edge = (w/2)|κ_s|`这条**上界**（假定带材宽面刚性跟着槽帧走），
   以及帧自己已经扭了多少（`∫|τ|ds`）。**两个数并排放着，差额是谁吃掉的本页不裁**——
   plans/14第2.3节写明那需要"双轴弯曲＋扭转＋槽壁接触"三件一起算，
   而本仓这三件今天凑不齐（扭转有`anisotropic_rod_twist`、槽壁接触有
   `groove_sweep_wall`与本轮的活站点档，**双轴弯曲＋扭转＋接触装在一根杆上没有**）。
   **plans/15第2.3条本页只兑现了前半句。**

9. **`central`档在闭合曲线上的接缝处理没有被执行过。**
   `centerline_invariants`对`topology="closed"`有一条"用`n−2`当`0`的后邻"的分支，
   而真实CSV一律声明`open`（GCW把闭合曲线导成开放折线，首末差一个采样步，
   `_require_stations`因此拒`closed`）。**那条分支今天没有语料走得到**，
   如实登记而不是硬造一个用例。

## 五、档位与负载级

清单身份：`case_id = case/real_centerline_invariants`，`load_tier = interactive`。

**A档、interactive**（与`oracle.json`的`load_tier: "interactive"`逐字一致，无pytest marker）。
实测耗时：`tests/cases/test_real_centerline_invariants.py` 仓内常驻9条 **0.07 s**；
接上真语料（5份、426—984站）11条 **0.27 s**。
最重的一条是收敛阶那两条（每条建4条中心线、最细一档321站），仍在毫秒量级——
本页一个自由度都不解，全部是站点表上的差分。

## 六、本案例不是什么

1. **它不是"这批线圈绕得了/绕不了"的结论。** 本页只回答几何：弯了多少、扭了多少。
   plans/14第2.3节那句"5.9%是上界，真值在它与0之间，今天没有任何工具能把它定位到
   区间里的哪一点"**本页一个字都没改**。
2. **它不是plans/14那张表的替代。** 那张表覆盖9个几何，本页够得到5个；
   第四节第1条写明了为什么。**够不到的条数是一条判据，不是一句免责。**
3. **它不判力，也不装配任何能量项。** `contact`一个字节都不碰。
   槽壁接触在`cases/groove_sweep_wall`，活站点档在决策0078。
4. **它不裁两种差分取法哪一种对。** 判的是"两者差多少、以及为什么差"。
   `laydown.ARC_DIFFERENCE_SCHEMES`因此**没有默认值**——那是声明者要拿的主意。
5. **`τ_max`那两行的订正本页只给证据，不改plans/14。** 改文档是另一条轨的事；
   本页把它钉成两条判据，让"有人改了原表"或"语料变了"都当场红。
6. **合成那两档不是"模拟真实数据"。** 金标一判的是**提取器本身对不对**，
   金标二判的是**两个差分模板之间的代数关系**。
   它们与真语料那一档的关系是"机理"与"现象"，不是"小样本"与"大样本"。
7. **它不读`left_*`/`right_*`那六列。** 22列里那六列是槽口两侧的点，
   由它们反解外倾角要先知道槽深，而槽深不在这22列里
   （`cases/groove_sweep_wall`第四节第1条同一条）。本页只用位置与三标架。
